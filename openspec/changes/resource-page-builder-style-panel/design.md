# Style panel

## The style panel

A style belongs to the node it styles. Each webpage node carries a `style` prop: for each breakpoint, for each state, a map from a property the panel offers to a CSS value. The renderer gives a styled node a class from its id and emits its rules — base first, then the tablet and the mobile media queries, a state after its default within each — so a later breakpoint overrides an earlier one, desktop-first. There is no free stylesheet, no selector the author writes, and no class shared between nodes, which removes the selector manager, `componentFirst` and the private-class bookkeeping GrapesJS needs.

- **Breakpoints** are three, after Webflow's: base, tablet at 991 pixels and below, mobile at 478 and below, named once beside the device widths that sit inside them. The device toggle is the active breakpoint: editing at tablet writes the tablet override. Base is desktop and names no width, so the narrowest width the canvas's desktop frame keeps is an open decision: it is set here beside 991 and 478 before the frame ships, and the [canvas](../resource-page-builder-canvas/design.md) reads it from this page.
- **States** are default and hover. Hover on a type a reader can focus emits for `:focus-visible` too, so no hover-only affordance ships.
- **Tokens** are the page's own, on the root: named colours and font stacks, emitted as custom properties. A colour field lists them as swatches first and a free colour second, and picking one stores `var(--color-name)`, so editing the token in the Theme panel recolours everything that uses it. These are the page's tokens, not the app's palette: the app's tokens theme the editor around the canvas, while a published page has one look of its author's.
- **Values** are free CSS within the property, checked with `CSS.supports` as they are typed; an invalid value stays in its field with the field's error and writes nothing. At the schema, a value is length-limited and excludes `<`, `{` and `}`, as [the canvas](../resource-page-builder-canvas/design.md) section says.

The panel is grouped the way `WebpageEditorStyleManager` groups it today, each sector a `UiCollapsible` that says how many overrides it holds: layout and flex, spacing as a box of four fields with a link toggle, size, position, typography, background as a list of colour, image and gradient layers (what `grapesjs-style-bg` added), border, and effects. Each field shows the value at the active breakpoint and state, or the inherited one as a placeholder saying where it comes from ("from Desktop"), with a reset that removes the override. The controls are the library's: `UiTextField` with a unit `UiSelect` for a length, where the arrows step the number and keep the unit, Shift by ten; `UiToggleGroup` for alignment, direction and decoration, icon-only with their titles as their names; `UiColorField` with the token swatches, which the library grows first; `UiSlider` for opacity. A drag on a slider previews in the canvas without writing history and commits one entry when it settles, which the slider already reports from the keyboard too. Copy style and Paste style are commands, the reuse a shared class would otherwise give.

An email node has no breakpoints and no states: email clients honour media queries unevenly, so MJML's own column stacking is the responsive model. Its style fields are its MJML attributes — padding, colours, font, alignment, border, background image — drawn by the same field components and stored as props.
