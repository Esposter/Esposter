# Tasks

The build's order, from the design in `design.md`. Each task states how it is verified. Tests are written first and seen failing, and an upstream defect's test is run against the installed package before it is kept.

## grid-engine-headless

- [ ] 1.1 Type the upstream audit. Read every issue and pull request with its comments through the API, give each one verdict with its proof, and record the Upstream table in the spec this change archives into. Characterize the installed package in a throwaway Vitest config beside the new package: the collision of a tile property, the missing-tile default, the two-tile block, a turn during a step, a diagonal move in four directions, and a teleport mid-step. Reproduce #528 and #551 first and record which fail. Verify: the verdicts cover every issue and pull request once, the table's counts sum to the tracker's total, and the characterization file runs green against the installed package.
- [x] 1.2 Create the package with the repository's package generator, with neverthrow as its only runtime dependency, and its README by the readme-standards skill. Verify: `pnpm build` in the package produces its entry and the package's publish checks pass, and the package's manifest has no Phaser, rxjs, mnemonist or tiled-property-flattener entry. Done: `pnpm build` writes `dist/index.js` and `dist/index.d.ts` with attw and publint clean; the manifest names only neverthrow at runtime and none of the four packages; the typecheck, `vp lint`, ESLint and the ledger-coverage check pass. The shape suite `headlessPackages` fails on the package's `-headless` name, since `openspec/specs/architecture/headless-package-shape` requires a `vue-<thing>-headless` Vue package; the owner decides between the name and that spec.
- [x] 1.3 Write the collision tests first: a blocking tile blocks; a position with no tile blocks; a position outside the grid blocks; a moving character blocks the tile it has left until it has left; characters block each other; `isBlocked` is true on a tile another character occupies (#213). Then implement the collision rule. Verify: the suite fails before the implementation and is green after. Done: the six tests failed on the missing factory before any code existed, and pass after; the moving-character test needs the stepping that 1.4 completes, so the move and update it uses are written here. The engine's members are `checkIsBlocked` and `checkHasCharacter`, since the naming rule refuses `is*` and `has*` on a function.
- [x] 1.4 Write the step and turn tests first: a step takes the same time at any split of one second of updates (#419); the default speed is four tiles per second; a move while moving is ignored; a move into a blocked tile turns once and emits `directionChanged` once (#323, #319); a turn emits only on a change of facing; a move from a position listener starts on the next update (#528); a diagonal move fails. Then implement stepping and facing. Verify: the suite fails before and is green after, and the #528 test fails against the installed package as recorded in 1.1. Done: four tests were red before the code (the `on`, `turnTowards` and diagonal checks did not exist), and five of the step tests already passed on the stepping 1.3 wrote, so they pin it; all 13 pass after. The #528 result against the installed package is 1.1's record and was not re-run here.
- [ ] 1.5 Write the event and teleport tests first: a listener stays subscribed until it unsubscribes (#293); `movementStopped` names the tile the character stopped on (#159); a teleport releases the tile a moving character left (#551, kept as a defect or a pin by the result of 1.1); `setPosition` for an unknown character returns an error (#136); a new engine has no character of the previous one (#14, #287); importing the core loads no Phaser module in a Node environment (#553). Then implement them. Verify: the suite is green after, and each upstream-defect test is recorded as failing or passing against the installed package before it is kept.

## dungeons/world

- [ ] 1.6 Write the binding's pure tests first, from the placement and depth behaviour the design records: the sprite placement table with the custom offsets (#306 pinned); the depth rule for tile layers and characters; the walking frame sequence over steps, stops and turns; and the collision grid read from a tilemap's Collision property, with absent tiles as undefined. Implement them in the dungeon services, unwired. Verify: the suite is red before and green after, and a driven run of the installed plugin records the placement and depth tables the tests pin.
- [ ] 1.7 Wire the binding behind the world, without a call site change: the engine is attached to each sprite on `addCharacter`, subscribed to the scene's update event, released on shutdown, and held raw in the world store. Verify: the wiring's suite is green, and the world still runs on the plugin, since the plugin's registration is removed only by 2.2.
- [ ] 2.1 Sweep first. Any file the swap edits that an open sweep ledger lists as unswept is swept in its own commit before the swap, with no behaviour change and its ledger row left alone. Verify: that commit's touched suites are green and the ledger's row for the unit is unchanged.
- [ ] 2.2 Swap the world onto the core in one commit. Move the call sites to the core's calls and events, wire the binding in the tilemap creation, remove the plugin's registration and augmentation, switch every type-only grid-engine import, delete the mirror, its maps, the derived event types and the test mock, and remove the catalog entry, the app's dependency and the lockfile records. Sweep the residue in the same commit: the ledger rows, the value-set skill's example, the world and scenes-and-input design prose, and the diagonal-movement note. Verify: `git grep -n "grid-engine" -- apps packages ':!pnpm-lock.yaml'` finds nothing outside the changelog, and the dungeon suites the commit touched pass under `pnpm test`; the typecheck and lint run on the push.
- [ ] 2.3 Drive the swapped world in a browser, by the run-app skill: walk the world, bump a wall and an NPC, step onto an encounter tile, teleport mid-step, respawn after a faint, switch tilemap, and check that the foreground still covers the player where it did. Compare the placement and the frame sequence with the table recorded in 1.6. Verify: each observation is written into the spec's design at archive, and any difference is either fixed or listed in the design's decisions.
- [ ] 2.4 Measure the swap. Re-run the absorb score and read the client bundle record the review writes after the swap lands, and compare the replacement's gzipped bytes with the design's size table. Verify: `pnpm ai:dependencies:score` no longer lists grid-engine, and the bundle record holds the core's bytes beside the figure the design records.
