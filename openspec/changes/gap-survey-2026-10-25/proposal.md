# Gap survey, 2026-10-25

## Why

The area roadmaps list open work, and the deferred and rejected trees list decided ideas. Neither catches what a spec admits without naming it as work, a deferred revisit trigger that has already fired, a resource type a cross-type feature skips, or a package that has no capability page at all. This survey reads the roadmaps, the deferred and rejected folders, the READMEs and the specs for those, and checks the code behind each claim. Nothing here restates an item already on a roadmap.

Each gap below is ranked by what it costs if left open. Its type says what to do next: a **missing proposal** to write, a **deferred** revisit to decide, or a **bug** to file.

## What Changes

1. **Message attachments are neither measured nor charged.** A room's size cap is checked against the size the client declares, and nothing re-reads the committed blob. The owner's storage allowance and its `BlobCreated` reconcile cover resource assets only: the reconcile function is scoped to the resource-assets container (`apps/functions/src/handlers/reconcileStorageLedgerEntryHandler.ts`, lines 11 to 15), and the reservation helper `reserveStorageBytes` (`apps/web/server/services/storage/reserveStorageBytes.ts`) is called from resource uploads and the character-pack upload, never from the message upload path. Evidence: `openspec/specs/esbabbler/file-media/design.md`, lines 13 to 16, which admits the gap. Why it matters: a client can write past the room cap for as long as its write SAS lives, and message files count against no allowance, so the storage bill has no bound. **Missing proposal**: charge message uploads to the owner's allowance and reconcile their size from the committed blob, on the same path resource assets use.

2. **Two Nuxt security options do nothing.** `ssg.exportToPresets` and `ssg.nitroHeaders` are validated (`packages/nuxt-security-module/src/schemas/ssgOptionsSchema.ts`, lines 6 and 10) and default to `true` (`packages/nuxt-security-module/src/services/getDefaultModuleOptions.ts`, line 30), but no runtime or module code reads either. The package's own spec says so: `openspec/specs/nuxt-security-module/README.md`, item 3 of its unbuilt list, reads "the `ssg.nitroHeaders` and `ssg.exportToPresets` options are read but not yet acted on". Why it matters: a site owner who sets them believes a header behaviour changed when nothing did. **Bug to file**: either build the prerendered headers file the spec names, or delete both options in the same change.

3. **Account deletion and data export may already be due.** Both are deferred until "the platform opens to real external users, or the first genuine deletion request arrives" (`openspec/deferred/user/account-deletion/design.md`, line 7; `openspec/deferred/user/data-export/design.md`, line 7). The public side is already open: browsing stays open to anonymous visitors (`openspec/specs/architecture/auth/spec.md`, lines 38 and 118), the profile page is open to signed-out visitors (`openspec/specs/user/public-profile/spec.md`, line 7), and sign-in is through social providers (`openspec/specs/user/account-linking/design.md`). The paid-storage proposal adds a second reason to ship both, since taking money "turns the deferred account deletion and data export obligations into the price of shipping" (`openspec/changes/resource-paid-storage-tiers/proposal.md`, Why), a trigger neither deferred page names. Why it matters: a data-rights obligation may already attach, and a roadmap item is blocked on it. **Deferred, revisit**: decide whether the external-users trigger has fired, and name the paid-tier trigger on both pages.

4. **A Dashboard cannot be exported in any form.** The portable map has entries for Email, Flowchart, Note, Sheet, TodoList and Webpage only (`apps/web/app/services/resource/PortableFormatMap.ts`). A Dashboard is a dataset consumer, not a provider, so the CSV command in `apps/web/app/services/resource/getResourceBladeItems.ts` (lines 41 to 43) does not reach it, and no spec covers a dashboard image, a PDF or a print. The resource roadmap names Power BI as the Dashboard's depth reference, and Power BI exports the page and each visual's rows. Why it matters: a report is the one type whose output a reader most often sends on. **Missing proposal**: a dashboard page export, and each visual's rows as CSV from the data it already binds.

5. **A moderator cannot set another member's display name.** The `ManageDisplayNames` bit exists (`packages/db-schema/src/models/message/RoomPermission.ts`, line 18) and the server checks it (`apps/web/server/services/message/updateUserToRoom.ts`, line 24), but the only UI is self-service in `apps/web/app/components/Message/Model/Room/Settings/Type/Profile/DisplayNameField.vue`. `openspec/specs/esbabbler/nicknames/design.md`, line 75, admits it. Why it matters: a role can be granted a permission the interface never lets it use. The esbabbler roadmap's nickname item is the global-name subtitle, a different feature. **Missing proposal**: a member-action path that sets another member's room display name, gated by that bit.

6. **Two client-data rules are enforced by review alone.** `openspec/specs/architecture/client-data/design.md`, lines 186 and 191, mark "an optimistic count" and "two reads sent in one tick, one held open" as **not yet mechanically enforced**. The enforcement ladder says a defect's fix changes the shape or adds a rung (`openspec/specs/architecture/enforcement-ladder/spec.md`, the requirement at line 41). Why it matters: the rules are the ones a reviewer is most likely to miss. **Missing proposal**: a lint or test rung for each, so the rule holds without a reader.

7. **A webpage's survey invite takes a bare survey id.** The SurveyInvite node's `surveyId` is a plain id field, and no component reads the owner's published surveys (`openspec/specs/resource/webpage-survey-invite-blocks/design.md`, line 41 and its Notes). Why it matters: an owner must paste an id copied from elsewhere, where every other reference in the editor is a picker. This is not on the resource roadmap. **Missing proposal**: the picker the spec calls owed.

8. **The `config` abbreviation is in code and outside the naming rule.** `apps/web/app/components/Ui/SchemaForm/Index.vue` declares a local `config` (line 25) and writes `jsonforms.config` (line 62), and `apps/web/app/composables/ui/useSchemaFormControl.ts` declares one at line 13. The naming skill says "no abbreviations" (`.agents/skills/naming/SKILL.md`, line 68), but its abbreviations reference does not list `config`, so no lint rule catches the breach. The rule that forbids it is recorded only in the auto-memory. The `control.value.config` read at line 13 is the form library's own key and stays as it is. Why it matters: the convention exists in one place a session may not read. **Bug to file**: rename the local variables, and add `config` to the naming skill's abbreviation reference in the same change.

9. **A Blueprint has no export or import file.** The portable map has no Blueprint entry, and the manifest can be copied only from its Editor blade, a JSON editor (`openspec/specs/resource/blueprint-resource/design.md`, line 41). Capture reads resources in and deploy writes them out, but neither produces a file another owner can take. The resource roadmap names the Azure portal's template deployment as the Blueprint's reference, and that product exports and imports the template. Why it matters: a blueprint is the one resource whose purpose is to be reused elsewhere. **Missing proposal**: a manifest export and import through the Portable capability.

10. **Free-text tag search is not wired.** The tags spec says so: "Free-text tag search inside global search is not wired up" (`openspec/specs/resource/tags/design.md`, line 52). Global search matches names only, and tags are reached through the All filter pill and the tags list. The resource roadmap does not name it. Why it matters: an owner who remembers a tag and not a resource's name cannot find it from the palette. **Missing proposal**: a tag match in the search procedure's results, on the same relevance path.

11. **`keyframe-store` is a published library with no area.** It is an npm package with its own README (`packages/keyframe-store/README.md`), and no `openspec/specs/keyframe-store/` folder exists. Its behaviour is split between `openspec/specs/architecture/compression/` and `openspec/specs/resource/resource-version-store/`. The openspec skill's page-shapes reference says a library another project could install gets an area, as `parse-tmx` and `trpc-msw` have (`.agents/skills/openspec/references/page-shapes.md`, line 31). Why it matters: a published package's requirements are owned by no page a consumer can read. **Missing proposal**: a `keyframe-store` area with its requirements and its Upstream table if it replaced anything.

12. **The nuxt-security-module's unbuilt work is on no roadmap.** Its README lists what is "Not built yet, in order" (`openspec/specs/nuxt-security-module/README.md`, lines 20 to 26): a run in a built app, regression tests checked against upstream, the prerendered headers file (item 2 above), the SRI checks on preload links and import maps, and the FEATURE rows the audit judges worth having. The repository's roadmaps cover esbabbler, genshin, infra, post and resource only. Why it matters: work a spec names as owed has no index a session reads before picking up new work. **Missing proposal**: an architecture roadmap entry, or a single proposal, for the unbuilt list.

13. **`shared-node` has no capability pages.** Its three parts, the machine-wide download cache, the hidden-window child processes and the benchmark reporting, are described in no spec under `openspec/specs/`. The only spec that cites the package is `openspec/specs/genshin/hosted-game-data/design.md`, which is outside this survey's bounds. The page-shapes rule gives a package that serves the repo no area, but says its capability pages describe it. Why it matters: a session changing the cache has no record of the rules it keeps. **Missing proposal**: capability pages under `openspec/specs/architecture/` for the three parts.

14. **A dataset row-cap deferral may have met its consumers.** `openspec/deferred/resource/dataset-row-cap-pagination/design.md` (line 11) revisits "when a real consumer (dashboard binding, Sheet import, email personalized export) hits the cap on real data". All three consumers shipped, and the cap is now surfaced through the warning in `openspec/specs/resource/dataset-row-cap-warning/`. The deferral does not say whether any real data has reached the cap since. Why it matters: the answer decides whether pagination is owed. **Deferred, revisit**: measure whether a real dataset has hit the cap, and decide from that rather than from the consumer list.

Items 1, 3, 4, 5, 6, 7, 9, 10, 11, 12 and 13 are the proposals in `tasks.md`. Items 2 and 8 are bugs, and items 3 and 14 are deferred revisits to decide, not proposals to write.
