# Design Canvas

## Why

Esposter has no surface for freeform, sketch-like work. A person who wants to block out a layout, box a few steps with arrows, mark up a screenshot or pin notes beside an idea has no resource to do it in. The nearest types each fit a different shape of work: the Flowchart draws connected steps on fixed handles, the Webpage and the Email are typed documents rendered to HTML, and the Dashboard is a grid over datasets. An agent has the same gap, since no type it reaches is a freeform canvas it can read and draw on.

## What Changes

- A new resource type, `Design`: a freeform canvas of rectangles, ellipses, diamonds, arrows, lines, freehand strokes, text, images and sticky-style notes, drawn in a hand-drawn style.
- Its editor is the open-source Excalidraw engine (MIT), mounted by one thin app component. This is the change's central decision. It brings React into the client as a second UI runtime, loaded only by the Design editor's chunk. The alternatives and what each costs are in the design.
- The document is one JSON content blob written through the one content door, described by a content schema that the generic agent tools read, return and patch the way they do for every other type.
- Images are file assets of the Design, and export to PNG and SVG is the Portable capability.
- Not in this change: publishing a Design, real-time collaboration, a Design-specific agent procedure, and any change to the Flowchart. The Flowchart's own future stays in its deferred page, although this change makes one of that page's options live for Design (see Waiting on).

## Capabilities

- **resource/design-canvas** (new): the Design type, its editor, its export and its agent surface.

## Impact

- A new `ResourceType` value and its Postgres enum value, through a migration generated by the drizzle skill.
- A `ResourceDefinitionMap` entry declaring `fileAssets` and `portable`, and no `publishable`.
- New catalog entries for the Excalidraw engine, React and React DOM. The engine's gzipped client size is roughly 350 KiB by an external estimate, so the repo's score tool must measure it before the editor ships (tasks 1.1 and 1.2).
- No behaviour of any existing type changes.

## Waiting on

Nothing blocks it. It does overturn one sentence of the [deferred flowchart page](../../deferred/resource/flowchart-on-editor-core/design.md), which says embedding Excalidraw "is not one of the options: it is a React application, and the app is Vue". This change makes that option live for Design. It does not decide the Flowchart's own future, which that page keeps deferred.
