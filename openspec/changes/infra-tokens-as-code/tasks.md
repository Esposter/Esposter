# Tasks

Section 1 is the code, built by a session. Section 2 needs the bootstrap token and touches production, so the lead runs it, in order, once section 1 has landed. Section 3 is the last step and archives the change.

Nothing here is ticked until its verify step has printed what it names.

## 1. Code

- [ ] 1.1 Declare the bootstrap provider "apps/infra/src/cloudflare/providers/tokenAdminProvider.ts", the helper "apps/infra/src/cloudflare/services/getAccountTokenPermissionGroupId.ts" that reads a permission group's id by name from the provider's data source, and the six account token resources under "apps/infra/src/cloudflare/resources/accountTokens/", one file each, as the table in `design.md` lists them. Scenario: "A consumer's token is an AccountToken resource with one consumer". Scenario: "A permission group is read by name". Verify: `pnpm -C apps/infra typecheck` passes, and `grep -rn "permissionGroups\[0\]\|id: \"[0-9a-f]\{32\}\"" apps/infra/src/cloudflare/resources/accountTokens` prints nothing, so no id is hard-coded.
- [ ] 1.2 Declare the explicit `cloudflare` provider in "apps/infra/src/cloudflare/providers/cloudflareProvider.ts", its `apiToken` the infra token's output, and give every Cloudflare resource the provider. Scenario: "A consumer needs one more permission group" is met by the token file alone: a consumer that needs one more group is widened by one edit to its own token file. Verify: `grep -rL "provider: cloudflareProvider" $(grep -rl "new cloudflare\." apps/infra/src)` prints nothing, and `pnpm -C scripts exec vitest run src/workspace/resourceProtection.test.ts` passes.
- [ ] 1.3 Declare the stack outputs `devR2AccessKeyId`, `devR2SecretAccessKey`, `prodR2AccessKeyId`, `prodR2SecretAccessKey`, `devRealtimeKitApiToken` and `prodRealtimeKitApiToken` in "apps/infra/src/cloudflare/outputs/", one file each. The access key id is the token's id, and the secret is the SHA-256 hex digest of the token's value, taken with `pulumi.secret` so it stays secret. Scenario: "An environment's R2 pair is derived from its token". Verify: `pnpm -C apps/infra typecheck` passes, and `pnpm -C apps/infra build` writes the barrel with each output in it.
- [ ] 1.4 Write "scripts/src/workspace/cloudflareTokenNames.test.ts" first. It reads each file in "apps/infra/src/cloudflare/resources/accountTokens/" and fails a token whose name is not `<env>-tok-esposter-<responsibility>` or `tok-esposter-<responsibility>`. Scenario: "A token name follows the convention". Verify: the test passes on the six names, and fails when one token is renamed to a name outside the convention, such as `infra-token`, with the rename reverted after the run.
- [ ] 1.5 Point the GitHub secret `CLOUDFLARE_API_TOKEN` at `tok-esposter-deploy`'s value in `apps/infra/src/github/secrets/cloudflareApiToken.ts`, and delete `apps/infra/src/cloudflareConfiguration.ts`, whose namespace read `cloudflare:apiToken`. Scenario: "Only the bootstrap token is made by hand". Verify: `grep -rn "cloudflare:apiToken\|cloudflareConfiguration\|requireSecret(\"apiToken\")" apps/infra/src scripts/src apps/web/configuration` prints nothing.
- [ ] 1.6 RealtimeKit provisioning drops its token branch: `scripts/src/services/realtimeKit/applyRealtimeKitActions.ts`, `readRealtimeKitExisting.ts`, `readPermissionGroupId.ts` and their plan in `planRealtimeKitProvision.ts`, with the tests that pin them. The provisioning keeps apps, presets and webhooks, which need Realtime Admin only. Verify: `pnpm -C scripts exec vitest run src/services/realtimeKit` passes.
- [ ] 1.7 Carry the docs: the token rows and rules in `apps/infra/docs/cloudflare/naming-conventions.md` (the `Tokens` section names the `bootstrap` exception), the Cloudflare section of `apps/infra/docs/stacks.md` (the token is `tok-esposter-infra` through the provider, and the ESC keys are the ones `design.md` keeps), and the Stack Setup note in `apps/infra/README.md`, which links the rule to `.agents/skills/security/references/credentials.md` instead of restating it. Verify: `pnpm exec oxfmt` on those files, then `git grep -n "cloudflare:apiToken"` finds only the archive and `CHANGELOG.md`.
- [ ] 1.8 Sweep the old names as `AGENTS.md` step 3 requires: `git grep` for `cloudflareBootstrapToken`, `tok-esposter-r2` (the account-wide name), `Zone Cache Rules Edit`, `Zone Rulesets Edit` and `cloudflare:apiToken` across `openspec`, `.agents`, `apps/infra/docs` and the READMEs, excluding the archive and the changelogs. Every hit is fixed in this section. Verify: the same grep prints nothing outside the archive.

## 2. Apply (the lead, with the bootstrap token)

Run each command from the repository root unless it changes directory. The token values are loaded into one command's environment and never printed. Check a value by its length.

- [ ] 2.1 Record the account's tokens before anything changes, by name, id and `last_used_on`, into a file in the scratchpad. The bootstrap's read is `curl -sS -H "Authorization: Bearer $BOOTSTRAP" "https://api.cloudflare.com/client/v4/accounts/$ACCOUNT/tokens?per_page=100"`, with `BOOTSTRAP="$(pulumi env get esposter-infra/prod bootstrapToken --value string --show-secrets)"` in the same command. Verify: the file lists `tok-esposter-infra`, `tok-esposter-r2`, `dev-tok-esposter-realtimekit` and `prod-tok-esposter-realtimekit`, each with an id.
- [ ] 2.2 Wire the bootstrap into the stack: `pulumi env set esposter-infra/prod pulumiConfig.esposter-infra:CLOUDFLARE_BOOTSTRAP_API_TOKEN '${bootstrapToken}'`. Verify: `BOOT="$(pulumi env get esposter-infra/prod pulumiConfig.esposter-infra:CLOUDFLARE_BOOTSTRAP_API_TOKEN --value string --show-secrets)"; echo ${#BOOT}` prints 53.
- [ ] 2.3 Preview the program: `pnpm -C apps/infra infra:preview`. Read the plan: six creates for the tokens, one provider create, and an update to each Cloudflare resource's provider. A replacement stops here, since `protect: true` would refuse it at apply. Verify: `pnpm -C apps/infra infra:preview 2>&1 | grep -E "replace|delete"` prints nothing that is a Cloudflare resource. Expected: resources under the provider show as unknown until the infra token exists, which is why 2.4 is read after it runs.
- [ ] 2.4 Apply untargeted: `pnpm -C apps/infra infra:up`. If Pulumi refuses it with the provider-registration error `references/operations.md` describes, that is the targeted run's error and the untargeted run is the one that succeeds. Verify: the run ends with no error, and `pnpm -C apps/infra infra:preview` then reports no changes.
- [ ] 2.5 Write the outputs into ESC, one command per key, each value passed through a subshell and never printed: `pulumi env set esposter-infra/prod pulumiConfig.esposter-infra:dev_R2_ACCESS_KEY_ID "$(cd apps/infra && pulumi stack output devR2AccessKeyId --show-secrets)" --secret`, then the same for `dev_R2_SECRET_ACCESS_KEY`, `prod_R2_ACCESS_KEY_ID`, `prod_R2_SECRET_ACCESS_KEY`, `dev_REALTIMEKIT_API_TOKEN` and `prod_REALTIMEKIT_API_TOKEN` from their outputs. Verify: each key's length is 32 for an access key id, 64 for a secret access key, and the RealtimeKit token's length matches the one 2.1 implies.
- [ ] 2.6 Verify each token's reach with the verify endpoint, the token loaded from its output or from ESC into the one command. For the realtime token: `curl -sS -H "Authorization: Bearer $TOKEN" "https://api.cloudflare.com/client/v4/accounts/$ACCOUNT/tokens/verify"` answers `status` `active`. Verify the R2 pair with a signed request, which also settles the digest encoding `design.md` leaves to it: `curl -sS --aws-sigv4 "aws:amz:auto:s3" -K <(printf 'user = "%s:%s"\n' "$ID" "$SECRET") "https://$ACCOUNT.r2.cloudflarestorage.com/<env>-r2-esposter-user-assets?list-type=2"` answers HTTP 200 for each environment. A 403 means the pair lacks the bucket's group, and the fix is the token file, not the pair. Scenario: "An environment's R2 pair is derived from its token" is the check this step runs.
- [ ] 2.7 Deploy: the apply has set the GitHub secret to the deploy token's value. Run Deploy on `ai/queue` through the CI run that triggers it, which puts the realtime Worker's new secret. Verify: `gh run list --workflow Deploy.yaml --limit 1` reports `success`, and `last_used_on` for `tok-esposter-deploy` moved.
- [ ] 2.8 Delete the hand-made tokens by the ids 2.1 recorded, once each one's `last_used_on` has not moved since the switch and the Deploy in 2.7 is green: `curl -sS -X DELETE -H "Authorization: Bearer $BOOTSTRAP" "https://api.cloudflare.com/client/v4/accounts/$ACCOUNT/tokens/<id>"`, for `tok-esposter-infra`, `tok-esposter-r2`, and the two `*-tok-esposter-realtimekit`. Verify: each answer is `success: true`, and the list no longer carries the id.
- [ ] 2.9 Delete the ESC keys the change retired: `pulumi env rm esposter-infra/prod pulumiConfig.cloudflare:apiToken` and `pulumi env rm esposter-infra/prod cloudflareBootstrapToken`. Verify: `pulumi env open esposter-infra/prod --format json | node -e` printing only the key paths no longer shows either key, and `bootstrapToken` and `pulumiConfig.esposter-infra:CLOUDFLARE_BOOTSTRAP_API_TOKEN` are still there.
- [ ] 2.10 Refresh the local copies that hold the old values, "apps/web/.env" and "apps/web/.env.production", from ESC by hand, and check the key names only. Verify: `grep -c "R2_ACCESS_KEY_ID" apps/web/.env` is 1, with its length checked as in 2.5.
