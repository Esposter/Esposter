# Cost & Security Posture

Esposter's Cloudflare estate is deliberately small. The Workers, D1, R2, Queues, Durable Objects and RealtimeKit all run on the paid plan's included allowances, and nothing shuts a product off automatically when spend appears. This page records the posture decisions the estate keeps on purpose and why.

## Cost

The cost ceiling is the paid plan's included allowances and the usage the program's own design bounds: each room, call and person has its own object, each message is one batch of a few statements, and each upload is one presigned PUT. Nothing in the estate turns a product off on a budget, so a cost spike is seen as a spike on the account and corrected by a person.

No spend alert is declared. Cloudflare's account-wide spend alert is a billing notification with a total-spend filter, and `@pulumi/cloudflare` cannot declare that filter, so the program declares no budget. Creating the alert by hand in the dashboard was rejected, since it leaves an account resource the program does not declare. The alert is declared once the provider's notification filters can express it.

## Posture decisions

| Area               | Posture                                                                                                                                                                                                                           | Why                                                                                                                                                                                                                                                                                                                                                                             |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Workers            | The web Worker is stateless and public; the jobs Worker is reached by its queues and its Cron Trigger, and the realtime Worker by the web and jobs Workers' bindings to its objects                                               | Live state lives in the objects, so no isolate holds anything between requests                                                                                                                                                                                                                                                                                                  |
| D1                 | One database, `core`, reached through its binding; no connection string in code                                                                                                                                                   | D1 is reached without a connection to pool, and the deploy token is the one credential the migrations use                                                                                                                                                                                                                                                                       |
| R2                 | Buckets are private by default; a `public-` bucket is served on a custom domain; private reads go through a presigned GET                                                                                                         | Public assets stay stable and cacheable at the edge, and everything else is reached for a few minutes at a time                                                                                                                                                                                                                                                                 |
| Queues             | Each job has its own queue and dead-letter queue, consumed only by the jobs Worker                                                                                                                                                | Retries and failures stay per job, and a job's failure never blocks another job's queue                                                                                                                                                                                                                                                                                         |
| Stateful resources | D1 databases, R2 buckets, queues and queue consumers are declared `protect: true`                                                                                                                                                 | They hold data, so a replace deletes it; protection makes the delete a refused change rather than a silent one                                                                                                                                                                                                                                                                  |
| Bots               | Bot Fight Mode, AI-bot blocking and JavaScript detections are off, declared in `esposterComBotManagement`                                                                                                                         | On the free plan Bot Fight Mode challenges every datacenter caller zone-wide, and no rule exempts a host: it refused the webhooks, the call provider's events and CI's reads of the assets hosts, and its detections script rode on every page                                                                                                                                  |
| Secrets            | Each secret is a schema key marked secret, read from the secrets environment and written to the Worker by the deploy job                                                                                                          | No secret value is in code, in the Worker's configuration file or in the repository                                                                                                                                                                                                                                                                                             |
| Claude Code in CI  | The warmup and the review run `pnpm dlx @anthropic-ai/claude-code` unpinned. The warmup's step holds `CLAUDE_CODE_OAUTH_TOKEN`; a review session's environment drops every other secret-shaped variable and keeps only that token | Accepted. A lock pin runs the same release with the token, since under the freshest-version policy Renovate moves the pin to each release on green, and it would add the CLI's native binary to every install (`dependency-updates` SKILL.md, Settled). Revisit if a session is given any credential beyond its own token, since the stripping is what keeps those out of reach |
| Registration       | `esposter.com` is registered at Cloudflare Registrar with auto-renew, the registrar lock and WHOIS redaction on, and the registration is not a Pulumi resource                                                                    | The provider has no registrar resource and the Registrar API does not yet cover renewals or contact updates, so the three settings are recorded here and read back in the dashboard                                                                                                                                                                                             |
| Expiry             | No expiry alert is declared. Cloudflare emails the Super Admin monthly from 45 days before expiry and the registrant weekly in the last month, and retries a failed renewal three times before it turns manual                    | Cloudflare's notification types include none for a domain's expiry, so both inboxes are read by a person                                                                                                                                                                                                                                                                        |
| Account sign-in    | The owner signs in through GitHub, admin roles stay few, the deploy token carries no registrar permission, and no two-factor enforcement is declared                                                                              | An admin role can unlock the domain and take its auth code, so the account is the domain's security. Enforcement would need the account imported and a token that writes account settings, for an account with one login; a second member reopens it                                                                                                                            |
| DNS                | DNSSEC is on, declared in `esposterComDnssec`, and Cloudflare publishes the DS record at the registry itself. The domain publishes a null MX, `v=spf1 -all` and `v=DMARC1; p=reject;`                                             | Without them, mail forged as the domain has no published policy to fail against. Reviving inbound mail deletes the null MX and the SPF record before Email Routing writes its own, and keeps the DMARC record                                                                                                                                                                   |

## Review principles

An infrastructure change prefers reducing exposed surface before adding recurring cost, and is reviewed for dev and prod separately, though one stack owns both.

## Key files

| File                                                        | Role                                                            |
| ----------------------------------------------------------- | --------------------------------------------------------------- |
| `apps/infra/src/cloudflare/resources/d1Databases/`          | The `core` database per environment, protected                  |
| `apps/infra/src/cloudflare/resources/r2Buckets/`            | The buckets per environment, protected, `public-` buckets named |
| `apps/infra/src/cloudflare/resources/r2BucketLifecycles/`   | The message-assets rule moving objects to Infrequent Access     |
| `apps/infra/src/cloudflare/resources/queues/`               | One queue and one dead-letter queue per job, per environment    |
| `apps/infra/src/cloudflare/resources/queueConsumers/`       | Each queue's consumer on the jobs Worker, protected             |
| `apps/infra/src/cloudflare/resources/workersCustomDomains/` | The custom domains of the web Worker                            |
| `apps/infra/src/cloudflare/resources/botManagements/`       | The zone's bot settings                                         |
| `apps/infra/src/cloudflare/resources/zoneDnssecs/`          | The zone's DNSSEC signing                                       |
| `apps/infra/src/cloudflare/resources/dnsRecords/`           | The zone's records, the no-mail baseline among them             |

## Sources

- [Cloudflare DNSSEC](https://developers.cloudflare.com/dns/dnssec/) and [Enable DNSSEC](https://developers.cloudflare.com/registrar/get-started/enable-dnssec/): the DS record added automatically for a Cloudflare Registrar domain, and its one-to-two-day publication.
- [Registrar API](https://developers.cloudflare.com/registrar/registrar-api/) and [Renew domains](https://developers.cloudflare.com/registrar/account-options/renew-domains/): what the API does not yet cover, and the expiry and failed-renewal emails.
- [Cloudflare account two-factor authentication](https://developers.cloudflare.com/fundamentals/user-profiles/2fa/) and [Transfer out from Cloudflare](https://developers.cloudflare.com/registrar/account-options/transfer-out-from-cloudflare/): Super Admin enforcement, and the warning that admin roles can unlock a domain and take its auth code.
- [Cloudflare login options](https://developers.cloudflare.com/fundamentals/user-profiles/login/): social login through GitHub, with Cloudflare's own second factor in addition to the provider's.
- [RFC 7505](https://www.rfc-editor.org/rfc/rfc7505): the null MX record, which says a domain accepts no mail.
