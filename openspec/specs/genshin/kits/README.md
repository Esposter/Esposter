# Character kits

A character's combat kit is its skills, cooldowns, costs and talent multipliers, and the game keeps those in its tables by the character's skill sets. Every playable character's kit is written on the framework below: the skill sets and talent multipliers read from the tables, the targeting that turns an action to its enemy, and the shared effects and kit events every kit uses. The table at the end links one page per character, and it is the record of which kits are built. The kits' hits are [combat](../combat/design.md)'s, and the kit's action state machine is documented there too. The attributes a kit is priced from are on [character attributes](../character-attributes/design.md), and the character's movement on the field is on [character controller](../character-controller/design.md).

## Skill sets

A character has one skill set in its own form, and a set for each element form its element may take, the one a statue's element picks. A set holds a skill, the character's elemental skill, and a burst, its energy skill, each read from the skill table by its id. The skill has a cooldown and its charges, the burst a cooldown, an energy cost and the element it deals, the element its energy is named as.

```mermaid
flowchart LR
  AV["AvatarExcelConfigData: each avatar's own skill sets and the element sets it may take"] --> RD["getCharacterSkillKits: each set's skill and burst, read from their rows"]
  SK["AvatarSkillDepotExcelConfigData and AvatarSkillExcelConfigData, in the dump"] --> RD
  RD --> JSON["stats/characterSkillKits, published with the other stat tables"]
  JSON --> APP["the hosted game data; no kit reads it yet"]
```

- **A set with neither a skill nor a burst is left out.** A character none of whose sets has either is left out too. One of the Traveler's element sets, 705, holds neither in this dump, so the dump gives the Traveler no form for it.
- **A burst's element is the one its energy names, when it names one of the seven.** A burst that costs no element has none. Which set a Traveler's kit reads is for the element a statue gives, which is not built yet.
- **The table is published by** `pnpm -C scripts genshin:assets stats`, the same run as the characters, weapons and artifacts. Each character is checked against the world's schema as it is built.

## Talent multipliers

The stats run publishes each playable character's combat talent multipliers as its own entry of the `talentMultipliers` index, by its avatar id, keyed by the talent's proud skill group. A level keeps its parameters (`paramList`) up to the last one that is not zero, so a read past that point is zero. The labels, the text id naming each parameter (`paramDescList`), go apart into the character's entry of the `talentLabels` index, which the combat table never carries.

Each character's multipliers are an entry of the hosted `talentMultipliers` index, under its avatar id ([hosted game data](../hosted-game-data/design.md)). `TalentMultiplierLoaderMap` is keyed by avatar id, and each entry reads that character's record from the world's game data base and checks it against its schema. `readTalentMultipliers` merges the records it is given by group, and `getTalentMultiplier` reads a parameter from the table by its index, which `buildKit` does for each parameter a kit's record names. `readCharacterKits` builds each joining character's kit once (`readCharacterKit`), from its multipliers, its `kits` record and its behaviour module, the three read together as the character joins, and `buildKit` turns the record's frames into seconds and its parameters into the tables' values, joins the behaviour and tags the hits; a character with no module fights with the Traveler's kit, from the Traveler's record, multipliers and behaviour. The world's gate reads the starting team's kits before the world opens, so its first frame has each member's combatant, and the world reads a character's as the team changes to take it in, reading a failed read again `DATA_FETCH_RETRY_MS` later, since a team that stays as it is starts no other. The world's entry carries neither: the multipliers' loader map replaced one static import that was 1.4 MB of it, and the behaviour map loads each module through its own `import()`, which the build splits into a chunk, while the barrel leaves the modules out. A member whose kit is still in flight has no combatant yet, which is a loading state rather than an error: it gains no energy, and on the field its kit's step waits, starting no attack, skill or burst and holding the team's effects, while the body moves on. The entry stays under the 1,350,000 the framework aims for with the kit modules and every character's icons out of it. The aim is a prompt rather than a gate, since nothing fails past it: crossing it calls for a cut that loses nothing, no point of a trace and no clarity of the code, and it is raised only when no such cut is left. What holds it is none of a character's: the glyph path maps the screens share (about 150 KB of path data, the element marks' and the Paimon menu's entries' the most of them, each traced path written in its shortest form, see [parity tracing](../parity/tracing/design.md)), the components (about 350 KB), the kit framework (about 74 KB) and the loader maps naming each character's hosted entries. The entry's size snapshot (`src/index.test.ts`) holds the figure. A character's skill and burst icons are per-character data like a kit, so they are hosted, one entry a character of the `skillGlyphs` index ([HUD](../hud/design.md)), and `readCharacterKit` reads a character's through `SkillGlyphsLoaderMap` by its own id beside the kit's three reads, so the kit carries them to the HUD and the entry holds none.

```mermaid
flowchart LR
  P["ProudSkillExcelConfigData: each group's levels and their parameters"] -->|"stats run, one record per character"| M["talentMultipliers index: avatar id to its record, keyed by group"]
  M -->|"fetched at the gate or as a character joins, checked by its schema"| R["readCharacterKit: the three read together as a character joins"]
  K["kits index: avatar id to its record, published by genshin:assets kits"] -->|"fetched beside the multipliers, checked by its schema"| R
  C["CharacterIdCreateKitBehaviourMap: each module's import(), a chunk of its own"] -->|"loaded as its character joins"| R
  G["skillGlyphs index: avatar id to its icons, published by genshin:assets skill-glyphs"] -->|"fetched beside the multipliers, by the character's own id"| R
  R -->|"buildKit: the record resolved and the behaviour joined"| T["the character's kit, built once: the Traveler's for a character with no module"]
```

Talent levels and constellations are read at the level the kit is built at: raising them is the [talents](../talents/design.md) and [constellations](../../../changes/genshin-constellations/design.md) pages'.

## Targeting

An action turns the body to the enemy it targets as it starts. That is the living enemy inside the action's targeting area scoring highest, where an enemy's score is 0.7 times its nearness to the body within the area's radius, plus 0.3 times its nearness to straight ahead, the angle from the body's facing over a half-turn. An enemy more than 2 metres above or below the body scores a fifth of that. Enemies outside the area, and the dead, are not targeted. The view, current-target and priority coefficients are not built.

## Shared effects

Each effect is on the party, in the list a `KitEffectState` holds, so a switch leaves it running, and a drown or a jump clears it. Each one is ticked each step.

- **Damage** is a hit: its talent multiplier, its gauge of an element, the element it names when it is not its character's own, the DMG Bonus it carries of its own, if any, added to its striker's as it is priced, and the additive base damage it reads from its striker, if any, added to its base damage. A hit with no internal cooldown applies its whole gauge, and one under a cooldown shares it through it.
- **Infusion** makes the character's normal attacks, charged attack and plunges deal its element at the gauge the hit gives it, 1U for a strike and 0U for a collision. One that converts the attacks gives each hit its converted poise and reach where it has them, and one with a DMG Bonus adds it to each hit it infuses, as Bane of All Evil's does to Xiao's Normal, Charged and Plunging Attacks alone. It is refreshed by a second one of its kind on the same character, not stacked.
- **Buff** adds a stat bonus to the character's pricing for its seconds: a flat ATK adds to its attack and any other bonus to its attribute total. It is refreshed by one of its attribute from the same source on the same character, not stacked: a source names the effect that gives it, so two effects on one attribute run side by side, as Sprawling Greenery's two Elemental Mastery buffs do. A kit gives one to a member in a call (`buffKitMember`), and the same one to every member of the deployed team, each its own, in another (`buffKitTeam`).
- **Heal and drain** are `changeKitMemberHealth`, the one way a kit changes a member's current HP, its own or another's, by an amount of HP: a heal is raised by its source's Healing Bonus and the member's Incoming Healing Bonus as the buffs on them stand, and a drain is taken as it is, as gcsim's `Heal` and `Drain` price them. Under it, the party's `healPartyMember` and `damagePartyMember` change a share of a standing member's Max HP, a heal never above all of it and a drain never below none, and a downed member stays down, as only a revive brings one back. Each records its change in the party's `healthChanges`, which [party](../party/design.md) describes and `HealthChanged` sends to the kits.
- **Energy** is the party's `gainPartyEnergy`, which an enemy's drop calls through `collectKitEnergyDrops`.
- **Field** is a circle placed where its character casts, for its seconds, with a tick on a schedule. Each tick runs while the body stands inside it, reading the character on the field and the team, and a tick's own buffs and infusions start at their full seconds. A tick that lands a hit casts it as a summon from the field's centre rather than the body, so a field that stays where it was cast lands its ticks from there whatever the body does after, as gcsim fixes a field's area as it is cast. A kit casts one in a call (`castKitField`), naming its schedule and its seconds, and its radius unless it reaches the body wherever it stands, and the call returns the field for a kit that reads it again. A task is how a kit sets something going a few frames on, as gcsim queues a task on its character: a field with no edge whose one tick runs after its delay (`scheduleKitTask`).
- **Summon** is an entity cast where its character stands, which lands its own hits on the seconds their hitmarks fall at, for its seconds. It is priced by the combatant that cast it, as it stood then, and its hits land from its own body, not the character's. A summon may travel: its body moves forward at its speed from its start on its clock, and its hits are reached from where it is then. A summon may follow the body on the field instead: its body stands where that body stands on each step, whoever is on the field, and its hits are reached from there. A summon whose seconds end on its last hitmark lives `SUMMON_LINGER_SECONDS` past it, so the step that lands its last hit still has it on the field however its clock and its seconds left round. A summon its kit ends, as Durin's recast ends his Dragon and Yae Miko's burst her totems, lands nothing from the next step, as gcsim's ticks check that their summon still stands. Its hits are dealt as the kind of attack its kit names as it casts it (`KitSummon.attackTag`), gcsim's attack tag for them, and as none where its kit names none. A kit casts one in a call (`castKitSummon`), naming its id, its kind, its seconds and the enemy it strikes, if it strikes one, beside its hits, the call returning the summon for a kit that reads it again. The hits that land every interval from a first frame, as Guoba's and the steles' do, are a list in the kit's record, each at its own hitmark's frames, and a kit whose count is set as it plays, as Oz's is by its seconds, builds them from the seconds its record holds. An action's hits whose hitmarks fall past its end are a summon too, cast as the action runs its course (`queueKitHits`), so each lands at its hitmark through a later action or a swap, dealt as the action's kind of attack and infused as it lands, by [combat's timing rule](../combat/design.md): an action's `seconds` is its gcsim cancel, never stretched to its last hit.
- **A coordinated summon** is set going by the character on the field, whoever that is: as that character starts a normal attack, `coordinateKitSummons` runs each summon's `onNormalAttackStart` with the world's context, whose body and combatant are that character's, called by the character component beside the action's own start. Any other action sets none going, and the summon's hook decides what it casts.
- **A shield** is set on the team by the character that casts it, for the seconds left of it, and is recast over the one that character already holds. It takes the damage the character on the field takes, whichever character cast it: an enemy's strike is taken by every live shield at once, each absorbing the full damage through the combat's `absorbShieldDamage` at the struck character's shield strength, and the character loses the least any of them passes on. The wiki gives the rule in its own words: "when the active character takes damage, damage is dealt to shield health first", and "When a character has more than one shield, the damage dealt by an enemy will affect every active shield simultaneously" ([Shield](https://genshin-impact.fandom.com/wiki/Shield)). A shield is dropped once its health is spent. A shield with an explosion goes off as it ends, whether its seconds run out, its health is spent or it is recast over. A kit casts one in a call (`castKitShield`), naming its element, health and seconds and its explosion if it carries one, and the call returns the shield for a kit that reads it again, as Zhongli's Jade Shield does; a Crystallize shard's shield is cast through it too.
- **A taunt** is an entity placed where its character cast it, with health, which draws the enemies' strikes while it stands. A taunt that carries an explosion explodes once, from its body and priced by the combatant that cast it, when its seconds run out or its health is gone, and one that carries none, as Ushi does, ends dealing nothing. `castKitTaunt` casts one, copying its body so it stays where it was cast. An enemy within its aggro range strikes it instead of the character, and each strike is taken from its health by `damageKitTaunt`, which puts the damage on the context's outbox for the kits to hear as `TauntDamaged`.
- **A bubble** is held on one enemy by a hit that casts it, for its seconds. A hit with poise damage bursts it, as its seconds running out do: the Omen goes on the enemy from the burst, and the explosion lands on that enemy alone, from where it stands, priced by the combatant that cast it. A hit that casts a bubble holds the enemy in one, and never restarts the one it holds, since each cast's bubble bursts on its own.
- **A status on a character** is a mark it carries for its seconds, by an id (`KitStatus`), as gcsim's character statuses are: a passive's or a constellation's own cooldown, such as Thundering Retribution's half second on the character on the field, or a mark a kit reads later, such as Havoc: Annihilation's on Tartaglia's stance. A second one of its id on the same character restarts it. A kit adds one in a call (`addKitStatus`), and a gate on a repeat starts its cooldown and learns whether one is still running in another (`startKitCooldown`), one that has run out on a step letting the gate through on it, as gcsim's `StatusIsActive` reads a status's expiry. `findKitStatus` reads it, `checkHasKitStatus` whether it is there, and `checkIsKitStatusActive` whether it has not run out, as one that runs out on a step stays among the effects until that step drops it.
- **A resource on a character** is a count with a cap that outlives any timer, such as Raiden's Resolve, Itto's Superlative Superstrength, Eula's Lightfall Sword stacks and Aloy's coils, held as a status that never runs out whose stacks are the amount. `gainKitResource` adds to it up to its maximum and returns what is held then, `spendKitResource` drops it at once and returns what it held, and `countKitResource` reads it.
- **A stance** plays its own normal attacks, charged attack and its stamina, skill and burst in place of its character's kit while it lasts (`KitStance`), and counts the seconds it has held, which its end reads. `enterKitStance` builds its combatant once as it starts, the character's combatant with the stance's actions in place in its kit, and the step of the character on the field plays the combatant of the stance it holds (`findKitStance`), its attributes as they stood as the stance started, so a stance's attacks are that character's normal and charged attacks wherever a kit's actions are read: their hits' kinds, an infusion, a coordinated summon. A stance that ends on a swap (`isEndedOnSwap`) ends as its character leaves the field, before the team's kits hear of the swap, as gcsim's exit handlers delete theirs: Soukai Kanka, Pactsworn Pathclearer, Nilou's two, Musou Isshin, the Seven-Phase Flash, the Melee Stance, Niwabi Fire-Dance, Paramita Papilio, the Ceremonial Garment, Painted Dome's and Manifest Flame's. A buff or an infusion that ends on a swap ends with them, as the Paramita's Pyro infusion and ATK and Royal Descent's do, and so does a summon its character cast, as Klee's sparks do, landing nothing from the swap's step (`endKitSwapEffects`). Zhongli's RES cut stands on his Jade Shield rather than the field, as gcsim's shred tasks read his `shielded` tag, and Razor's Wolf Within, Xiao's Bane of All Evil and Ningguang's Star Jades keep a field of their own that ticks every step: Razor's first tick at the hitmark gives his bonus only if he still stands on the field, Xiao's drain and Tamer of Demons read his infusion standing within the swap's own step, and a Star Jade a gem gives after Ningguang has left ends on the next step, where no swap follows. Itto's Arataki Kesagiri stance, which his stacks hold, Durin's and the Windfavored state, during which gcsim allows no swap, stay.
- **A stance's hits deal the kind of attack of the group they play in**, set as its kit is built, unless a hit names its own: Nilou's sword dance plays as her normal attacks but names Elemental Skill DMG, and Ayato's Shunsuiken slashes are Normal Attack DMG.
- **A field may lower cooldowns.** A skill or a burst cast while the body stands inside a field with a `cooldownMultiplier` has its cooldown multiplied by it, each such field multiplying in turn, as Atmospheric Revolution's frost field does (`getKitFieldCooldownMultiplier`).
- **An infusion may quicken the normal attacks.** An infusion with a `normalAttackSpeedBonus` plays each normal attack of its character that much faster, its seconds and its hitmarks alike, as Steady Breathing's does.
- **A strike may carry a DMG Bonus against some enemies.** A kit's `getStrikeDamageBonus` reads each of its own strikes and the enemy it lands on, and adds what it returns to the hit's DMG Bonus as it is priced, as Frozen to the Bone's 15% against an enemy with Cryo on it and Rally of Four Blades' 15% against an enemy with less of its HP left do. `getStrikeCriticalRateBonus` does the same for the hit's CRIT Rate, and `getStrikeAdditiveBaseDamageBonus` adds a flat amount to its base damage; both read the team's effects.
- **A Moonsign character's kit holds its Moonsign Benediction** (`moonsignBenediction`): the Lunar reactions it turns the party's reactions into and the Base DMG Bonus it gives them from its holder's stats, which the deployed team's Moonsign reads as each strike lands. A `lunarHit` on a hit makes it a direct Lunar hit, which [combat](../combat/design.md#lunar-reactions) prices from the stat its `getScalingStat` reads, ATK if none, as Hymn of Eternal Rest's Lunar-Bloom is. The party's Verdant Dew is the Lunar-Bloom's resource, which a kit spends with `spendVerdantDew`.
- **A Stellar Linchpin character's kit holds its Stellar Jubilee** (`stellarJubilee`): the Stellar reactions it enables for its party while it is deployed. The deployed team's enablers are read as each strike lands, and a Superconduct or a Cryo Swirl becomes a Stellar-Conduct or a Stellar Swirl only while one of them enables it, as [combat](../combat/design.md) prices it.
- **A status on an enemy may strike on its own schedule.** A status with a `tickIntervalSeconds` counts down to its next tick, and each tick that falls due while it lasts is put on the outbox (`tickEnemyStatuses`), which the step sends to the kits at once, as Hydrospout's on Riptide is. A refresh restarts its seconds and keeps the schedule it holds. A status may also cut the ATK the enemy strikes with by its `attackReduction`, as Divine Suppression's Talisman does, and a status's own interval is a status of its own, as Riptide Flash's 0.7 seconds on each enemy are.

## Kit events

A passive or a constellation that answers something happening in combat is a kit's `onKitEvent`, one handler on each kit over one channel. The step of the character on the field sends each event to the kit of every member of the deployed team whose combatant is built, on the field or off it (`emitKitEvent`), and each kit reads it as its own character, whose ascension and constellation count gate what it does. A handler writes through the team's effects, the party and the enemy's statuses, and a strike it sets off is a summon cast at the enemy or the body, landing a frame or more on, as gcsim queues them.

  STEP -->|"a normal attack's first hitmark falls"| LANDED["NormalAttackLanded"]
  STEP -->|"a burst starts, ahead of its own start"| BURST["BurstUsed"]
  STEP -->|"a skill starts, as a burst does"| SKILL["SkillUsed"]
  STEP -->|"a charged attack's first hitmark falls"| CHARGED["ChargedAttackLanded"]

- **CharacterSwapped** carries the character that left the field and the one now on it, read off the character the team's effects last stepped with (`KitEffectState.fieldCharacterId`). Chongyun's field infuses the one coming on, Ayato's Namisen stacks clear as he leaves, and Fischl's burst spawns its Oz at once.
- **TauntDamaged** carries a taunt on the team and the damage an enemy's strike dealt it. `damageKitTaunt` puts each strike on the outbox (`KitContext.outbox`) as it lands, between steps, and the step sends the outbox in the order the strikes landed and empties it, ahead of its effects running down, so a strike that spends the taunt's health is heard before the taunt ends. Ushi's stack as it takes damage answers it.
- **EffectExpired** carries an effect the step dropped, its seconds run out or ended by its kit or a swap. Rimechaser Blade strikes as Chongyun's field ends, and Tartaglia's stance sets his skill's cooldown as it ends.
- **NormalAttackLanded** carries a normal attack of the character on the field as its first hitmark falls, whether or not it struck anything. Evernight Raven's Oz attacks along with it, Gaze of the Deep fires with Fischl's own, and Ice Unleashed's blades follow Chongyun's fourth strike.
- **ReactionTriggered** carries an enemy, the reactions a hit triggered on it and the combatant that dealt the hit. Thundering Retribution answers an Electro-related one the character on the field triggers while Oz stands.
- **DamageTaken** carries an enemy, the hit as it struck, its kind of attack when it is one of its kit's own actions (`KitHit.attackTag`), the combatant that dealt it, whether it was a CRIT hit and whether it defeated the enemy. The Talisman's heal, A Glimpse into Arcanum, Ascetics of Frost, Frozen Skies, and Riptide's application and every strike it sets off answer it.
- **StatusTicked** carries an enemy and the status on it whose tick fell due. Hydrospout answers Riptide's.
- **BurstUsed** carries the member that used its Elemental Burst and the burst's energy cost, sent as the burst starts and ahead of the burst's own start, as gcsim announces a burst before it plays. Resolve's stacks from another member's burst answer it.
- **SkillUsed** carries the member that used its Elemental Skill, sent as the skill starts, as a burst is.
- **ChargedAttackLanded** carries a charged attack of the character on the field as its first hitmark falls, whether or not it struck anything, as a normal attack does.
- **ElementalHit** carries an enemy, the element a hit was dealt as (its own, or the striker's where it carries a gauge) and the striker, sent for each enemy the element lands on.
- **WeakPointHit** carries an enemy and the striker of a hit whose `KitHit.weakPoint` is set. The strike sets the flag on an aimed hit (`KitStrike.isAimed`) to an enemy whose family has weak points the wiki states, the Ruin machines (the Automatons family, cited part by part in `services/enemy/enemyFamilyWeakPoints.ts`). Every aimed hit on them counts, as the aim's point and the exposure conditions (airborne, paralysed, specific attacks) are not modelled.
- **EnemyDefeated** carries the enemy and the striker, the combatant that owns the damage that took its last health, if one does. A strike sends it after its `DamageTaken`; an elemental tick, a reaction's reach and a Lunar hit send it too, and only from a standing enemy, so a dead one is never defeated twice.
- **EnergyParticleCollected** carries the particles or orbs an enemy dropped: how many, which of the two, their element, none for a clear one, and the member on the field, who collects them. It is sent once the team has taken their energy, every standing member by the game's rule, the one on the field in full and the others a share by the party's size, as gcsim distributes a particle before announcing it. Every drop is collected where it falls, a strike's, a reaction's reach or an elemental tick's alike (`collectKitEnergyDrops`). Wishes Unnumbered's Resolve answers it.
- **MoraPickedUp** carries the character on the field as it picks up Mora lying in the world. A pick up is an interaction outside the step, so the pickups emit it as a world event (`pickUpMora`), which the combat puts on the outbox for the next step to send. Lucky Dog's four-piece answers it ([artifact enhancement](../artifact-enhancement/design.md)).
- **HealthChanged** carries a recorded change to a member's HP, as the party's `healthChanges` hold it, with no character for an enemy's strike or a drown. `healPartyMember` and `damagePartyMember` record every change wherever it is made, so a strike between steps is heard as well as a kit's own, and the step sends the changes last and empties them: a change a handler makes as it hears one is sent on the next step. Let the People Rejoice's Fanfare and Endless Waltz answer it.

## How a kit is read

Every kit page is written on the same reading, so a page names only what departs from it.

- **Values.** A kit's multipliers are read from its character's proud skill groups in the [hosted game data](../hosted-game-data/design.md): the first group holds the strikes, the charged attack, its stamina and the plunges, the second the skill's and the third the burst's. Cooldowns and the burst's energy cost come from those groups or the skill kit record, at the level their talent plays at when the kit is built. A page lists its groups and how many decimal places its multipliers match gcsim's to.
- **Sources.** A page's Sources cites the character's gcsim directory at v2.47.2, the tag its record is read at, and the files it reads, with what the kit takes from each: hitmarks, cancels, reaches and areas, and the values gcsim states. `kitSources` names the file and line each of the record's values came from, so a page cites what its record holds. A gcsim file or function is named in prose or linked to its raw file, never as a code name, since this tree holds no gcsim.
- **A table cell is cited by its row.** An area whose radius is read from an index into a module-scope Go table, `attackHitboxes[c.NormalCounter][0]`, takes the row the counter names, and the overlay cites the line of that row, not the constructor's; the reader finds the constructor from the table's declaration line. An index that is neither a literal nor the hit counter gives no area.
- **A character's field is a value only where its package writes it once.** A `c.<field>` the package's own `char` struct declares takes the value of its one literal `=` write, cited at that line, when nothing else in the package increments, compound-assigns or writes it again. A field of the embedded template, such as `NormalCounter`, or one written twice or changed by `op=` or `++`, gives no value, so an index on it names no row.
- **A local alias reads as its single right-hand side.** A constructor's source, `player := c.Core.Combat.Player()`, resolves to that expression when the name is bound once by `:=` or `var` at the function's top level, before the use. A name bound again, or in an inner scope, gives no area: `Unsourced` with the reason "alias not single-assignment".
- **A borrowed plunge.** gcsim has no plunge file for most kits. Their plunges borrow Bennett's plunge timings from gcsim's `bennett/plunge.go`: each landing's frames and hitmark, its hit's element, gauge, tag and poise, and the collision's, each cited at its file and line, with the reaches as the fallback's areas. A kit that takes other timings or no poise says so on its page, and a recording of the character's plunges would settle each one.
- **A borrowed charged attack.** A charged attack gcsim does not implement takes another kit's measured frames and reach, or the table's shape for a spin, with the multiplier and stamina read from the first group, until a recording settles it.

## How a kit's record is built

`pnpm -C scripts genshin:assets kits` publishes each character's record as `kits` and where each of its values came from as `kitSources`, both by avatar id, the Traveler's under `TRAVELER_CHARACTER_ID`. A record is built from gcsim at v2.47.2, the wiki, the published tables and the character's committed overlay (`packages/genshin-world/src/data/kits/<name>.json`). A publish replaces the whole index, so it builds every kit, and it fails on a record that differs from the published one unless its kit is named in `--only`: a value moves only where a commit names the kit it means to change. It builds the published kits and each one `--only` names, so a kit yet to be published is built the first time `--only` names it, and fails the publish where it is built unnamed; `--compare` reports such a kit and seeds no overlay for it, as there is no published record to reproduce.

- **What the slots do not hold is held by name.** A value a behaviour reads outside its record's slots is in one of seven bags (`actions`, `areas`, `frames`, `hitFields`, `hits`, `parameters`, `stances`), under the name its module reads it by, as one value or a list of them. A count a kit reckons in whole frames, as gcsim rounds a cut off an interval or adds a drawn interval to the last hitmark, is read as frames (`readFrames`, `readFramesList`) and turned into seconds at the end (`toKitSeconds`), so no module divides by the frame rate. A stance holds only the actions that differ from its kit's. A hit's fields are a hit short of what its behaviour gives as it plays, a hitmark or a multiplier, and are read naming exactly those (`readHitFields(name, shortFields)`), so the read is typed as the hit it is and fails on a record that holds a field named or lacks another. A `frames` or `parameters` entry named for a constant of its character's gcsim folder takes that constant as gcsim's value, joined by the name the record or the overlay holds, so a rename reads at its new name before it is published; one gcsim only derives keeps its name and is classified by its module's comment. A value gcsim writes inline is cited by the overlay entry `{ file, line, source: "Gcsim", value }`, with the file relative to its character's folder: the line evaluates to the value, and the citation stands, or the line's first value is read as a difference that compare names as `DiffersFromSource`; a line inside a `for` loop whose count is a literal takes the array of its value at each index, and a loop whose count is not one is `Unsourced`; an area is cited by the circle constructor on its line, its radius and fan angle equal to the object's and its height the builders' shared 2 metres, and a box or a line with no constructor is `Unsourced`; a hitmark inside a `Tasks.Add(func() {` block takes the block's `}, delay)` added, nested blocks adding up, and any other field is cited as written whatever block its line is in, and a delay that is not a number makes the value `Unsourced`. An overlay key may name a run of consecutive hits, `hits.fatalBlossoms.0-6.hitmarkFrames`: a cited array gives one value per hit, matched element by element against the loop's element at each hit's index, and a field the run shares takes one value for every hit.
- **A value the kit picks as it plays is a list.** Where a level, a count or a place picks one of several talent parameters or hits, its record holds each in order and its module takes the one it needs, so no module names a talent's group: Xinyan's shield at each level, Yae Miko's totem strike at each, Yanfei's charged attack at each count of seals, Furina's Salon members and Ayato's Shunsuiken strikes. A test over the modules holds the split, failing on one that divides by the frame rate, names a proud skill group or calls `getTalentMultiplier`.
- **`--compare` reports the gap and seeds the overlays.** The gap is each value where the record built from the sources and the committed overlay differs from the published one. The run then rewrites each overlay so the gap is none: a value no source holds is an entry with its cause, one of the six shared causes by rule or `Unclassified`, and a value a source disagrees with keeps the published one as `DiffersFromSource`, unless gcsim gives it at a file:line and the module's comments do not explain it, where it takes gcsim's value (see the gcsim-wins bullet). A cause the committed overlay already holds is kept while its value stands, so a run never downgrades it to `Unclassified`. An overlay file that fails to read is left as it is and reported under the failures, since a rebuild from nothing would drop its hand-authored entries.
- **A named hit joins to gcsim by its multiplier.** A hit a module spawns as a named list (`hits.<name>.<i>`) takes its talent group from its multiplier's proud skill group, its talent variable from the gcsim leaves holding its index, and its multiplier from gcsim as the join's value. From that variable's one attack literal it takes its element, gauge, internal cooldown tag, poise and strike type; a variable with two literals gives none. Its hitmark and area come from the queue calls firing that variable's attacks: the hitmark from the call's delay, the area from its `combat.New*Hit*` hitbox, read as a circle or box on the player or the primary target. Where the calls are as many as the named list's hits they are taken in order, and otherwise the hit's hitmark and area stay Unclassified. Every hit list's multiplier path is matched by one matcher, and a hit is a named list's only where the hit path that matcher reads is `hits.<name>.<i>`, so a skill hold's `skillHolds.0.hits.0` names no list.
- **A value gcsim states where the module says nothing takes gcsim's value.** A `DiffersFromSource` entry drops where gcsim gives the value at a file:line and no comment in the kit's module explains the record's. Only the values gcsim states directly move: an internal cooldown tag, element, gauge, strike type, area and poise, and a plunge's collision hitmark from its `collisionHitmark` constant. A frame count stays as recorded, and a hitmark moves only where gcsim names one. A gcsim `None` element or a zero gauge is no value.
- **A queue call in a loop of constant bounds fires once per iteration.** A `QueueAttack` or `QueueAttackWithSnap` inside a `for` loop whose start, bound and step are constants is read once per iteration, its delay with the loop variable's value, as layla/burst.go's eight ticks are and amber/burst.go's `i <= 120` arrows are. A local its declaration gives no number takes the first constant it is assigned, `travel = tickTravel` in the branch that defaults it.
- **The Traveler's gcsim folder is composite.** Her files are read from `traveler/anemo/lumine` and `traveler/common/anemo` as one character, and a constant gcsim reads by her gender is taken at the gender her `NewTraveler` call passes, Lumine's.
- **Holds, presses and arrows are read from gcsim's names.** A hold's frames and hitmarks come from its `skillShortHold` and `skillHold` constants, one hold per list where they are lists of lists, and its area from the hitbox of the one queue call firing at that hitmark, else the `E-Hold` hitbox where the hold strikes once. That call's attack gives the hold's element, gauge, tag and poise, and its talent leaf the multiplier, where the call is the only one at its hitmark. A press's come from its `skillPress` and `skillTap` constants and its `E-Tap` or `E-Press` hitbox. A press's or a hold's hitmarks listed as plain numbers are one for each state gcsim reads them at, as Razor's are for his burst, so they give no hits. An arrow's box on its target is the circle round the body as long as the box. A burst's or a hold's variant, and a hold gcsim models apart from the module's (Kirara's and Sayu's two levels against eleven), are not read from gcsim, so their values stand in the overlay.
- **A committed overlay is held to the published record.** `kitOverlays.test.ts` reads every overlay's values against the published record at the same paths, through the mirror, so an overlay edited without a publish fails it.
- **gcsim is read at v2.47.2 alone.** It is gcsim's last release under MIT, and every later tag is under its own licence, so the builder reads that tag and records it in each value's provenance; a character the tag predates is built from the tables, the wiki and its overlay. gcsim is read, never run: a handful of literal forms, a constant evaluator for sums and quotients, which keeps a whole-valued float a float, and a YAML read take its values, and what a character does is written here against the primitives rather than translated from gcsim's queue.
- **A character the tag predates is built one way.** Its frames are its clips' lengths at 60 a second, as totals only, since the clips carry no events to read as a hit or a cancel. Its hitmarks and areas are a gcsim kit's of the same weapon and role, provisional until a recording of its strikes settles them. Its multipliers are its proud skill groups' rows, each at the position its table label names, and its energy, cooldowns and costs are the table's. Its passives add nothing until a kit reads them. Its page names only its clips, its donors, its labels and its costs.
- **gcsim's shapes the reader takes.** A slot's frames are read from its first state where gcsim lists one per state, and from the first state at each level where the list is nested. A `const` group's spec with no expression repeats the group's last one, and an index named by `iota` is its spec's place in the group. A burst with no attack under the burst tag is a buff, a heal or a drain, so it has no hits. A slot with no hitmark constant is hit by the queue calls its frames' file makes with its first attack literal, each at the damage delay its call passes, and a charged attack with no hitmark constant is read from the queue calls of its charge's file the same way. A delay written in a local takes the local's first number. A claymore's charged attack, which gcsim has no file for, takes the shared no-action-file rule, so it is no gap in gcsim.
- **The overlays hold about ten thousand entries.** Most are `Unclassified`, a value the published record holds that no source gives and no shared cause explains, until its kit's module comments say what it is; about a sixth are `DiffersFromSource`, where a source disagrees and the published value stands; a few dozen choose the wiki's or the tables' value over gcsim's, and a few dozen name a shared cause. Each kit's are classified from its module's comments, a kit at a time, in the `kit-records` ledger.

## Framework decisions

- **A kit is its record and one behaviour module.** The record holds every value, and `buildKit` resolves it once as its character joins: each frame count divided into seconds at `KIT_FRAMES_PER_SECOND`, each area as the record holds it, each multiplier, cooldown, cost and stamina read off the talent tables at its group and index, and each hit tagged. Every kit has the same slots: a normal attack's string of hits, a charged attack, a plunge's collision and its low and high plunges, an Elemental Skill and an Elemental Burst. The behaviour is one module under `services/kit/characters/`, keyed by its declared id into the generated behaviour map, which loads it as its character joins, and its `create<Name>KitBehaviour` returns what the character alone does over the shared effects (a hit, a field, a summon, a buff, an infusion, a heal and a shield), written from the talent's description and the wiki's notes. A character with no module fights with the Traveler's kit.
- **A behaviour reads its record once, as its kit is built.** Its module is given the record's reader (`KitRecordReader`) and reads every value it plays by at its top, never as the kit plays: a slot's off the kit the record's slots build, which is the very kit `buildKit` returns, so a check against `kit.elementalBurst.hits[0]` holds as the kit plays, and anything else by its name in the record's bags. A read fails on a name its bag does not hold or holds in the other shape, so a typo fails the kit's suite. What the behaviour returns joins the slots by place, an action's hits in the order its record holds them, and the build fails on a behaviour naming more than its record holds, or on a record feature no value completes left without what its behaviour gives: a party heal's chance, a bubble's Omen, a stacked hit's status and a variant's check.
- **Behaviour is TypeScript, the record values.** The record holds no expression or condition, so a constellation's gate, a passive's condition and an event's answer are functions in the character's module, typed and tested as any code, and a hit's talent parameter is read by the builder from gcsim's talent file, which names the game's index beside each multiplier, never mapped by hand. No generated TypeScript is committed for a kit, since its record is a hosted dataset.
- **A catalyst's and a bow's attacks.** A catalyst's every attack deals its element, a bow's only its charged shot, and every other weapon physical damage unless an infusion changes it. A bow's `R` aims instead of targeting, as the controls bind it.
- **A kit's action carries its start.** A kit action may name an `onStart` that adds its effects, given the world's one context (`KitContext`), whose body and combatant are the character's, and the enemy it turned to, so a module writes what its burst or skill sets going without the framework knowing which. A burst may name a variant the same way a skill hold does, played instead while its check holds on the step it starts.
- **A character's ascension phase is on its combatant.** A passive reads `combatant.ascension` against the phase its table names, so the Diluc A4 gate is `ascension >= 4`. The deployed team's built combatants come in as its third argument, from `getDeployedCombatants`, so a passive reads each member's element and region.
- **A character's constellations are on its combatant as a count.** A character's `constellationCount` is on her `Character` record, and the world copies it onto the combatant beside its ascension phase. The [save data](../save-data/design.md) holds the roster, so a reload restores the characters a player held. A constellation reads `combatant.constellationCount` against the level it needs, so Breastplate's C1 gate is `constellationCount >= 1` and its C4 gate `constellationCount >= 4`, each read as the effect is cast. Bennett's C1 and C6 read it alike, on `constellationCount >= 1` and `constellationCount >= 6`.
- **A gcsim call says what it puts on the character.** "ApplySelfInfusion" puts an elemental aura on the character, not a weapon infusion; only "AddWeaponInfuse" is one, and the kit's `infusion` effect is that. A branch on `c.Base.Cons >= N` is constellation N, so the kit gates it on `constellationCount >= N`. The Bennett fix is the evidence: its field infused the character at every constellation, having read the self-infusion as a weapon infusion, with the Cons 6 branch left ungated.
- **Boxes are circles.** An area holds a fan or a circle, so a box is priced as the circle to its farthest corner, provisional until areas hold boxes.
- **A kit's provisional values share six causes.** A plunge gcsim has no file for borrows Bennett's plunge from `bennett/plunge.go`, and a value that differs from it with no reason on its page or in its module takes Bennett's. A claymore's charged attack gcsim gives no frames for strikes at half a second and a second and ends at 1.2. A poise gcsim gives none reads 0. A hold's threshold with no table or wiki figure is half a second, Bennett's first Charge Level's 0.5. A reach on a target is the circle round the body until areas hold targets, and a box round the body the circle to its far corner until areas hold boxes. A talent whose hits its module spawns as a named list keeps its own list at zero, `NamedHitList`, as Amber's burst does with its fiery rain arrows, where gcsim counts three. `genshin:assets kits` names each as a `KitProvisionalCause` and applies it by rule, so a kit's own page and overlay name only the value that differs from these six.
- **An overlay value no source gives is `Unsourced` once its module has been read.** `Unsourced` names a value the published record holds that no source gives and no module comment explains; the published value stands. `Unclassified` is the cause a value takes until its kit's `kit-records` row is swept, and it leaves the enum with the last row. A row is swept only when none of its kit's entries is still `Unclassified`: an entry its module explains but no cause names stays `Unclassified`, and its kit reopens for a sweep that gives it a source.
- **A hit's gauge, tag, group and particles come from the wiki.** The client holds them only in its scrambled ability configs, so the builder reads a hit's gauge, internal cooldown tag and poise from the wiki's Advanced Properties into its record beside gcsim's, and `kitSources` names the page each came from. Poise is gcsim v2.47.2's where gcsim gives it, and a hit with no source value stays provisional, its value in its overlay.
- **A collision infused at 0U still deals the element.** A hit's element no longer needs a gauge, so the collision's Pyro damage lands with no aura, as the wiki's table gives it.
- **A charged attack after a strike skips its windup.** gcsim skips 14 frames of the charge's windup after a normal attack, so the hit lands at 56 frames here, and at 70 from rest, which the kit does not start.
- **A skill with holds starts on its release.** A kit's `elementalSkillHolds` are ordered by their minimum seconds, and a release plays the highest level its held seconds reach, else the press, on that level's cooldown. The press therefore starts when the key is let go, as the game's Charge Levels do, rather than on the press.
- **A cooldown multiplier is read as a skill's cooldown starts.** `getSkillCooldownMultiplier` takes the world's context, the body, the combatant and the team's effects among it, and each skill's cooldown is multiplied by it when the skill starts. Bennett's A1 cuts every Passion Overload by 20%, and A4 halves it while Bennett stands in a field he cast, which a field's `characterId` names. The deployed team's Impetuous Winds multiplies a skill's cooldown by a further 0.95 after the kit's own, in `startNextKitAction`, so the two compose.
- **A charged attack's stamina multiplier is read as it starts.** `getChargedAttackStaminaMultiplier` takes the world's context, and a charged attack's stamina is multiplied by it both where the pool is checked and where it is spent, in `startNextKitAction`, so a multiplier of none starts the attack on an empty pool. A charged attack that costs none spends nothing, so it does not hold the pool's refill back. Ningguang's Backup Plan gives none while she holds a Star Jade, from Ascension 1, and Impetuous Winds' cut applies after the kit's, as it does to every spend.
- **An enemy's strike takes the team's shields through the combat shield, all at once.** `absorbKitShield` gives the strike's damage to every live shield, each priced by `absorbShieldDamage` with the struck character's shield strength, the rule the combat page gives, so the Geo shield's 150% and the shield strength are the combat's. The character takes the least overflow among them as damage to HP, so a shield that holds the whole strike leaves none. The kit keeps no second absorption arithmetic.
- **An enemy strikes the nearest live taunt within its aggro range.** `selectEnemyTaunt` picks, for each enemy on each step, the nearest taunt within `ENEMY_AGGRO_RANGE` of the enemy, and a taunt with no seconds or no health left is not picked. The taunt takes the damage the strike would deal the active character, as the kit gives a taunt no defence of its own.
- **An enemy's statuses add to the damage of each hit on it.** An enemy carries statuses for their seconds, stepped with the enemy. A hit's `enemyStatus` gives it to each enemy it strikes before the hit's damage is taken, restarting a status of its id, each status's `damageTakenBonus` adds to the damage bonus the hit reads, its `resistanceReduction` lowers the enemy's resistance to each element it names, as Enduring Rock's Geo RES does, and its `physicalResistanceReduction` lowers the Physical RES a physical hit reads, as the Jade Shield's does, and its `defenseReduction` lowers the DEF a hit's defence reads, by the game's defence multiplier.
- **The team's effects are the world screen's.** The world's context holds one `KitEffectState`, the character on the field steps it, and the enemies and their strikes read its list. A kit's write reassigns the list rather than changing it, as the adding and the removing do, so a walk runs over the list as it stood, and only the step's last walk, where no kit code runs, drops what ran out in place. A kit drops effects at once by a check (`removeKitEffects`), and the step sends no `EffectExpired` for them, where an effect a kit ends by running its seconds out is dropped by the step's last walk and heard as expired. The character emits `clearKitEffects` on a drown, a jump and its unmount, which the screen answers by emptying the list, so a shield or taunt does not outlive a drown, a jump or the character's unmount. A switch clears nothing, so a shield another character cast stands while someone else is on the field.
- **A skill's charges are the seconds until every one is back.** A kit's `elementalSkillCharges` gives its skill more than one, and the party member's one skill cooldown counts the seconds until all of them are back: each use adds its cooldown, and the skill starts while no more than the other charges' cooldowns are left, which `getSkillReadySeconds` reads for the step and the HUD alike. That is the game's recharge, a charge at a time, each on the skill's cooldown, as gcsim's charges run, and a skill of one charge waits out the whole cooldown as before. A use adds its cooldown at the kit's multiplier and Impetuous Winds', and the charges' threshold takes Impetuous Winds' alone, which is exact while no kit with charges has a multiplier of its own, as none does. The HUD counts down only while no charge stands, and the count of charges the game draws on the button is not built. Klee's and Xiao's skills hold 2, their skill sets' count, which each record holds as `skillCharges`, as a kit reads no skill set.
- **One event channel, not a hook per event.** A kit has one `onKitEvent`, sent every event of combat while its character is deployed, as gcsim subscribes each character to the core's events, and a handler that answers only some ignores the rest. A new passive or constellation is a branch of its kit's handler, never a new hook on the framework.
- **An action's start is given the enemy it turned to.** `onStart` reads the target the step's targeting picked, so a hit gcsim centres on the primary target lands there from a summon, as Flash of Havoc does.
- **Every call a kit answers is given the world's one context.** `KitContext` is the world's combat state, built once by `useWorldCombat` and written in place by each step: the party, every built combatant of the deployed team by id, the enemies and their tables, the team's effects, the seeded random source, the outbox, the body and combatant of the character on the field, and the step's own lists of the effects that ran out on it and the strikes it lands, which it empties by their length, so a step where nothing lands allocates nothing. An action's start, a variant's check, a summon's coordination, a field's tick, a hit's strike, a sprint, the cooldown and stamina multipliers and an event are all given it, so no call builds a context of its own, and a test builds it with `createKitTestContext`. A hit's strike is given the strike as well, whose body and combatant are the ones that dealt it, and an event the kit's own combatant, which a passive reads as its own character. What only the step of the character on the field reads, the controller it acts from, the camera's aim and the ores its hits strike, is apart from it (`ActiveKitControls`).
- **The bench times the proof party's minute.** `stepActiveKit.bench.ts` runs the scripted minute idle and in combat, and the diff of its committed report is a change's before against its after on one machine. The kit framework took about a fifth off the minute idle and in combat alike, the before re-run from the bench's first commit in the same sitting. A profile of the minute put about two fifths of it in Vue's reactive reads and writes of the party, which no kit owns: `stepPartyCooldowns` writing every member's unchanged zero cooldowns each step the most of them, then the Moondrifts' seconds. So the world's party holds the state only the step reads raw and writes a cooldown only while it runs ([party](../party/design.md)), which took the minute from 34.5 to 19.3 ms idle and from 45.8 to 30.1 ms in combat, re-run in one sitting on mains power under a load of about 58 on eight cores, and two more alternating pairs agreed within 2 ms. The reads of the members and the teams the HUD draws stay reactive; typed arrays and an ECS store for the effects wait until the bench shows the kits' own pricing or effects dominating it.
- **The step reads what the build resolved.** A stance's combatant is built once as the stance starts, and each hit carries its kinds of attack from the build (below), so no frame searches a kit. An action and a summon each keep the index of their next hit (`KitState.nextHitIndex`, `KitSummon.nextHitIndex`), so a step compares one hitmark rather than the whole list, and a summon with nothing due does nothing. `stepKitEffects` steps the team's effects in one order, their seconds, then the fields, then the summons, taunts, bubbles and shields, in three walks, the last dropping what ran out; an effect a field's tick adds is stepped only by the walks after that tick. Strikes and events are plain objects made as they land, with no pool kept for them, since a step where nothing lands makes none. Hits land on seconds, not on an integer frame clock, which would move the step a hit on a boundary lands in.
- **A kit draws from the world's one seeded random source.** The context carries it (`KitContext.random`), so a kit's step, an action's start, a field's tick and a hit's strike draw from the same source the kit events, a hit's CRIT and a shard's bearing read, and the world plays the same under the same seed. The Ajaw's laser intervals are drawn as Kinich's burst starts. A summon's hits read no random source.
- **A strike an event sets off is a summon.** Thundering Retribution, the Talisman's and Riptide's strikes and the coordinated attacks are summons cast where the enemy or the body stands, landing a frame or more on as gcsim queues them, priced by the combatant that casts them; Fischl's are priced by Oz, which holds her as she cast it.
- **A hit's kind of attack is set on it as its kit is built, and a summon's is read off the summon.** `tagKitHits` gives each hit of a kit's actions its action's kind as `buildKit` builds the kit, and each hit of a stance's as `enterKitStance` builds the stance's kit, so a hit keeps its kind through a stance that starts or ends while its action plays, and an infusion's copy keeps it too. Beside it, the hit is given the kind of the action it sits in (`KitHit.actionAttackTag`), which an infusion and an ore read rather than the kind it is dealt as: an infusion takes the hits of a normal attack, the charged attack and the plunges, and an ore takes a normal or charged attack's as melee, so a stance's normal attack whose stance ends mid-swing is still a normal attack to both, as gcsim infuses an attack by its own tag as it lands (`internal/template/character/character.go`). A summon's hits carry the kind its kit names as it casts it, gcsim's tag for them: Aurous Blaze's explosion is Elemental Burst DMG, and Thundering Retribution, the hit an Electro reaction sets off, Elemental Skill DMG. An action's own hits queued past its end carry their action's. A summon whose kit names no kind deals none, as gcsim's "AttackTagNone" hits do, though gcsim tags some that still name none here, Gaze of the Deep's and Riptide Flash's among them, Normal Attack DMG. A reaction's own damage is no kit's hit, so it sends no `DamageTaken`, and gcsim's reaction tags are none of the five kinds a kit reads.
- **A normal attack lands as its first hitmark falls.** `NormalAttackLanded` is sent once for each normal attack, whether or not it strikes, as the wiki gives Evernight Raven "every execution of a Normal Attack regardless if it hits", where gcsim fires it as the attack starts and every second it holds.
- **An interval on an enemy is a status of its own.** Riptide Flash's 0.7 seconds, Riptide Slash's 1.5 and the Talisman heal's second each go on the enemy as a status of their own id, as gcsim keeps them, and a passive's own interval goes on its character as a `KitStatus`.
- **A skill's sweep reads full while more is left than the kit's own cooldown**, as a stance's end sets on Tartaglia's 1-second press cooldown.
- **A Swirl's member is matched by its element from the deployed combatants.** The world's context carries every built combatant of the deployed team by id (`KitContext.characterIdCombatantMap`), so a passive reads each member's element as the Swirl's element is read.
- **A field's Geo count reads the deployed team's combatants.** A field's tick is given the world's context, whose combatants by id Crunch counts its Geo members from, as gcsim counts the party when it loads.
- **An absorb check takes one element from all the enemies it reaches, in gcsim's priority.** `findAbsorbedElement` walks Pyro, Hydro, Electro and Cryo in turn and takes the first any reached enemy holds, whichever enemy holds it, as gcsim's absorb check walks its priority ahead of its enemies. An element is held as gcsim reads an aura: Pyro under a Burning aura too, and Cryo under Freeze. Sucrose's field, Kazuha's Autumn Whirlwind and Heizou's Windmuster Iris each read it, Heizou's on the one enemy its aura check strikes.

One fixed step of the character on the field, in its order:

```mermaid
flowchart TD
  BUILD["buildKit, once as a member joins: each hit's kinds of attack"]
  SWAP["a swap: the effects that end on it end, CharacterSwapped sent"] --> OUT["the outbox sent in order to every deployed kit"]
  OUT --> EFFECTS["stepKitEffects: three walks in place, the strikes and expired effects kept on the context"]
  EFFECTS --> PARTY["EffectExpired sent; Verdant Dew, Moondrifts and Crystallize shards step"]
  PARTY --> ENEMIES["enemy statuses tick onto the outbox, sent again"]
  ENEMIES --> REACT["elemental ticks, Lunar-Charged and Moondrift Harmony strike, Dendro Cores burst"]
  REACT --> STEP["stepKit on the stance's combatant: the cursor lands hits, or presses start one"]
  BUILD -.-> STEP
  STEP -->|"an action starts"| START["the body turns to its target, BurstUsed sent, then onStart and the summons it coordinates"]
  STEP --> STRIKES["the strikes: each summon's and the step's own, each infused by its striker's infusion"]
  START --> STRIKES
  EFFECTS --> STRIKES
  STRIKES --> PRICE["strikeKitEnemies: priced from the buffs, reactions and damage sent"]
  PRICE --> ENERGY["attack energy rolled for the strikes"]
  ENERGY --> HEALTH["last: HealthChanged for each change to a member's HP"]
```

## Not built in the framework

Each page names only what it alone lacks. These are the gaps every page shares, so each is stated once here.

- **The Nightsoul Blessing's points and entry are built; its strikes are not.** Each Natlan character holds its own Nightsoul points and blessing, as gcsim's per-character state does: `enterKitNightsoulBlessing` enters it with its points and rate, and the step runs each rate, ending the blessing when its points drain to none. Five Natlan kits enter theirs so far (Mavuika, Ifa, Mualani, Iansan and Kinich). The strikes a blessing replaces are not built, and each Natlan page names what its own Blessing would change. Kachina's waits on Turbo Twirly's riding states, and Mizuki's state is the Dreamdrifter, not the Nightsoul Blessing.
- **Constellations 3 and 5 raise talent levels no kit reads.** Each raises the skill and the burst by three levels, and a kit reads each group at its start level, so `getConstellationTalentAdditions` is unread.
- **Skill particles are not built.** A skill's or burst's particles wait on a hit that gives particles, which nothing yet does, so an enemy's HP drop and a Resonance's particle on a listed reaction (`getReactionParticleDrops`) are the only energy a strike gives.
- **A talent raise takes effect at the next join or reload.** A kit is built once as its character joins the party, so an upgraded talent or a constellation's raise plays at its new level from then, not at once. A kit in play holds its state, so rebuilding it on each raise is not built.
- **The Hexerei team bonus is not built.** Every Hexerei kit and its constellations waits on it. gcsim turns them on by default, and the kits here follow the standard kit.
- **A kit moves no enemy.** Pulls, knockbacks and holds that move or fix an enemy in place are not built.
- **A hit is priced from its striker alone.** A kit reads no other member's buff into a hit, so a Quill or a banner that adds to another member's hits is not built.
- **Hitlag, ICD groups and strike types are not recorded.** gcsim holds them, and they stay out of the record until a rule reads them.
- **A character holds no aura.** Only an enemy holds elemental state in this package, so an aura on a party member is not built.

## Out of scope

- **The Mannequins have no kit.** Avatars 10000117 and 10000118 are Miliastra Wonderland's avatars, not the main game's roster. Their dump entries hold no energy skill, and a kit's record requires its burst, so no record is built for them and they stay without a kit. A character without a kit fights by the Traveler's kit.

## Sources

- [AnimeGameData](https://github.com/DimbreathBot/AnimeGameData), the community's per-patch dump: the avatar, skill depot and skill tables the table is read from, and the proud skill table the multipliers are read from.
- [gcsim](https://github.com/genshinsim/gcsim), MIT up to [v2.47.2](https://github.com/genshinsim/gcsim/tree/v2.47.2/internal/characters), the tag the builder reads: each character's `config.yml` hitboxes and talents, its action files' hitmark and frame literals and `AttackInfo` records, and its generated `zz_<name>.dm.go` talent indices. The shared Nightsoul state is in [`internal/template/nightsoul`](https://github.com/genshinsim/gcsim/tree/v2.47.2/internal/template/nightsoul).
- **Animation clips, read for timings.** The clips' own events are the only timings gcsim does not give, and they are empty: no attack clip of Xiangling's or Kachina's fires an event, so no event is a hit or a cancel. A clip's duration is its whole length at 60 a second, 107 to 135 frames for Xiangling's five normal attacks against gcsim's cancel frames of 17 to 70, so a duration is read as an action's total frames only, and each hit's hitmark is taken from gcsim's hitmarks for a kit with the same strike count, provisional until a recording settles it. Read with `pnpm -C scripts genshin:assets timings <pattern>`. Nefer's, Zibai's, Illuga's, Lohen's and Linnea's clips carry no events either, so their frames are read the same way.
- **Animator controllers and event patterns, not read for timings.** A hit's timing could sit in a character's "AnimatorController" state machines or its "ConfigAnimatorEventPattern". The extraction does not decode the controllers (no "AnimatorController" type is indexed), and the "EventPattern_Loli_Pole_Kachina" block is not read, so this source gives no timing for any kit.
- **Avatar ability configs, not read for timings.** The per-avatar ability tables are scrambled `MiHoYoBinData` named by hash, and no Kachina or new kit's ability file is identified among them, so this source gives no timing for any kit.
- [Template:Advanced Properties](https://genshin-impact.fandom.com/wiki/Template:Advanced_Properties), Genshin Impact Wiki, read through the wiki's [MediaWiki API](https://genshin-impact.fandom.com/api.php) (`action=parse`, `prop=wikitext`): each hit's gauge, ICD tag and type, and poise. [Dough-Fu](https://genshin-impact.fandom.com/wiki/Dough-Fu) is the hand-worked case the builder's tests take their oracle from.
- [Shield](https://genshin-impact.fandom.com/wiki/Shield), Genshin Impact Wiki: the active character's damage is taken by its shields first, every active shield takes an enemy's strike at once, and absorption is scaled by the active character's Shield Strength.
