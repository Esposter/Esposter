# Drawing a character

The model [read from a pack](../pmx-reader/design.md) becomes one skinned mesh, shaded by the game's own character shader rather than MMD's toon. What that shader takes for Lumine is recorded in [Lumine's shading](../shading/design.md); this page is how a pack's material is drawn with it.

- **One skinned mesh.** `createPmxMesh` builds one geometry with a group for each material's run of triangles, in the file's order, which is the order MMD draws them in. Each bone is nested under its parent and placed from it, bound by the step back from where it stands, since the rest pose turns no bone. MMD's unit is scaled into the world's metres by `PMX_UNIT_METRES`.
- **Each material by the game's shader.** `createCharacterMaterial` builds the body's path of Lumine's shader as TSL nodes (`createCharacterShadingNode`): the region's tint, the shadow ramp's row and column, the toon threshold, the metal matcap where the lightmap's red passes its gate, the specular step, the emission lerped in by the main texture's alpha where the material draws its emission from it, and the output tone. Each equation's constants come from one module (`shading/constants.ts`), which the pure functions beside it also read. The material takes no three lighting, and its output is the shaded colour.
- **A pack's inputs, one model.** The material's inputs are `CharacterShadingInputs`, in the shape of the shading page's Inputs table. A PMX material fills it as that table's production column says: its diffuse is the main texture and colour, its toon the ramp, read up its one column where the pack ships its own toon and across one row where it names a shared one (one of the world's ten ramps, `getSharedToonRamp`), the layout chosen as the material is built (`createRampUvNode`), its sphere laid over the diffuse by its mode where that is Multiply or Add (not the metal map, see the shading page's Decisions), and its specular and edge carry over. A material with no toon names the world's ramp.
- **The defaults a pack does not supply.** A PMX file has no lightmap, so every material takes the flat one the page proposes: red 0 (no metal, no specular), green the neutral middle, alpha 0 (region one). No region tint is set, so each region takes the material's colour. The light area and the band width are the ones the shading page derives from MMD's toon lookup, so a pack's toon is read as MMD reads it. Where the page leaves a value unfitted, the material takes a stand-in and says so in the code: the face's depth term is 0.5, the brightness, desaturation and contrast are 1, 0 and 0, and the outline's knots are unit scales, so the width is as drawn.
- **One open stand-in.** The light's colour scales the lit colour and the specular, as the game's main light colour does, but the light factor `f` is left out: the world's light carries its colour and no strength beside it.
- **Hair and face are their own paths.** `CharacterMaterialKind` selects the body (with its metal branch), the hair (the body's path without the metal branch) or the face, which takes its shade from the face map's window in place of the ramp. A pack's material is always a body, since a PMX file names no kind; the other two paths are built and tested but not yet fed a face map or a hair lightmap.
- **Posed from the body's state.** Nothing in the file drives the skeleton, so `createCharacterPoser` poses its standard bones, each found in the skeleton under the name a bone name map gives it (MMD's Japanese names for a pack, the rig's own names for the game's model) and skipped where a model lacks one. A bone's pose is written in its rest frame, so a model whose bones rest turned holds the same pose as one whose rests are the identity, and each arm's rest is taken raised to the T, the elbow laid along it from the shoulder, so a model resting in an A-pose, as both Lumine's pack and the game's model do, holds the same pose as one in the T. Each frame `computeCharacterPose` turns them from the controller's state: the arms come down from the T, the chest and shoulders breathe, a walk, run or sprint swings the legs and arms opposite each other, a jump, a fall or a glide holds a fixed stance, and a state's pose cross-fades from the one before. A gait's stride is `advanceStridePhase`, a full turn for each stride the state's speed covers, so the feet keep pace with the ground they cross. Its angles are provisional, not yet measured against a still or a capture, and the stance and cycles are procedural rather than the game's clips. The body's skinned mesh is looked for again only once a child is added to or taken from the body, which three reports on the body as `childadded` and `childremoved`, so the model is found when it arrives rather than every frame.
- **The outline in the material's edge.** The outline pass picks a material by its toon flag, and every solid material sets it, as the game outlines every character; a transparent one does not. A material whose edge the file sets is outlined in that edge: its colour is the material's colour times its edge colour, toned as the body is. One whose file sets none, as every material of an official release does, takes the world's own outline, its colour and width (Provisional, until the body's outline values are fitted). A game avatar's material sets its edge from the game's own values instead, as the shading page's "The outline" section sets out. Its width is the scene's outline width, scaled along the view depth by the three knots `getOutlineScale` interpolates, so a material's knots move its outline's width with distance. A material outlined this way gets one outline material per distinct edge, built once and shared, as the scene's outline is, except a game avatar's edge colour read per pixel: it samples that material's own textures, so its outline material is its own and goes with it.
- **Blended in the model's own order.** A material is opaque, writing its depth as MMD draws one, unless its diffuse alpha is below one or its texture has a texel below full alpha. Such a material is blended and drawn from both faces, so a texel it leaves clear shows what the materials before it drew. A material set to draw both faces is drawn from behind as well.
- **Textures as the model samples them.** `createPmxTexture` decodes a texture unpremultiplied and unconverted, leaving the blend and the colour space to three, and unflipped, since a PMX model's texture coordinates run from the image's top left. Past its edges it repeats. A toon texture is the exception: it is one column lit at its first row, read flipped, so the shading reads it up the column with the lit end at the top, as the MMD loader reads it.
- **It faces where its holder faces.** `CharacterModel` stands the model at the origin of whatever holds it, turned half round to face -z, as a yaw of none does. The [character controller](../../character-controller/design.md)'s body faces the same way, so whatever moves the body moves the model by holding it.
- **The Traveler rides the controller's body.** The world plays the Traveler (`TRAVELER_CHARACTER_ID`), drawn on the character controller's body from where Windrise starts, from whichever pack it has, else as the body's capsule. A witness render draws no character.

## Notes

- **The game's characters do not darken in the rain.** A character's material takes none of the wetness the environment's toon material reads ([weather](../../weather/design.md)).
- **A toon or sphere texture is read only where a material draws with it.** A model's shared toon ramps are generated, never read, so a release without any toon texture ships no file beyond its model and textures.
- **In development the Traveler is drawn from the game's own model.** When the developer's exports hold `playergirl` with its `avatar.json` and `avatar.bin`, the world draws the Traveler from them in place of the pack: the bones at their rest pose, the humanoid bones named for the poser's MMD name map, and each material shaded from the game's values, read at runtime and never committed. Its textures are flipped to the game's bottom-left UVs and only the colour slot decodes as sRGB, the lightmap, face map, metal map and ramp read as stored (`createAvatarTexture`). Nothing reaches production, since the avatar's modules are a separate chunk the export index gates, and the model's facing is not yet checked by eye.
- **The pose is procedural.** The game's own locomotion clips are not retargeted onto the MMD skeleton, so the Traveler's stance and cycles are the poser's own rather than the game's animation. Retargeting those clips is the roadmap's fidelity step ([roadmap](../../../../changes/genshin-roadmap/tasks.md)).
- **MMD's unit is reckoned, not measured.** Eight centimetres is the community's reckoning from a model's height. The scale the game draws a character at is measured from its own models, as the [proposal](../../../../changes/genshin-characters/design.md) lists.
- **Where the drawing departs from MMD's loader, on purpose.** The oracle for the pose and the mesh is three-stdlib's `MMDLoader`, since three's own examples no longer ship one. A pack does not carry MMD's shared toon bmps, so the world's ten ramps stand in for them, and the oracle reads a material's colours as linear where the drawing decodes the file's sRGB colours. The lighting is no longer MMD's: the drawing takes the game's shader, so the oracle is no longer its comparison, and a character's look is measured against a frame of the game ([Lumine's shading](../shading/design.md), [parity](../../parity/README.md)).

## Key files

| File                                                                                | Role                                                                                                            |

| `packages/genshin-engine/src/character/createPmxMesh.ts`                            | The skinned mesh: the geometry's groups, the skeleton, and the scale to metres                                  |

| `packages/genshin-engine/src/character/pose/createCharacterPoser.ts`                | Drives the model's bones each frame, cross-fading between states                                                |

| `packages/genshin-world/src/services/character/avatar/readCharacterAvatar.ts`       | Fetches an avatar's manifest, its binary and each texture its drawn materials name, once each                   |
| `packages/genshin-world/src/services/character/avatar/updateAvatarFaces.ts`         | Sets each face's threshold and flip from the main light and the face's root bone, once a frame                  |
| `packages/genshin-world/src/services/character/avatar/createAvatarTexture.ts`       | Reads the game's textures flipped to its UVs, with sRGB on the colour slots of `AVATAR_TEXTURE_SLOTS`           |

| `packages/genshin-engine/src/character/getSharedToonRamp.ts`                        | MMD's ten shared toon ramps, generated once in the world's own tones, a material's default ramp                 |
