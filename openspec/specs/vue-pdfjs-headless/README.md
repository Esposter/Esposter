# vue-pdfjs-headless

`packages/vue-pdfjs-headless` (npm `vue-pdfjs-headless`) is a PDF viewer's loading, page drawing and viewer state with no styling: composables that take the elements a consumer renders and return refs and functions. The renderer is the consumer's, passed in, so the package never imports `pdfjs-dist` at runtime and a consumer picks the build it needs, the legacy one included.

The package has two capabilities, each with its own design page and requirements:

- [Document](document/design.md) loads a document from a URL, from bytes or from a file, through the consumer's renderer, with its progress, its password prompt, its failure and a superseded load.
- [Viewer](viewer/design.md) draws the pages, their overlays, zoom, search, outline and thumbnails, fullscreen, download and print.

The app's own use of the package is the [PDF viewer](../architecture/pdf-viewer/design.md): the renderer's worker and folders, the thumbnail and the dialog's look.

## Upstream

Both wrappers' trackers get one verdict per issue, open or closed, read with its comments. `vue-pdf-viewer`'s source is closed, so its tracker is the only evidence for it, and its features are answered by the viewer's decisions. A feature the dialog does not draw yet keeps its in-scope verdict, which judges the viewer rather than one consumer of it, and its row links the capability building it. The page drawing's in-scope defects carry tests in the package's page composable: #52 on the scale function and #20 on a redraw at a new width. #28 and #261 are fixed upstream by the wrapper's own verdict, so no test here proves an open defect. The five worker-syntax rows in `vue-pdf-embed` (#125, #266, #277, #283, #291) are answered by the [document](document/design.md) capability, which takes the renderer's legacy build from its consumer.
