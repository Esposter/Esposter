# User Data Inventory

Every place the platform keeps data that belongs to one account, with how each one is keyed to that account, what removes it today and which entry of the data export holds it. Account deletion and data export both read this page: a store missing here is a store a deletion would leave behind and an export would omit. It describes the code as it stands; a change to a store updates its row here in the same change.

The export entry column names the entry of the data export archive (`openspec/changes/user-data-export/design.md`, "What the archive holds") that holds the store, and says None where the archive does not read it.

## Other stores

- **The storage ledger** holds one row per charged blob, with its container, its name and its owner. It is the one exact list of the blobs a user is charged for.
- **Azure AI Search** (`messages-index`) holds message text, the author's id and filenames. A pull indexer fills it from the `Messages` table on a schedule. Nothing deletes from it, and whether the indexer drops soft-deleted messages is not recorded.
- **Web PubSub** carries room traffic and per-user groups. Both are transient.
- **Event Grid and Service Bus** carry transient payloads, including the scheduled-message and reminder queues.
- **The browser** keeps recent pages per device. Nothing server-side is involved.

## Ownership rules that shape a sweep

- A room has one owner, `rooms.userId`. Leaving a room as its owner deletes the room for everyone, through `deleteRoom`. No transfer path exists.
- A resource has one owner, `resources.userId`, enforced by `getOwnerProcedure`. No sharing model exists.
- A message is attributed to its author in the `Messages` partition of its room. There is no index from a user to their messages.

## Known gaps

Each one is named where it is decided and says which operation it affects. Items 5 and 6 are omissions the export design decides on purpose. Items 7 to 11 are stores the archive leaves out that the export design does not decide, so each stays open until it does.

1. **Deletion and export.** Messages a user wrote in rooms they have since left stay attributed to them, because membership is the only index (`user-account-deletion/design.md`, "Limits the spec states"). The export leaves them out too (`user-data-export/design.md`, "Not included").
2. **Deletion and export.** Moderation logs and notes that name the user in rooms it does not own, and the user's activity on other people's resources, are kept (`user-account-deletion/specs/user/account-deletion/spec.md`, "The deletion states what it does not remove"). The export leaves out the same activity, since its resources entry covers owned resources only, and its moderation entry holds the records that name the user as target (`user-data-export/design.md`, "What the archive holds").
3. **Deletion and export.** The shared character-pack files are kept, and have no owner to attribute them to (`user-account-deletion/specs/user/account-deletion/spec.md`, "The deletion states what it does not remove"). The export leaves them out too (`user-data-export/design.md`, "Not included").
4. **Deletion only.** Azure AI Search keeps a copy of message text whose removal path is unverified (`user-account-deletion/design.md`, "Limits the spec states"). The export reads `Messages`, not this index.
5. **Export only.** Sessions, API keys and every token in `accounts` are left out, so the archive names a sign-in provider and nothing it signs in with (`user-data-export/design.md`, "Not included"). The deletion removes them with the user row.
6. **Export only.** Other people's messages and data are left out, since they are not the account's (`user-data-export/design.md`, "Not included").
7. **Export only, not decided.** Posts, likes and friend requests are not in the archive, and the export design neither includes nor excludes them (`user-data-export/design.md`, "What the archive holds").
8. **Export only, not decided.** The room record, the person's memberships and roles in rooms, and an owned room's categories, member permissions, bans, invites, search histories, call sessions, scheduled message jobs, thread follows and webhooks are not in the archive. The export design neither includes nor excludes them (`user-data-export/design.md`, "What the archive holds").
9. **Export only, not decided.** A resource's versions, version assets, publications, links, accesses and favorites are not named in the archive's resources entry, and the export design neither includes nor excludes them (`user-data-export/design.md`, "What the archive holds").
10. **Export only, not decided.** Message reactions, the person's own activity on resources they own, the program participants and survey responses on those resources, and the moderation records where the person is the actor in rooms they own are not in the archive. The export design neither includes nor excludes them (`user-data-export/design.md`, "What the archive holds").
11. **Export only, not decided.** The room profile images, the emoji, the message file thumbnails, the character-pack list and its staging, and the storage ledger are not in the archive. The export design neither includes nor excludes them (`user-data-export/design.md`, "What the archive holds").
