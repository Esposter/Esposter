# User Data Inventory

Every place the platform keeps data that belongs to one account, with how each one is keyed to that account, what removes it today and which entry of the data export holds it. Account deletion and data export both read this page: a store missing here is a store a deletion would leave behind and an export would omit. It describes the code as it stands; a change to a store updates its row here in the same change.

The export entry column names the entry of the data export archive (`openspec/specs/user/data-export/design.md`, "What the archive holds") that holds the store, and says None where the archive does not read it.

## Room objects

Each room's messages, reactions and search live in that room's object, and the sweep reaches them through the room's own methods rather than a query across rooms. A person's own messages are indexed in their user object, so each deletion can take its entry out.

## Other stores

- **The storage ledger** holds one row per charged object, with its bucket, its name and its owner. It is the one exact list of the objects a user is charged for.
- **Sockets** — the hibernating WebSockets of the room, call and person objects carry live traffic. They hold no data once closed.
- **Queues and alarms** — queues carry transient job payloads. A room's or a person's alarm holds its scheduled messages and TodoList reminders until each fires.
- **The browser** keeps recent pages per device. Nothing server-side is involved.

## Ownership rules that shape a sweep

- A room has one owner, `rooms.userId`. Leaving a room as its owner deletes the room for everyone, through `deleteRoom`. No transfer path exists.
- A resource has one owner, `resources.userId`, enforced by `getOwnerProcedure`. No sharing model exists.
- A message is attributed to its author in its room's object. The author's user object indexes the messages they sent, so the person's own messages are found there rather than by scanning every room.

## Known gaps

Each one is named where it is decided and says which operation it affects. Items 3 to 9 are omissions the export design decides on purpose, each citing its reason in the export design's "Not included" section, and no item is left undecided.

1. **Deletion and export.** Messages a user wrote in rooms they have since left stay attributed to them, because the sweep walks the rooms the person is a member of ([account deletion](../../user/account-deletion/design.md), "Limits the spec states"). The export leaves them out too (`../../user/data-export/design.md`, "Not included").
2. **Deletion and export.** Moderation logs and notes in rooms the user does not own, where the user was the moderator, and the user's activity on other people's resources, are kept with the moderator's id set to null. A record that names the user as target is removed with the account ([account deletion](../../user/account-deletion/spec.md), "The deletion states what it does not remove"). The export leaves out the same activity, since its resources entry covers owned resources only (item 6 covers the owned resources' log), and its moderation entries hold the records that name the user as target and the actions the person took as moderator in rooms they own (`../../user/data-export/design.md`, "What the archive holds").
3. **Export only.** Sessions, API keys and every token in `accounts` are left out (`../../user/data-export/design.md`, "Not included"). The deletion removes them with the user row.
4. **Export only.** Other people's content and counts are left out (`../../user/data-export/design.md`, "Not included").
5. **Export only.** A resource's version history is left out (`../../user/data-export/design.md`, "Not included").
6. **Export only.** The activity log of a resource the person owns is left out, and deletion removes it with the resource (`../../user/data-export/design.md`, "Not included").
7. **Export only, by decision.** Program participants and survey responses on resources they own are not in the archive (`../../user/data-export/design.md`, "Not included").
8. **Export only.** Derived thumbnails are left out (`../../user/data-export/design.md`, "Not included").
9. **Export only.** The storage ledger is left out (`../../user/data-export/design.md`, "Not included").
