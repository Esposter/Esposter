# Deep equality

`checkIsDeepEqual` in `packages/shared/src/util/object` answers whether two values hold the same data. It replaced `fast-deep-equal`, which thirteen call sites in `apps/web` and `azure-mock` imported. The replacement is written against the same behaviour in ESM, with the upstream's ES6 cases (Map, Set, typed arrays, `RegExp`, `Date`, `NaN`, `valueOf`) in the one build, since the callers relied on the upstream's default entry and that entry compared a Map or Set as an object with no keys.

## How a comparison is decided

Each step returns as soon as it decides, so the cheapest test comes first.

```mermaid
flowchart TD
  start["checkIsDeepEqual(first, second)"]
  identity{"Identical?"}
  primitive{"Both objects?"}
  constructor{"Same constructor?"}
  array{"Arrays on both sides?"}
  bytes{"Binary views or buffers?"}
  pattern{"RegExp, weak collection<br/>or Promise?"}
  valueOf{"Own valueOf on both?"}
  collection{"Map or Set on both?"}
  keys{"Same enumerable keys,<br/>each deep-equal?"}
  start --> identity
  identity -->|yes| equal["true"]
  identity -->|no| primitive
  primitive -->|no| sameValueZero["SameValueZero, so NaN equals NaN"]
  primitive -->|yes| constructor
  constructor -->|no| unequal["false"]
  constructor -->|yes| array
  array -->|yes| elements["Element by element, in order"]
  array -->|no| bytes
  bytes -->|yes| byteRange["Byte by byte over the view's own range"]
  bytes -->|no| pattern
  pattern -->|"RegExp: source and flags"| equal
  pattern -->|"weak collection or Promise"| unequal
  pattern -->|no| valueOf
  valueOf -->|yes| sameValueZero
  valueOf -->|no| collection
  collection -->|yes| members["Size, then each entry or member"]
  collection -->|no| keys
```

Three choices follow from the flow. A `valueOf` or `toString` is used only when it is a function and not `Object.prototype`'s, so an object with a data field of that name is compared by its keys and a null-prototype object has nothing to call. A Set holds its members by identity, so two Sets of equal objects are unequal, as the ECMAScript definition of a Set says. A typed array compares its bytes rather than its elements, so `+0` and `-0` in a `Float64Array` are different where they are equal in a plain array.

## Notes

- The replacement compares a Map or Set's contents, where the upstream's default entry compared its own keys. A caller that relied on two different Sets being equal would now see them unequal. None of the thirteen callers does.
- Cyclic structures are not detected. A comparison of data with a cycle overflows the stack, as the upstream's does, and no caller compares cyclic data.

## Key files

| File                                                       | Role                                                                   |
| ---------------------------------------------------------- | ---------------------------------------------------------------------- |
| `packages/shared/src/util/object/checkIsDeepEqual.ts`      | The comparison and its decision order                                  |
| `packages/shared/src/util/object/checkIsDeepEqual.test.ts` | One case per upstream issue fixed, and the ES6 cases the upstream kept |

| `packages/shared/src/util/object/checkIsCustomMethod.ts`   | Whether a `valueOf` or `toString` is the value's own                   |
| `packages/shared/src/util/object/getEnumerableKeys.ts`     | Own enumerable keys, symbols included                                  |
| `packages/shared/src/util/object/checkIsSameValueZero.ts`  | Equality that treats two `NaN`s as equal                               |
