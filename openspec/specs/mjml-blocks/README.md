# mjml-blocks

`packages/mjml-blocks` (npm `mjml-blocks`) holds MJML's component set as block types on the [headless block editor](../vue-block-editor-headless/editor-core/design.md). Each type carries its attributes in MJML's own type grammar, MJML's defaults, the tags it may hold and its content kind. A document renders to MJML's JSON form, serialises to MJML source, and reads back from MJML source, refusing every tag, attribute or value the package does not take. The package has no framework, no DOM and no MJML runtime: the compile is the consumer's, one `mjml2html` call with strict validation.

The email editor's canvas, preview and fields belong to the [email editor](../resource/page-builder/email/design.md), and the server's compile to the document model. What the package does not own is MJML's own, so each rule is held equal to the installed MJML rather than copied from it.

- [Block types](block-types/design.md) — each MJML component as a block type, its attributes and content kind, and the files each part of the behaviour lives in.

## How a document becomes MJML and back

```mermaid
flowchart LR
  DOC["Block document"] --> FOLD["renderBlockNodes: each node after its slots"]
  FOLD --> NODE["each type's render"]
  NODE --> JSON["MJML's JSON form, the head from the root's props"]
  JSON --> COMPILE["the consumer's compile: mjml2html, strict validation"]
  JSON --> SERIAL["serializeMjml<br/>MJML source"]
  SOURCE["MJML source"] --> PARSE["node-html-parser: block text kept raw, attributes decoded"]
  PARSE --> MAP["readMjmlRoot"]
  MAP --> SCHEMA{"the registry's document schema"}
  SCHEMA -->|accepted| DOC
  SCHEMA -->|refused| ERR["the refusal, naming the node or tag that failed"]
```

- **The render.** `renderMjmlDocument` folds the document through `renderBlockNodes` into MJML's JSON form: a tag, its attributes, and its children or its content. The render escapes every attribute value once, since MJML writes a value exactly as given, and an option stamps each node's id as its `css-class` so the proof can find its box.
- **The serialiser.** `serializeMjml` writes that JSON as MJML source for the export. It writes every element with its own closing tag and no indentation, so an element that closes nothing never swallows its siblings.
- **The read back.** `parseMjmlDocument` reads source with `node-html-parser`, which keeps the content of each ending tag as raw text, decodes every attribute value and closes every self-closing tag. A head tag becomes a root prop, a body tag a node, and the content of a content-kind tag goes through its kind's reader. The result is parsed by the registry's document schema, so the refusal has one path, and it names the node that does not fit.

## Decisions

- **The component set is MJML's, current and whole.** Parity is with the components of the MJML release the `pnpm-workspace.yaml` catalog pins, so a component the plugin never shipped is in the set too. Each block type's name is its MJML tag, so the render, the slot rules and the canvas key on one name.
- **The head is the root's props.** A head component belongs to the whole email, so `lang` and `dir` sit on `mjml`, `mj-title` and `mj-preview` are text props, `mj-font` is a list of a name and a stylesheet address, `mj-breakpoint` and `mj-body`'s attributes are maps, and `mj-attributes` is a map per type. `mj-style` is a list, and its schema refuses a `<` in the CSS so the CSS can never close its element.
- **Components left out of MJML's set are refused by name.** `mj-include` reads files from the compiling server's disk, `mj-html-attributes` and `mj-class` target attributes by selector and share named classes, and the community components are not part of MJML's own preset. A head or body tag the package does not take, or a second tag of one the head or body reads once, is refused under its name in angle brackets (`<mj-include>`, `<body>`), a key no prop the root or the head reads can be. The `mjml` element takes `lang` and `dir` as root props, the direction held as `direction`, and any other attribute it carries is refused under `<mjml>`.
- **Slots are MJML's nesting map.** Each container's `children` slot is the allow list MJML's core preset registers for its tag, and the root's content is the list for `mj-body`. A consumer's own leaf is added where MJML allows a leaf. A test holds every allow list equal to the installed preset, so a release that changes the nesting fails a test.
- **A consumer's leaf renders with the consumer's context.** A leaf type brings its own render, and `renderMjmlDocument` hands it the `context` its options carry, typed by the registry, so a survey invite builds its link from the site's origin while MJML's own types ignore the context. Rejected: a registry built per origin, which would leave the email's persisted schema depending on where it renders.
- **The root's props are typed by the registry.** `MjmlRegistry` is the core's registry over `MjmlRootProps`, inferred from the root's schema, so `parseMjmlDocument` returns an `MjmlDocument` whose head is typed, and the render reads it without parsing it a second time.
- **Attributes are declared once, in MJML's grammar.** Each table entry is `color`, `enum(...)`, `unit(...)`, `boolean`, `integer` or `string`. The editor's field descriptors are read from the tables, each props schema spreads the same table through `createMjmlAttributeShape`, so its keys are the table's keys, and two tests hold each table equal to the installed component's attributes and defaults, less `css-class` and `mj-class`. The [block types page](block-types/design.md) states the rest of each component's rules.
- **An unset attribute stays absent.** A node's props hold what its author set. The cascade answers an attribute in MJML's order: the node's own value, the root's value for its type, the root's value for all components, then MJML's default. MJML writes the root's value for all components into every type that takes its name, so the root refuses one unless each such type accepts it; the [block types page](block-types/design.md) holds that rule. MJML's defaults are not Zod defaults, since parsing would write every default into every node and `mj-attributes` could never apply.
- **Content is one of three kinds.** Rich text goes through the consumer's definition. A plain label is written escaped, and an imported label holding an element is refused at its node. Raw HTML is stored only as the sanitiser returns it, so a raw block never holds a script.
- **The kind's schema is one map.** `MjmlContentKindSchemaMap` holds the content schema of each fixed kind, the label's and the raw's. A label-kind or raw-kind component takes its content schema from that map and declares none of its own, and the renderer parses content with the same entry, so the kind and its schema cannot drift apart. Rich text is the exception: its schema is the consumer's definition's, which the map does not hold. The map is typed to cover every fixed kind, so a new fixed kind without a schema is a compile error. A definition whose kind is a label or a raw cannot hold a schema whose content is not a string: `MjmlBlockTypeDefinition` refuses it at compile time, on the generic path as on each node's. Label and raw are both strings, so a component given the other kind's entry, or a copy of an entry, is refused by its test.
- **An image's alternative text is required or marked decorative.** A decorative image renders an empty `alt`, and the read back turns an empty `alt` into the decorative flag, so the two are inverses.
- **The read back is `node-html-parser`.** MJML's own XML parser drops an `mj-include` without a word, needs MJML's component registry to know its ending tags, and reads the disk. parse5 reads a self-closing custom tag as an open one, which swallows its siblings on import.
- **The compile is the consumer's.** The package holds no copy of MJML at runtime. MJML and its preset are development dependencies, used only by the tests that hold the tables equal to the installed release.

## Sources

- [MJML documentation](https://documentation.mjml.io/): the component set, each component's attributes and defaults, the head components, and "Using MJML in JSON", the object form `mjml2html` takes in place of markup.
- `mjml-core`'s "createComponent": `htmlAttributes` writes each attribute with its value as given, which is why the render escapes.
- `mjml-preset-core`'s `dependencies`: the allowed children of every tag, which the slots are held equal to.
- `mjml-parser-xml`'s `MJMLParser`: `ignoreIncludes` defaults to true, and the ending tags come from its `components` option.
- [node-html-parser](https://github.com/taoqf/node-html-parser): the block text elements and the decoded attributes the read back uses.
- [GrapesJS MJML](https://github.com/GrapesJS/mjml): the plugin whose surface this package replaced, and whose tracker the Upstream table answers.
