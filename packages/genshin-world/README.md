Genshin Impact's world, rebuilt as an unofficial, non-commercial fan work on [`genshin-engine`](https://github.com/Esposter/Esposter/tree/main/packages/genshin-engine) and not affiliated with HoYoverse.

It ships no image, model or sound from the game: every mesh, texture and shader is generated by code, and each mark on a screen is a vector path traced from the game's own or taken from a published vector of it.

## <a name="getting-started">🚀 Getting Started</a>

```bash
pnpm i genshin-world genshin-engine genshin-interface genshin-text @esposter/shared @tresjs/core @vueuse/core three vue zod
```

Mount `WorldScreen`, which brings its own canvas, and pass in only what your bundler and server decide, and load the screens' styles once:

```vue
<script setup lang="ts">
import { WorldScreen } from "genshin-world";
import TerrainTileWorker from "genshin-world/terrainTileWorker?worker";
import { ENGLISH_GAME_TEXT, GameLanguage } from "genshin-text";
import "genshin-interface/style.css";
import "genshin-world/style.css";
</script>

<template>
  <WorldScreen
    :create-terrain-worker="() => new TerrainTileWorker()"
    :game-text="ENGLISH_GAME_TEXT"
    :is-tuning="isDevelopment || undefined"
    :language="GameLanguage.English"
    :quality-tier
    game-data-base-url="https://your-host.example/game-data"
    region-data-base-url="genshin"
  />
</template>
```

Region data lives in `src/data/regions/<region>.json`, and your server serves it at the base URL, so a region is fetched as the camera comes within reach and released as it leaves.

The game's data is not bundled. Every record the world reads — the opening's title logo and login screen, the world's ground, catalogue and animals, the game's tables and words, the character profiles and the book bodies — is fetched from `game-data-base-url`, which `GameOpening` takes as `WorldScreen` does, and every reader the package exports (`readGameData`, `readStatTables` and the rest) takes the same base as its first argument. Your host must serve every object and index entry that the package's `gameDataLock.json` names, each as `<base>/<sha256>.json`, with CORS for your page's origin. Esposter's own accounts admit only Esposter's origins, so another host must publish its own copy.

## <a name="documentation">📖 Documentation</a>

We highly recommend you take a look at the [documentation](https://github.com/Esposter/Esposter/tree/main/openspec/specs/genshin) to level up. How each screen is matched to the game is described on the [parity page](https://github.com/Esposter/Esposter/tree/main/openspec/specs/genshin/parity).

It holds everything that is the game's rather than any engine's:

- each region's authored data: its heights, colours, look and landmarks;
- the catalogue of regions, areas and subareas;
- the game's screens — its opening's splashes, login screen and startup loading — built from [`genshin-interface`](https://github.com/Esposter/Esposter/tree/main/packages/genshin-interface)'s pieces;
- the TresJS components and composables that build all of it.

### Key Exports

| Export              | Kind       | Purpose                                                                                                     |
| ------------------- | ---------- | ----------------------------------------------------------------------------------------------------------- |
| `GameOpening`       | component  | The game's opening: its splash sequence, login screen and startup loading                                   |
| `GenshinSave`       | type       | One player's whole Genshin save, with one key per system                                                    |
| `genshinSaveSchema` | schema     | The Zod schema a save is parsed against, refusing one that is too large                                     |
| `readCatalogue`     | function   | The catalogue of regions, areas and subareas, fetched by key and checked against its schema                 |
| `readGameData`      | function   | Reads one game-data record by key and parses it with the schema given                                       |
| `readGenshinSave`   | function   | Reads a save into the world's systems, leaving derived ones to the rules that read them on load             |
| `readStatTables`    | function   | The game's stat tables, fetched by key and checked against their schema                                     |
| `useSky`            | composable | Writes the sky at the game's clock into everything the sky lights, and drifts the clouds with the wind      |
| `WorldScreen`       | component  | The whole world as one screen with its own canvas, opened once its names, tables and first view have loaded |

## <a name="commands">⌨️ Commands</a>

Run from `packages/genshin-world/`:

```bash
pnpm bench              # vitest bench, one run
pnpm build              # tsdown
pnpm build:parity       # vite build --config parity/vite.config.ts
pnpm game-data:mirror   # node scripts/gameData/mirror/index.ts
pnpm lint               # lint the package
pnpm lint:fix           # eslint --fix
pnpm parity             # vite --config parity/vite.config.ts
pnpm test               # vitest watch mode
pnpm test:visual        # vitest, browser config
pnpm typecheck          # tsrs --fast --runExternalCode
```
