# Approval

Read when approving a screen's images or citing a reference for one. The one-line rules are in `SKILL.md`; this page is their reasoning.

- **The order is reference, fixture, component, `compare`, `approve`, suite.** The reference comes first because the screens built without it drifted: with the screenshot beside the screen, the parity loop has a target from the first line of the component. A fixture variant is a subscreen, and each names a reference of its own through the entry's `variant`, or a pending entry stating why it has none; `ParityReferenceMap.test.ts` fails on a variant that borrows its base's. A screen folder with no fixture is named in `packages/genshin-world/parity/pendingScreens.ts`, which `parity/screens.test.ts` reads. An approved image is `Index.png` or `Index-<variant>.png`, with no platform segment, and is written only once that subscreen's own compare clears.

- **No reference, no approval.** A screen's size, colour and place are measured from a reference in its own language and build, never carried over from another client's or guessed; a value with no reference ships only as a best estimate, marked provisional where it stands with what it was estimated from. `ParityReferenceMap.test.ts` fails for any fixture (not `isMotionOnly`) no entry of the map names, so a screen that was never compared cannot reach the suite; a pending entry names it with the reason it has no reference, and `compare` scores none of it. A public video that letterboxes the game (a phone, a window) is sampled outside the repository into a labelled screenshot cropped to the game's screen there, and scored over a `region` clear of watermarks; its edges are the video's softness, so a clean score there is an outline of about a percent. A wiki crop of one dialog or button row with no whole frame behind it gives its colours and glyphs but no scale: a compare shoots at the reference's own size, so its unit is the crop's and not the game's, and the screen's size is a best estimate held provisional, with a whole frame on the References sought list and a queue item until one is found.

- **An agent approves with `genshin:parity approve` once `compare` is clean against a stored reference.** `pnpm -C scripts genshin:parity approve <reference>` runs the reference's compare and prints its score against the bar (the screen's own `approval` on its reference when it records one, its measure and bar; otherwise `DEFAULT_APPROVAL`, a mean difference under 1%, the 99% likeness the screens are held to, which the output names as the fallback). Only a score under the bar writes the image, by running the visual suite with `-u` for that one screen's test alone, never the whole suite. A reference missing from disk is fetched first, from its wiki title, as `fetch` does; one sampled from a recording is reported there with its `source`, for a person to cut, and a `plateSource` screenshot missing from disk is reported with its own. A refusal writes no image and names its reason: no reference, a failed compare, a score at or over the bar, or a reference that judges less than the whole screen in its base state (a region it names, or props of its own, which shoot another state than the fixture's). Such an item is met by its compare alone: a score under its bar ends it with no image, since the image is the whole screen, which that screen's whole-frame item approves. A variant's image is approved with `--variant` only when the screen's reference records that variant as its `variant`, since the compare then judges that variant's state; a variant the map does not record is refused with no compare, so no other state's score can approve it. The compare's row is written to the committed report whether or not it clears the bar. The commit carries the image, `Index.png` beside the component. A fixture's `variants` are further states, each approved as `Index-<variant>.png` (`FIXTURE_VARIANT_SEPARATOR`, a dash, since the repository's `ID_SEPARATOR` is a character Windows rejects in a file name). A screen that moves (a scene) is held still for the suite by its fixture's `stillProps`, read by the suite alone, so the page and the references keep drawing it as it moves. A new image's first run writes it and fails, so a missing image is only ever written through `approve`, never by a whole-suite run without `-u`. `genshin-interface`'s components have the same fixtures and images, shot to their own box at 1080 high, and its suite fails for a component without a fixture; those components have no reference in the map and are not screens on the parity page, so `approve` cannot approve them.

- No person approves images, and nothing is approved blind.
