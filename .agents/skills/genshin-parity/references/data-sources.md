# Data sources

Read when a table is missing from the dump, a dump field is obfuscated, or a fit or loop publishes its record. The one-line rules are in `SKILL.md`; this page is their reasoning.

- **The dump is the install's build, so every table is compared with `main` and replaced where its size differs.** `genshin:text fetch` lists every table in `ExcelBinOutput/` and every text map in `TextMap/`, not a named list, every talent config in `BinOutput/Talent/AvatarTalents/`, which a reader takes whole, the binary of each quest the reader carries (its main quest's, fetched once the tables are down), and each other `BinOutput/` file the dump already holds, and replaces each that differs from the community repository's `main`, the branch at 7.1.0, the install's build. `master` is the 6.6 patch and is never a source. Fetched tables go into `~/Esposter/genshin-parity/text/ExcelBinOutput/`, never the repository, and the 6.6 copy of the tables, the text maps and the held binaries is kept beside it at `~/Esposter.noindex/genshin-dump-backup-6.6/`.

- **An obfuscated dump field is modelled under the dump's own key, named in a comment by the game's field, and checked against a value the game shows before its rows are trusted.** The skill depot's passive opens are `LLEFDMDOMGG` at this revision, each phase `DHIEHDPAFGI` (`LHNAJLJNBAH` and `KGGNNMEALJM` in the 6.6 dump), checked against the phases the first and fourth ascension passives open at (`openspec/specs/genshin/talents/design.md`). A renamed key reads as absent rather than failing, so a refresh that moves a key is followed by a reader migration, checked against shared rows, before any hosted record is published from the refreshed dump.

- **From 7.1 the dump leaves out every field at its default, and `readExcelTable` writes the numbers, flags, lists and messages back.** The tables are written as protobuf's JSON writes them, so a 0, a `false`, an empty list or an unset message is absent from its row, and a list of messages holds `{}` for an entry at every default. `readExcelTable` is the one reader of `ExcelBinOutput/`, and `fillDumpDefaults` restores each field another row of the table holds at its kind's default, recursively, as protobuf reads an unset message, leaving a numeric key alone, since it is an entry of a map keyed by id. A slot a list leaves empty, written `{}` in 6.6 as in 7.1, is so read with every field at zero, and a reader skips it by its zero id, never by a missing field. A string is not restored, since an enum is written by name and its zero's name is held by no row the dump writes: a reader of an enum field names its own default (`type = EXPEDITION_RANK_CONDITION`). `BinOutput/` is read raw, so its readers name their own defaults.

- **A fit or a parity loop publishes its record by key, and the page reads it through the mirror.** `genshin:assets fit <component> --only <part>` and the loops that refit one record (`notes`, `expression`, `instruments`, `calibrate --write`) each replace one key of the hosted game data, and read the record they refine from its last publish, never a file; the parity page's fixtures pass `GAME_DATA_LOCAL_BASE_URL`, which `gameDataMirrorPlugin` answers from the local mirror (the `genshin-data` skill).
