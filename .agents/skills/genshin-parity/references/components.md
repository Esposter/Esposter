# Components

Read when adding a component, its fixture, or its reference index. The one-line rules are in `SKILL.md`; this page is their reasoning.

- **A component is a PascalCase folder under a PascalCase section, named by its path as Nuxt names the app's**: `packages/genshin-world/src/components/<Section>/<Name>/Index.vue` exports as `<Section><Name>` (`Login/Screen` is `LoginScreen`), and its fixture, browser tests, approved images and game reference sit beside it as `Index.fixture.ts`, `Index.browser.test.ts`, `Index.<platform>.png`, and `Index.reference.ts` with a `<Topic>.reference.ts` per part of it. Props in, events out, no store. A section is a part of the game (`Game`, `Splash`, `Loading`, `Login`, `World`, then `Menu`, `Hud`, `Map` as they come), and `Game/Opening` owns every handoff between the screens it shows, so a host mounts it once. A piece more than one screen uses is a `genshin-interface` component, never a shared folder here. Services and models mirror the section in lowercase (`services/login/`, with a part's own constants beside its code: `services/login/tower/constants.ts`), and an exported map is a file of its own. The app wires a screen to its stores; `AgentConsole/Panel/Opening.vue` is the pattern.

- **Read a component's `Index.reference.ts` and its topics before searching, and write every result into the topic it was run on.** The index holds every piece of the game's data the component derives from (an asset's kind, block, path ID, name and role; a capture's file and parity reference; a table's path) by a key a derived value cites, and each `<Topic>.reference.ts` one part's investigations, each its method, result and outcome (dead ends and rejections too), with what is open; how each kind of data reads and the shortcuts to reach for first are `openspec/specs/genshin/game-data-formats/design.md`. Metadata only, never a value or a pixel of the game's.
