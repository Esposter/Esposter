# The interface

Read when a 2D screen is laid out, styled or set in text to match the game's, or compared over a scene.

- **Draw every screen inside `genshin-interface`'s `GameScreen`**, its root: the size container, the game's face and pointer, `--unit` (`min(100cqh / 1080, 100cqw / 1920)`, the smaller axis as the game fits its interface; height alone breaks any window narrower than 16:9), `--canvas-unit` (a unit of the interface's 1600 by 900 canvas, 1.2 of `--unit`) and `--canvas-inset`. Everything inside is `calc(var(--unit) * n)`, measured from a reference scaled to 1080 high (a 1440 reference's pixels times 0.75).
- **Place a piece where the game's RectTransform anchors it.** The screen's interface tree (its RectTransforms, dumped raw for their anchors) says which edge or corner each piece rides on; the screen's `fit` publishes the tree as its `<screen>/interfaceRects` record (`fitInterfaceRects`, keyed by path under the root), which the screen reads from the hosted game data, so a refit shows once that record is published, and the markup nests a `GameRect` per piece in the game's order, each placed inside its game parent's box, the outermost on the canvas (the screen less `--canvas-inset` at each side). A piece is never placed by a hand-copied rect (`apps/web/content/docs/genshin/interface-layout.md`). A foot anchored to the bottom stays there on any window, where a position measured from the middle rides up a window narrower than 16:9; shoot one, such as 1080 by 1440, to see it. What the tree cannot hold (a prefab loaded at run time, a piece a script resizes, a line of text in its rect) is measured and written inside the `GameRect` it loads into, from that box's edge. A layout group's children read zero and the fit leaves them out, so their spacing is measured off the recordings.
- **No element a host styles.** A screen is mounted inside the app's pages, whose element rules (the console's `h1`–`h6`, `b`, `strong`) reach through scoped styles; a heading is a `<p role="heading" aria-level>`, and `compare` on the parity page cannot catch a host's rule, so check the screen in its host once.
- **A `genshin-interface` screen is compared through the `genshin-world` component that mounts it.** The parity page globs only `genshin-world`'s components, so a screen in `genshin-interface` has no `?screen=` of its own: its world wrapper (`components/Inventory/Screen`, the bag) carries the `Index.fixture.ts` and its barrel name is the reference's `screen`. The wrapper is where the state is held, so a state the interface holds in its own props (a selection, a tab) is set through the wrapper's own state.
- **Styles are scoped `<style>` in the SFC** with the measured hex values, not UnoCSS or the app's tokens: a screen matches the game, not the design system. `@tsdown/css` bundles each package's into its `style.css` (`genshin-interface/style.css`, `genshin-world/style.css`), which the app loads in `configuration/css.ts`.
- **Text is the game's face, or the open face nearest it.** The game sets everything in HYWenHei 85W, a commercial face nothing may ship, so `GAME_FONT_FAMILY` names it first for a reader who has it, then Signika. Signika was chosen by setting the game's own lines (a large French notice frame) in each of seventy open candidates, scaling each line to the game's ink box, and scoring the overlap of its binarised ink with the game's (the width of the same words at the same height is a second score): Signika SemiBold overlapped most, where Asap, picked first on width alone, and a serif like Lora, suggested by a sharpened 12px heading, both lost. Score both sides binarised, since the game's text is grey and a candidate's black, and read a heading's shape from a large frame, never a small sharpened picture. Pick a replacement the same way, never by eye alone. A text screen's remaining difference against the game is the face's.
- **Place a traced icon in the reference's own pixels.** A screen sets `--reference-pixel` to one pixel of the reference it is compared against (`unit * 0.75` for a 2560 wide still, `unit / 0.875` for 1680), so each glyph box and rect is written as the still measures it and lands on it at any window size. A glyph and a button that takes its box come from the same trace region.
- **Score a translucent panel over the region it is opaque in.** A menu's glass shows the world, which the page does not draw and no still holds apart from the menu, so the compare region stops where the glass turns clear, and what is left is named as the game's typeface, texture or art.
- **Keep the game's cap height and letter-space Signika out to the line's width**, since at one cap height it sets narrower than the game's face.
- **A reference in another language names it in its props, never its text.** A reference whose `props` name a `language` has the parity page hand any screen taking `gameText` that language's own words (`GameTextLoaderMap`), so a localized frame is compared in the words its client shows, from the one map every reader loads.
- **Compare an interface over a scene on the reference's own frame.** With `isBackdrop`, a reference's clean plate is drawn behind the screen (its frame with its region filled from the pixels around it, served to the page, pixelated so it lands exactly), so a cell the interface leaves bare scores that plate's own error rather than 0.00%, and a render that draws nothing is punished rather than rewarded. Capture frames are rewritten without FFmpeg's gamma and primaries tags, which a browser colour-manages. Translucent glass (a band, a bar) would darken twice over the recording's own glass, so solve its colour from the scene around it instead (`luma` or `measure` above and inside it), and the score checks the opaque pieces and every placement. An interface compared over its recording cannot see a piece it drops, since the backdrop draws the game's own; a region's plate removes that piece, so only a whole-frame reference still needs the screen shot bare.
- **An SVG's sizes are in its viewBox's units, never pixels.** A CSS `calc(var(--unit) * n)` on an SVG `text`'s font size or stroke reads as n metres of the view, so it draws n times the view's scale and overflows the screen. A pixel size inside an SVG is a share of its view's extent, as the map's names are (`MAP_LABEL_SHARE`, `services/map/constants.ts`); the pixels a reference measures become the share at its own view's scale. A backdrop is only for a frame with no interface of its own: a wiki screenshot of a whole screen (the quest screen) draws its text under ours, so its score counts a double print rather than a placement, and such a screen is compared whole, its blurred scene named as what the page cannot draw.
