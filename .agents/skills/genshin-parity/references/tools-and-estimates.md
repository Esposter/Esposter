# Tools and estimates

Read when a loop has not converged, a tool is built or pruned, or a value is estimated. The one-line rules are in `SKILL.md`; this page is their reasoning.

- **What nothing published shows clearly is estimated, then verified in one batch.** The estimate names its basis where it stands (the nearest reference, a neighbouring screen's measure, the extracted data). One the agent is unsure of goes on the roadmap's **Manual verification** list as one line: the value, ours beside the source it was estimated from, and the yes-or-no it asks. The user works the list in one sitting when it suits them, and nothing waits on it.

- **Reach for the unknown's tool before a round.** `references/toolbox.md` names the tool that answers each unknown; a loop that has not converged in two rounds is missing one, and the `recreation-tooling` skill is how it is found and built.

- **A tool earns its place by the benchmark.** The only reward line is faithfulness to the game, which each pass's measure against the game's own data and, at acceptance, `compare`'s committed report score. A tool stays while it produces or reads those scores, or supplies exact data that moves them; one that has done neither through a derivation, a scratch solver or a superseded cost, is deleted rather than kept for later. A committed score taken where nothing fits (a loss table at an unsolved pose) is noise and is not committed.
