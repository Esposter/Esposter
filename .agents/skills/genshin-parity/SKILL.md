# Genshin Parity

The loop and why it is shaped this way are `openspec/specs/genshin/parity/README.md`, and the route a question takes through the game's own files, a shader's port among them, is `openspec/specs/genshin/game-reading/design.md`. This skill is the rules each step follows.

## Settled — do not re-propose

- **Committing a reference.** Screenshots, recordings and wiki images of the game live in `~/Esposter/genshin-parity` (`PARITY_DIRECTORY`) and never enter the repository. Only `ParityReferenceMap` names them, by wiki title or by a recording in `captures` and the second to take (`capture`, `seconds`).
- **Asking the user to record what is published.** Text, wording, marks and screens come from a search first: the wiki (its API, `list=search&srnamespace=6` for files), the user's installed game, decoded at its own patch, for every string the game holds (a community dump only until the install's reading of that file lands, never a second source beside it), and for its tables the community dump pinned to the install's revision (the entry on decoding the tables, below). What the install decodes stays outside the repository, under `~/Esposter/genshin-parity/text`; the repository commits only the slices the app reads, generated per language and loaded on demand, a few megabytes in all, so a decoder that would commit tens of megabytes is a design to rethink, never a commit, and public videos, fetched into `captures` by `recreation clip --directory ~/Esposter/genshin-parity/captures` (`--download-sections` for the minutes needed). What nothing published shows is estimated, never recorded on request (the next entry).
- **Waiting on the user for a recording, or asking for one.** Users do not record data for this workflow: more clips were owed than one person's sessions cover. A value a recording would measure is sourced in order: a wiki screenshot for a still look, a public clip on YouTube or Bilibili for motion (`recreation search`, then `clip`), the extracted animation clips for a timing. Where none shows it, a best estimate ships marked provisional with its basis, so no work waits; the clip still sought stays on the roadmap's **References sought** list, and an estimate the agent is unsure of goes on its **Manual verification** list.
- **Reading leaked server data, or looking in the client for the scene group scripts.** The community's decoded group scripts (the Grasscutter resource sets) come from a 3.6-era leak of the game's server data with no licence, so they are never read, not even as a cross-check. The client holds no group script at all, only each scene's config and dummy points (`openspec/specs/genshin/game-data-formats/design.md`), so a field only a group script holds comes from the next source: the official map's points, the dump's tables, the wiki, else an estimate marked provisional.
- **Sending input to the game.** The tool launches and records the game; the user plays. Injected input is botting under its terms, with an anti-cheat driver watching.
- **Rendering a screen through Nuxt to check it.** A screen renders on the world package's parity page on plain Vite, up in about a second; a Nuxt build per check was the cost that sank the old screenshot suite.
- **A hand-kept list of screens.** A screen is on the page and in the suite by having an `Index.fixture.ts` beside its `Index.vue`, and is named by the package's own barrel.
- **Shipping or committing anything taken from the game's files**, converted or not: nothing of them is committed, built, uploaded or deployed. Extracted assets are references like any screenshot; what ships is our re-derivation, our shaders, generators and fitted data, so the deployed render path is our own. Short of that line a re-derivation has no fidelity ceiling: the goal is the browser showing what the game shows. A developer's own local extraction is drawn, never shipped: the witness render measures our path against it on the parity page, and under `nuxt dev` the world draws it in place of the stand-ins of each family it holds, read from the developer's disk at request time (`openspec/specs/genshin/scene-derivation/design.md`, `openspec/specs/genshin/derived-assets/development-exports/design.md`).
- **Decoding the Excel and BinOutput tables through the code metadata.** The only public 7.x decoder is pinned to 7.0, reads a running process for its asset path, and yields positional rows without names, and the build's field names are likely scrambled in the metadata too. So the tables stay the community dump's, pinned to the install's revision, while the install decodes the text maps. Revisit when a public tool decodes the current patch with its names.
- **Injecting anything into the running game**, to read a script's fields or capture its frames. The game's code metadata is another matter: it may be decrypted offline from the user's own install when what it decodes is worth far more than the dump gives, such as the tables' real field names or a MonoBehaviour's type data. Nothing it reads is committed, and the running game is never touched. Short of that, what the exporter dumps is read as a reference: a shader asset, and a MonoBehaviour's raw serialized bytes, scanned without type data for the pointers and values whose shape names them.
- **A `genshin-assets` package.** Nothing extracted is committed, so it would be empty; the extraction and the fitting transforms are tooling in `scripts`, and what they emit is data beside the component reading it. The packages stay three: `genshin-engine` (game-agnostic rendering), `genshin-interface` (the game's 2D interface, no three.js, so an interface-only page never loads it) and `genshin-world` (the game's content: its regions, scenes and screens).
- **Tracing below full resolution.** A trace starts from the source's full resolution, never reduced, and enlarges a small mark before tracing it.
- **Gating the music's noise on how much of a band lies on our partials.** No share tells the lowest band from 125 Hz, both above nine tenths on partials, so the gate that clears the lowest band's overfill takes 125 Hz's noise too and lowers pitch agreement; through the noise solve's own masks, which carry each note's ring, it shuts nearly every band. The overfill is the player's noise playing in step across notes (`openspec/specs/genshin/music/README.md`, "Not yet").
- **Masking a note's partials in the noise solve through its voice's whole release** rather than `MUSIC_RELEASE_SECONDS`. Too few readings are left and they decide the solve: the bass's 125 Hz noise rose several times over and pitch agreement fell.
- **Subtracting a synthesis of our own tones before reading the noise.** A note's envelope spreads next to nothing past the partials' clearance, so the noise barely moves.
- **Starting a note's noise between two sample frames**, at its exact time with an offset in the loop. Its loop is then read between samples, which loses about half the top band; a whole-sample offset alone changes nothing while the start lies between frames, so the start is rounded to a frame as well (`openspec/specs/genshin/music/README.md`, "Not yet").
- **Choosing a recorded instrument by its fitted profile.** Ranking candidates through `fitInstrument` by harmonics and envelope picked a cello that overfilled the band at 125 Hz: that ranking charges a faint high overtone as much as a loud low one (`openspec/specs/genshin/sampled-instruments/design.md`).
- **Carrying a tuning from a recorded instrument's own fit.** Each library's mappings already tune its recordings to within about ten cents, so a voice keeps the game's fitted tuning; the cello's own fit read half a semitone sharp (`openspec/specs/genshin/sampled-instruments/design.md`).
- **Choosing recorded instruments by the bands alone.** The bands are blind to pitch, and their choice, timpani on the top voice among them, cost both pieces pitch agreement; a candidate keeps its voice's pitch as well as pure tones do, and a mix is ranked by its whole listening score (`openspec/specs/genshin/sampled-instruments/design.md`).
- **Looking in the sampled render for a pitch loss every recording shares.** `genshin:parity solos` reads pianos, harps and plucked strings at or past pure tones' agreement in every voice of both pieces; the loss was the instruments chosen (`openspec/specs/genshin/sampled-instruments/design.md`).
- **Carrying the game's swells in each note's velocity.** A velocity is fixed when its note starts, and a section swells under notes already sounding; each segment's expression carries it, as an orchestral mockup's expression controller does (`openspec/specs/genshin/music/README.md`).
- **A fixed equaliser over the shipped music, or over a layered mix.** Its band gains, fitted on one half of a piece, leave the other half about as far off as before, so what it gains in place is that stretch's frames rather than the music's balance (`openspec/specs/genshin/music/README.md`). Held out over the second piece's layered mixes, what it gains is smaller than the spread between the solve's distance and `listen`'s (`openspec/specs/genshin/sampled-instruments/design.md`).
- **A reverb to close what the recorded instruments leave.** The best mixes' largest band gaps do not move with a note's age, so they are short of spectrum rather than ring, and a reverb only lengthens what a note already holds (`openspec/specs/genshin/sampled-instruments/design.md`).
- **Joining a transcribed note to the one before it at its pitch** where the game's fundamental does not rise at its start. `attacks` reads no fewer jumps and both pieces lose pitch agreement, since a joined note then sits on its decay where the game's holds (`openspec/specs/genshin/music/README.md`, "Not yet").
- **Taking a note's level and decay at the frame the voice's median attack predicts**, not at the note's loudest frame. The first piece then barely decays, jumps far less often than the game's and loses pitch agreement (`openspec/specs/genshin/music/README.md`, "Not yet").
- **A decay per octave of overtones on the synthesizer.** The fit reads the second piece's overtones dying faster than their fundamentals, yet playing it moves neither score, for an oscillator an octave on every note (`openspec/specs/genshin/music/README.md`, "Not yet").
- **Holding the first piece's pitch with the catalogue's recordings** by their levels, by two layered on a voice or by an octave equaliser on each voice. Solved for pitch alone, none reaches the synthesizer's agreement, and the equaliser held out across time stays further under it (`openspec/specs/genshin/sampled-instruments/design.md`).
- **Softening a component to match a recording's blur.** A recording softens everything it shows, but the game draws its text crisp, so a component is never blurred to a capture: `compare` softens our shot by its capture's measured sigma (`openspec/specs/genshin/parity/README.md`, `references/toolbox.md` "Softness").
- **Pausing the compute queue along with other work.** A session that stops its feature lanes, for a usage window or a user's stop on one lane, leaves the queue's runners running and restarts any that stopped: the user alone stops the queue (`references/compute-queue.md`, "Keeping it busy").
- **Keeping noise levels past `MUSIC_DECIMALS`.** It moves the listening score by hundredths of a decibel.

## Rules

- **Numbers before looking.** Run `pnpm -C scripts genshin:parity compare <reference>` and read the mean and the grid; zoom only on a cell that stands out. Target a mean of hundredths of a percent, with any remainder explained (antialiasing along an edge). The run rewrites its row of the committed `ParityReferenceMap.snapshot.md` (`--all` every row), which is committed with the change that moved it and is the only score a session quotes.
- **An agent approves a screen's image with `genshin:parity approve` once its compare is clean against a stored reference, and fetches a missing reference first.** No person approves images, and nothing is approved blind (`references/approval.md`).
- **A screen's load is held to its budget by the load bench**, `pnpm -C scripts genshin:parity load <screen>` (`openspec/specs/genshin/load-budget/design.md`).
