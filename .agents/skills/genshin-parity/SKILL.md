# Genshin Parity

The loop and why it is shaped this way are `apps/web/content/docs/genshin/parity.md`. This skill is the rules each step follows.

## Settled — do not re-propose

- **Committing a reference.** Screenshots, recordings and wiki images of the game live in `~/Esposter/genshin-parity` (`PARITY_DIRECTORY`) and never enter the repository. Only `ParityReferenceMap` names them, by wiki title or by a recording in `captures` and the second to take (`capture`, `seconds`).
- **Asking the user to record what is published.** Text, wording, marks and screens come from a search first: the wiki (its API, `list=search&srnamespace=6` for files), the community data dumps for in-game text, and public videos, fetched with yt-dlp from a throwaway virtual environment in the scratchpad (`--download-sections` for the minutes needed) into `captures`. Record the game only for what nothing published shows, or ask the user for a picture when a search engine refuses a script (image search does).
- **Sending input to the game.** The tool launches and records the game; the user plays. Injected input is botting under its terms, with an anti-cheat driver watching.
- **Rendering a screen through Nuxt to check it.** A screen renders on the world package's parity page on plain Vite, up in about a second; a Nuxt build per check was the cost that sank the old screenshot suite.
- **A hand-kept list of screens.** A screen is on the page and in the suite by having an `Index.fixture.ts` beside its `Index.vue`, and is named by the package's own barrel.
- **Shipping or committing anything taken from the game's files**, converted or not, and a render path that draws such files locally. Extracted assets are references like any screenshot; only parameters fitted to them ship, so the one render path is our own kits.
- **A `genshin-assets` package.** Nothing extracted is committed, so it would be empty; the extraction and the fitting transforms are tooling in `scripts`, and what they emit is data beside the component reading it. The packages stay three: `genshin-engine` (game-agnostic rendering), `genshin-ui` (the game's 2D interface, no three.js, so an interface-only page never loads it) and `genshin-world` (the game's content: its regions, scenes and screens).
- **Tracing below full resolution.** A trace starts from the source's full resolution, never reduced, and enlarges a small mark before tracing it.

## Rules

- **A scene is judged by its shape and its tone.** A 3D screen rebuilt from shapes never matches the game pixel for pixel, so `compare`'s `shape` (an F-score of the edges both share, 1 identical) and `tone` (blurred colour, 0 identical) are its numbers; the mean is read for a flat screen. A reference sets the props its state needs (`props`, a time of day), so one screen serves several references.
- **Numbers before looking.** Run `pnpm -C scripts genshin:parity compare <reference>` and read the mean and the grid; zoom only on a cell that stands out. Target a mean of hundredths of a percent, with any remainder explained (antialiasing along an edge).
- **A component is a PascalCase folder under a PascalCase section, named by its path as Nuxt names the app's**: `packages/genshin-world/src/components/<Section>/<Name>/Index.vue` exports as `<Section><Name>` (`Login/Screen` is `LoginScreen`), and its fixture, browser tests and approved images sit beside it as `Index.fixture.ts`, `Index.browser.test.ts` and `Index.<platform>.png`. Props in, events out, no store. A section is a part of the game (`Game`, `Splash`, `Loading`, `Login`, `World`, then `Menu`, `Hud`, `Map` as they come), and `Game/Opening` owns every handoff between the screens it shows, so a host mounts it once. A piece more than one screen uses is a `genshin-ui` component, never a shared folder here. Services and models mirror the section in lowercase (`services/login/`, with a part's own constants beside its code: `services/login/tower/constants.ts`), and an exported map is a file of its own. The app wires a screen to its stores; `AgentConsole/Panel/Opening.vue` is the pattern.
- **Draw every screen inside `genshin-ui`'s `GameScreen`**, its root: the size container, the game's face and pointer, `--unit` (`min(100cqh / 1080, 100cqw / 1920)`, the smaller axis as the game fits its interface; height alone breaks any window narrower than 16:9) and `--edge-inset`. Everything inside is `calc(var(--unit) * n)`, measured from a reference scaled to 1080 high (a 1440 reference's pixels times 0.75).
- **Place from the middle, and only corner buttons from an edge.** Only one axis fits the window, so on the other the screen is wider or taller than 1920 by 1080 units: a position is `calc(50% ± var(--unit) * n)` on both axes, measured from the reference's centre, as the game centres its interface. A top of `var(--unit) * n` rides high on a window narrower than 16:9; shoot one, such as 1080 by 1440, to see it. The corner buttons and the build string are the one exception, since the game anchors them to the screen's sides: `var(--edge-inset)`, 96 units on 16:9 and 71 more on any wider screen, measured on a 2560 and a 3440 wide recording.
- **No element a host styles.** A screen is mounted inside the app's pages, whose element rules (the console's `h1`–`h6`, `b`, `strong`) reach through scoped styles; a heading is a `<p role="heading" aria-level>`, and `compare` on the parity page cannot catch a host's rule, so check the screen in its host once.
- **Styles are scoped `<style>` in the SFC** with the measured hex values, not UnoCSS or the app's tokens: a screen matches the game, not the design system. `@tsdown/css` bundles each package's into its `style.css` (`genshin-ui/style.css`, `genshin-world/style.css`), which the app loads in `configuration/css.ts`.
- **A glyph comes from the game's own mark by `trace`, preferring the wiki's standalone render** (`File:Element <Name>.svg`, 1600 units). A mark on a screenshot is small, and a pale one traces rough. Keep the region and trace check image, and read it before using the path. Paths live in a `…PathMap` service keyed by an enum (`ElementType`; never `Element`, which is the DOM's).
- **An order the game shows is its own array, never an enum's.** Lint sorts an enum's members alphabetically, so `Object.values(ElementType)` is not the game's order; `ElementTypes` lists it (Pyro, Hydro, Anemo, Electro, Dendro, Cryo, Geo).
- **A vector beats a trace.** Before tracing a logo, search Wikimedia Commons (`commons.wikimedia.org/w/api.php`, `list=search&srnamespace=6`) for its SVG, and use its paths and transforms as they are: the publisher's letters and ring silhouette come from `File:HoYoverse Logo.svg`. A trace of a raster chips wherever compression or printed detail meets an edge. Check a found SVG is the same lettering (Commons' `Genshin Impact wordmark.svg` is an older one without the star and arcs).
- **The tracer splits ink by distance from the paper**, the colour at the region's corners, so a coloured or lit mark needs no inverting, and it drops outlines smaller than a sliver of the region (`SPECK_SHARE`), which removes a logo's printed sparkles. A logo the game draws flat on a splash is traced from its coloured render with the ink share lowered (`trace … 1 0.25`), so sparkles on an edge stay ink instead of notching it, and filled flat.
- **A multi-colour mark is a silhouette filled by angle and by radius**: the shape as a CSS `mask` from its path, and its colours sampled in both dimensions from the mark's own field by `polar <image> <bands> <angles>`, each band a `conic-gradient` laid over the band inside it through a radial mask ramping between their radii, so the fill shifts from outside to inside as well as round it (angle alone was tried first and flattened the ring's lighter inner edge). Its glow is a blurred copy on a wrapper (a filter on the masked element blurs before the mask cuts). The publisher's ring is the pattern.
- **Find a mark's box from the pixels**, not by eye: the ink's column runs and extents along the row give each box, and equal boxes around each centre keep the marks aligned as the game draws them.
- **Motion: find, sample, then pause.** Sample a recording at 1 fps to find its events, then `frames <file> 30|60 <start> <seconds>` over each one (sharp for GIF and animated WebP, which the wiki serves and FFmpeg cannot decode; FFmpeg for video). `shoot <screen> <w> <h> --motion entry <ms…>` holds the screen's own animations as it mounts; `props` (the default) lets those finish, then sets the fixture's `motionProps` and pauses on the transitions that setting starts. Stills and the visual suite show `props` alone. The page flushes style between the entry and the props, or the browser folds both into one style change and starts no transition. After a new import, the first load of the page reloads while Vite optimises it; shoot again. Compare with `luma` over the same region of both; it takes a frames folder too, since a second at 60 frames outruns Windows' command line. A sequence of screens runs as one Web Animations timeline per screen (fades and holds as keyframe offsets, each segment's easing on its keyframe), so a held shot at any moment shows that moment; its fixture is `isMotionOnly`, since the visual suite's screenshot finishes animations. Measured timings live in the section's `constants.ts`, with how they were measured. A recording's colours read true only because `RECORD_ENCODING` converts to labelled limited-range YUV before AMF, which otherwise labels its own limited range as full and squeezes every value (white as 234); keep that conversion, and still take exact colours from a lossless still or the wiki's PNG. `session-2.mp4` predates it and was relabelled limited range in place (`h264_metadata=video_full_range_flag=0`); its white still reads 253, so a comparison against it has a floor of about 0.4%.
- **Record the game's window only**, with `record <name> <seconds>` armed before the user starts the game: Windows Graphics Capture by executable, GPU-encoded, Matroska. Never capture a screen rectangle, which takes the desktop, the webcam and any overlay whenever the game is not in front.
- **FFmpeg is the pinned release the tool fetches** (`FFMPEG_ARCHIVE_URL` and its SHA-256, into `FFMPEG_DIRECTORY`). To move it, bump the version and checksum together; never add an npm FFmpeg (none bundles 8 or later, which window capture needs).
- **No reference, no approval.** A screen's size, colour and place are measured from a reference in its own language and build, never carried over from another client's or guessed; a value with no reference is not shipped. `ParityReferenceMap.test.ts` fails for any fixture (not `isMotionOnly`) no reference names, so a screen that was never compared cannot reach the suite. A public video that letterboxes the game (a phone, a window) is cropped to the game's screen with the reference's `crop`, and scored over a `region` clear of watermarks; its edges are the video's softness, so a clean score there is an outline of about a percent.
- **Text is the game's face, or the open face nearest it.** The game sets everything in HYWenHei 85W, a commercial face nothing may ship, so `GAME_FONT_FAMILY` names it first for a reader who has it, then Signika. Signika was chosen by setting the game's own lines (a large French notice frame) in each of seventy open candidates, scaling each line to the game's ink box, and scoring the overlap of its binarised ink with the game's (the width of the same words at the same height is a second score): Signika SemiBold overlapped most, where Asap, picked first on width alone, and a serif like Lora, suggested by a sharpened 12px heading, both lost. Score both sides binarised, since the game's text is grey and a candidate's black, and read a heading's shape from a large frame, never a small sharpened picture. Pick a replacement the same way, never by eye alone. A text screen's remaining difference against the game is the face's.
- **A screen's behaviour only a browser runs is an `Index.browser.test.ts` beside it**: the Web Animations and CSS transitions a screen or the opening hands on with, played to their ends with `finish()`, with timers and frames faked for the rest and the browser's own frame kept for the events a transition sends. The browser suite (`test:visual`) runs it; the package's ordinary suite excludes it. `Game/Opening`'s holds the opening end to end: splashes, the login's title, flight and door, the startup marks and the finish. A 3D screen's frames are real renders, so its test's timeout covers the flight.
- **Approve with the visual suite once `compare` is clean.** `pnpm -C packages/genshin-world test:visual --run -u`, then commit the image, `Index.<platform>.png` beside the component, with it. A fixture's `variants` are further states, each approved as `Index-<variant>.<platform>.png` (`FIXTURE_VARIANT_SEPARATOR`, a dash, since the repository's `ID_SEPARATOR` is a character Windows rejects in a file name). A new image fails its first run, the one that writes it. `genshin-ui`'s components have the same fixtures and images, shot to their own box at 1080 high, and its suite fails for a component without a fixture.
- **Compare an interface over a scene on the reference's own frame.** With `isBackdrop`, a reference is drawn behind the screen (served to the page, pixelated so it lands exactly), so every cell the interface leaves bare scores 0.00% and only the interface can differ. Capture frames are rewritten without FFmpeg's gamma and primaries tags, which a browser colour-manages. Translucent glass (a band, a bar) would darken twice over the recording's own glass, so solve its colour from the scene around it instead (`luma` or `measure` above and inside it), and the score checks the opaque pieces and every placement.
- **Keep the game's cap height and letter-space Signika out to the line's width**, since at one cap height it sets narrower than the game's face.
- **The world's shapes come from the game's own assets, measured and never shipped.** `pnpm -C scripts genshin:assets map`, then `extract <component>`, then `fit <component>`, with the game closed: the steps, what an export holds and each fit are `apps/web/content/docs/genshin/derived-assets.md`. Nothing extracted enters the repository or a build, and no vertex or pixel of it is kept; `fit` writes only our kits' parameters, as `packages/genshin-world/src/data/<component>/*.json`, which a scene reads and never hand-edits. Adding a component takes a name pattern in `DerivedAssetComponentMap` and a fit in `DerivedAssetFitMap`. The interface is the exception, rebuilt from screenshots and recordings, which its overlay compares hold exactly.
- **A component is its arrangement, not its meshes' names.** One set of meshes is laid out several times across a scene's blocks, so a fit keeps only the roots the component is (`readComponentPlacements`), and a scene's sky, effects and prefab parts are found from what its renderers draw, through the asset map's path IDs (the page's "Finding what a scene draws"). A layout that places a part nowhere the captures show it is the wrong arrangement or the wrong heading, before it is a missing asset.
- **Read a texture's channels before fitting it.** They are rarely colours: a gradient can be falloff curves and an atlas's red the painted light. A diffuse texture is albedo, so light is measured over it, never baked into it.
- **What the blocks cannot hold is measured from the captures, over what they can.** A MonoBehaviour or a particle system exports without its fields, so a camera path, an emitter's spread or a light's strength is read off the references and expressed over a fitted value (the camera's height over the walkway's width, a light's strength over the stone's albedo), never as a bare figure. A scalar is measured over the region it governs (a light's strength over a lit patch of the stone, both sides sampled with `measure`), never by a search of the whole frame's mean: that mean rewards a washed-out frame over the hazy references, and a search of it lifted every light several times over while the towers lost their shading.
- **`fit` never reads the game.** `extract` is the one step that runs AnimeStudio, and it refuses while the game runs; a change of fit, selection or tolerance reruns `fit` alone.
- **The parity page is `pnpm -C packages/genshin-world parity`, on port 3002, and the tool `pnpm -C scripts genshin:parity`, run through `tsx` for its enums**, started in the background before `compare` or `shoot`.
