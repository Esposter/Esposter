# Genshin Parity

The loop and why it is shaped this way are `apps/web/content/docs/genshin/parity.md`. This skill is the rules each step follows.

## Settled — do not re-propose

- **Committing a reference.** Screenshots, recordings and wiki images of the game live in `~/Esposter/genshin-parity` (`PARITY_DIRECTORY`) and never enter the repository. Only `ParityReferenceMap` names them, by wiki title or by a recording in `captures` and the second to take (`capture`, `seconds`).
- **Asking the user to record what is published.** Text, wording, marks and screens come from a search first: the wiki (its API, `list=search&srnamespace=6` for files), the community data dumps for in-game text, and public videos, fetched with yt-dlp from a throwaway virtual environment in the scratchpad (`--download-sections` for the minutes needed) into `captures`. Record the game only for what nothing published shows, or ask the user for a picture when a search engine refuses a script (image search does).
- **Sending input to the game.** The tool launches and records the game; the user plays. Injected input is botting under its terms, with an anti-cheat driver watching.
- **Rendering a screen through Nuxt to check it.** A screen renders on the world package's parity page on plain Vite, up in about a second; a Nuxt build per check was the cost that sank the old screenshot suite.
- **A hand-kept list of screens.** A screen is on the page and in the suite by having a `<Name>.fixture.ts`.
- **Tracing below full resolution.** A trace starts from the source's full resolution, never reduced, and enlarges a small mark before tracing it.

## Rules

- **Numbers before looking.** Run `pnpm -C scripts genshin:parity compare <reference>` and read the mean and the grid; zoom only on a cell that stands out. Target a mean of hundredths of a percent, with any remainder explained (antialiasing along an edge).
- **A screen is a presentational component in its section: `packages/genshin-world/src/components/interface/<section>/<Screen>.vue`**, props in, events out, no store. There is one section per part of the game's interface: `splash`, `login`, `loading`, `menu`, `prompt`, `hud`, `dialogue`, `map`, `character`, `settings`. A piece two sections share (a menu tile, a capsule button) is in `interface/shared`. Its services and models mirror the path (`services/interface/<section>/`), and whatever every section reads, such as the element marks, sits at `services/interface/`. The component barrel exports each component under its bare file name wherever it sits, so no two screens may share one (`StartupLoading`, not `Startup`). The app wires the screen to its stores; `AgentConsole/Panel/Loading.vue` is the pattern.
- **Lay a screen out in the game's units.** The root is `container-type: size`, and everything inside is `calc(var(--unit) * n)` with `--unit: min(100cqh / 1080, 100cqw / 1920)`, the smaller of the two axes as the game fits its interface (height alone breaks any window narrower than 16:9), measured from a reference scaled to 1080 high (a 1440 reference's pixels times 0.75).
- **No element a host styles.** A screen is mounted inside the app's pages, whose element rules (the console's `h1`–`h6`, `b`, `strong`) reach through scoped styles; a heading is a `<p role="heading" aria-level>`, and `compare` on the parity page cannot catch a host's rule, so check the screen in its host once.
- **Styles are scoped `<style>` in the SFC** with the measured hex values, not UnoCSS or the app's tokens: a screen matches the game, not the design system. `@tsdown/css` bundles them into `genshin-world/style.css`, which the app loads in `configuration/css.ts`.
- **A glyph comes from the game's own mark by `trace`, preferring the wiki's standalone render** (`File:Element <Name>.svg`, 1600 units). A mark on a screenshot is small, and a pale one traces rough. Keep the region and trace check image, and read it before using the path. Paths live in a `…PathMap` service keyed by an enum (`ElementType`; never `Element`, which is the DOM's).
- **An order the game shows is its own array, never an enum's.** Lint sorts an enum's members alphabetically, so `Object.values(ElementType)` is not the game's order; `ElementTypes` lists it (Pyro, Hydro, Anemo, Electro, Dendro, Cryo, Geo).
- **A vector beats a trace.** Before tracing a logo, search Wikimedia Commons (`commons.wikimedia.org/w/api.php`, `list=search&srnamespace=6`) for its SVG, and use its paths and transforms as they are: the publisher's letters and ring silhouette come from `File:HoYoverse Logo.svg`. A trace of a raster chips wherever compression or printed detail meets an edge. Check a found SVG is the same lettering (Commons' `Genshin Impact wordmark.svg` is an older one without the star and arcs).
- **The tracer splits ink by distance from the paper**, the colour at the region's corners, so a coloured or lit mark needs no inverting, and it drops outlines smaller than a sliver of the region (`SPECK_SHARE`), which removes a logo's printed sparkles. A logo the game draws flat on a splash is traced from its coloured render with the ink share lowered (`trace … 1 0.25`), so sparkles on an edge stay ink instead of notching it, and filled flat.
- **A multi-colour mark is a silhouette filled by angle and by radius**: the shape as a CSS `mask` from its path, and its colours sampled in both dimensions from the mark's own field by `polar <image> <bands> <angles>`, each band a `conic-gradient` laid over the band inside it through a radial mask ramping between their radii, so the fill shifts from outside to inside as well as round it (angle alone was tried first and flattened the ring's lighter inner edge). Its glow is a blurred copy on a wrapper (a filter on the masked element blurs before the mask cuts). The publisher's ring is the pattern.
- **Find a mark's box from the pixels**, not by eye: the ink's column runs and extents along the row give each box, and equal boxes around each centre keep the marks aligned as the game draws them.
- **Motion: find, sample, then pause.** Sample a recording at 1 fps to find its events, then `frames <file> 30|60 <start> <seconds>` over each one (sharp for GIF and animated WebP, which the wiki serves and FFmpeg cannot decode; FFmpeg for video). `shoot <screen> <w> <h> entry <ms…>` holds the screen's own animations as it mounts; `props` (the default) lets those finish, then sets the fixture's `motionProps` and pauses on the transitions that setting starts. Stills and the visual suite show `props` alone. The page flushes style between the entry and the props, or the browser folds both into one style change and starts no transition. After a new import, the first load of the page reloads while Vite optimises it; shoot again. Compare with `luma` over the same region of both; it takes a frames folder too, since a second at 60 frames outruns Windows' command line. A sequence of screens runs as one Web Animations timeline per screen (fades and holds as keyframe offsets, each segment's easing on its keyframe), so a held shot at any moment shows that moment; its fixture is `isMotionOnly`, since the visual suite's screenshot finishes animations. Measured timings live in the section's `constants.ts`, with how they were measured. A recording's colours read true only because `RECORD_ENCODING` converts to labelled limited-range YUV before AMF, which otherwise labels its own limited range as full and squeezes every value (white as 234); keep that conversion, and still take exact colours from a lossless still or the wiki's PNG. `session-2.mp4` predates it and was relabelled limited range in place (`h264_metadata=video_full_range_flag=0`); its white still reads 253, so a comparison against it has a floor of about 0.4%.
- **Record the game's window only**, with `record <name> <seconds>` armed before the user starts the game: Windows Graphics Capture by executable, GPU-encoded, Matroska. Never capture a screen rectangle, which takes the desktop, the webcam and any overlay whenever the game is not in front.
- **FFmpeg is the pinned release the tool fetches** (`FFMPEG_ARCHIVE_URL` and its SHA-256, into `FFMPEG_DIRECTORY`). To move it, bump the version and checksum together; never add an npm FFmpeg (none bundles 8 or later, which window capture needs).
- **No reference, no approval.** A screen's size, colour and place are measured from a reference in its own language and build, never carried over from another client's or guessed; a value with no reference is not shipped. `ParityReferenceMap.test.ts` fails for any fixture (not `isMotionOnly`) no reference names, so a screen that was never compared cannot reach the suite. A public video that letterboxes the game (a phone, a window) is cropped to the game's screen with the reference's `crop`, and scored over a `region` clear of watermarks; its edges are the video's softness, so a clean score there is an outline of about a percent.
- **Text is the game's face, or the open face nearest it.** The game sets everything in HYWenHei 85W, a commercial face nothing may ship, so `GAME_FONT_FAMILY` names it first for a reader who has it, then Signika. Signika was chosen by setting the game's own lines (a large French notice frame) in each of seventy open candidates, scaling each line to the game's ink box, and scoring the overlap of its binarised ink with the game's (the width of the same words at the same height is a second score): Signika SemiBold overlapped most, where Asap, picked first on width alone, and a serif like Lora, suggested by a sharpened 12px heading, both lost. Score both sides binarised, since the game's text is grey and a candidate's black, and read a heading's shape from a large frame, never a small sharpened picture. Pick a replacement the same way, never by eye alone. A text screen's remaining difference against the game is the face's.
- **Approve with the visual suite once `compare` is clean.** `pnpm -C packages/genshin-world test:visual --run -u`, then commit the image, which is kept in the section's `__screenshots__`, with the screen. A new screen fails on its first run, the one that writes the image.
- **The parity page is `pnpm -C packages/genshin-world parity`, on port 3002, and the tool `pnpm -C scripts genshin:parity`, run through `tsx` for its enums**, started in the background before `compare` or `shoot`.
