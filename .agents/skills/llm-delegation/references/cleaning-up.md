# Cleaning Up a Batch

Read when a batch is done and its worktrees or branches are left to remove: the removal command, what it refuses, and which branches are yours to delete.

A batch leaves nothing to sweep but the branches and worktrees an older batch made. Remove a worktree with `pnpm ai:worktree:remove <path>`, never `git worktree remove` by hand: that deletes through any junction into the main checkout's `node_modules` (it empties the root install), so the command unlinks the junctions first, then removes the worktree, prunes it and deletes its branch once the branch has landed. Git still refuses a dirty worktree, which is the signal to look before deleting; a branch left with no worktree takes `git branch -d`. On Windows a hand removal stops part way twice over: a `node_modules` nests past the 260-character path limit, and a native binary another checkout's process has loaded refuses deletion through every one of its pnpm store links, though it can be moved. The command handles both. A removal that stopped part way leaves a folder git no longer lists, which `pnpm ai:resume` names, and the same command deletes it. Use `-d`, never `-D` by hand: the refusal to delete an unmerged branch is the only thing standing between a stale worktree and lost work. A rebased branch whose commits reached `origin/ai/queue` by patch has a tip that origin does not hold, so `-d` refuses it and the command leaves it. `git cherry origin/ai/queue <branch>` printing only `-` lines is the evidence that its work landed; on that evidence alone an `agent/*` branch may be deleted by hand with `-D`, and the batch's report names each one. The one `-D` is the command's own, for a branch whose tip `origin/ai/queue` already holds, which has landed whatever `-d` makes of it. **Only branches you created for an agent are yours to sweep.** A branch with a name someone chose deliberately (not the `agent/*` or `worktree-agent-*` pattern) is presumed long-lived: leave it and ask, even when asked to "clean up old branches".
