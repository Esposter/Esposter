# Dist Size

Read when a size test fails after a manifest, `deps` entry, config factory or bundled package's export change, or when a size ceiling's number is in question.

Every package with a tsdown configuration has a size test in `src/index.test.ts`: a bundle ceiling on its built entry, `dist/index.js` for most, and a types ceiling on `dist/index.d.ts`, plus one on the declaration file of each further entry its test names (agent-console-server's `contracts.d.ts`). A private package emits none, so it has only the bundle ceiling. A package with no build, a Claude Code plugin, has no bundle to measure. Each test holds its file to a ceiling written in the test, and `testing`'s `references/bundle-size.md` says how the test is written. After changing a manifest, a `deps` entry or a config factory, rebuild and run those: a file that grows past its ceiling means something started being bundled that should not have been, so the reading is taken before the number is touched.

**Adding an export to a bundled package grows every bundle downstream of it, and some of those live outside `packages/`.** `apps/functions` and `apps/infra` carry the same size test, and `apps/functions` inlines `@esposter/db-schema` — so a values array added to one enum there grows a bundle by a few dozen bytes, which a ceiling reports only once growth crosses it, in a suite `pnpm test:packages` never runs, because that script is `--project "packages/*"`. The gate for a change to a bundled package's export surface is `vp run build:packages && pnpm -C apps/functions build && pnpm -C apps/infra build`, then the `src/index.test.ts` of every package plus those two apps — not `test:packages` alone.

The two apps' size tests run from the repo root as `pnpm -C apps/functions test src/index.test.ts --run` and `pnpm -C apps/infra test src/index.test.ts --run`. A ceiling is raised by the change that outgrows it, after a fresh build reads the real size, and never to absorb a jump: a growth the change does not explain is read before the number is touched. A number a failure printed from a stale `dist/` is never written into a ceiling, since the build that would show the real size has not run. The raise is the number being edited in the test, and the path argument is what keeps each run to its one file, as it does for the packages.

A size claim is measured, not inferred: a manifest or dependency edit is called size-neutral only once a build has read `dist/index.js` before and after it. A reason offered for why an edit cannot move a bundle is a claim for that build to check, not a reason to skip it.

A ceiling fails only growth, so it never sees a shrink, and a collapse of ambient declarations is one (`references/declarations.md`).
