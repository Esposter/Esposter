# Game version update

Read when the installed game's version changes, and the outputs stamped with the old version are made again for the new one.

The rules are the requirement `openspec/changes/genshin-pipeline-provenance/specs/genshin/pipeline-provenance/spec.md` names; this page is the order they run in. Every command below runs from the repository root, and a stamped command is regenerated by that command, never by editing its stamp.

## The order

1. **Update the install.** The launcher writes the new `game_version` into `config.ini` beside `GenshinImpact_Data`, which every stamp reads. A hand-copied install must carry that file too.
2. **`pnpm -C scripts genshin:version status`.** It prints the install's version, one row per command that wrote a stale output (the command, how many of its outputs are stale, and the game version they name), the hosted lock's recorded version and the decoder constants' pin. It writes nothing. It exits 1 while any row is stale, which is the state an update starts in, so that exit is not a failure here. `not recorded` and `not pinned` are printed values, not gates: the lock records no game version and the decoder constants are pinned to none.
3. **`pnpm -C scripts genshin:version plan`.** It prints each stale command once, under its kind, in the order the update runs them: Extractions, Map, Fits, Publishes. A command under `Commands no kind lists` is in no kind yet, so add its kind to `scripts/src/services/gameVersion/constants.ts` before running it.
4. **Run the planned commands in the plan's order.** A stamped command is its verb with the same arguments, under the script it belongs to:
   - `extract`, `clips`, `interface`, `shaders`, `inventory`, `playlist`, `avatar`, `scene-scripts` and `witness` run as `pnpm -C scripts genshin:assets <command>`, with the game closed.
   - `genshin:text fetch` and `genshin:text decode` run as `pnpm -C scripts genshin:text <verb>`. Their stamped command already carries the script's name.
   - `map` runs as `pnpm -C scripts genshin:assets map`, with the game closed. It remakes a map whose stamp names another version, so no map is deleted by hand. `city-areas` runs as `pnpm -C scripts genshin:assets city-areas`.
   - Each `record <path>` line is regenerated by the fit that publishes that record. Run `pnpm -C scripts genshin:assets fit <component>` once per component, not once per record. A fit publishes its records as it runs, so the publish is part of this step. A fit that reads an export the install must make first runs only when named with `--only`, so a record still listed by the next status needs its named run.
5. **Run the Publishes heading** when the plan has one, as the command it names.
6. **`pnpm -C scripts genshin:version status`** again. It lists nothing and exits 0 once every planned command has run.
7. **`pnpm -C scripts genshin:data verify`.** It follows the publish, and must pass on both accounts.
8. **Commit the lock**, `packages/genshin-world/src/generated/gameDataLock.json`, by its path, with any `gameDataKeys.ts` the publish rewrote.

## Copying from a peer

A machine on an older game version updates its game before it copies from a peer. `pnpm ai:fleet:data` refuses every path a peer's stamp of another version covers, so an older install copies nothing from a newer peer until its own install matches.
