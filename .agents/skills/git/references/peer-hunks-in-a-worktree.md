# Building a commit in a throwaway worktree

Read when a hunk of a file a peer also has dirty is committed, or a commit is built in a throwaway worktree rather than the checkout.

- **Committing only your hunks of a file a peer also has dirty.** A pathspec commit takes the whole working file, peer's hunks included. So build the commit in a throwaway detached worktree cut from the branch head, with your hunks applied there, and record that head. Then move the branch with a compare-and-swap, `git update-ref refs/heads/ai/queue <new> <recorded head>`: it refuses if anyone committed meanwhile, where a plain `update-ref` or `reset` silently drops their commit. Last, run `git restore --staged <file>` in the checkout, so its index matches the new head and no reversal of your hunk sits staged for the next plain commit.

- **A throwaway worktree has no `node_modules` of its own, so its pre-commit format runs on the main checkout's tools.** The hook borrows the main checkout's `oxfmt` and config when the worktree has none (`.githooks/pre-commit`), so a `git commit` there formats; it names the config by its physical path, since through a symlinked folder (as on macOS) the config's ignore patterns match nothing and a `*.snapshot.*` file comes out formatted; a commit that skips the hook keeps the files as they were written. Format the files first with the checkout's own `node_modules/.bin/oxfmt`, then copy them in. A compare-and-swap that refuses leaves its commit dangling: rebuild on the new head rather than moving the branch by hand, and check the commit's stat for a blank line where a row belongs, since a `grep` feeding the row can come back empty while a peer rewrites the file.
