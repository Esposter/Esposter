# The `scripts/` layout

Read when adding a command, a sub-command or a plugin under the repo-root `scripts/`, or deciding where one of its services or types lives.

**`scripts/` is laid out by layer like the app, keyed by command** — `src/<command>/index.ts` is the entrypoint a pnpm script names (an oxlint plugin is `src/oxlint/<plugin>.ts`, the path `oxlint.config.ts` loads), and everything it runs lives under `src/services/<command>/` (its `constants.ts` included) with its types under `src/models/<command>/`. A sub-command (`coderabbit/<verb>`, `sweeps/<scan>`) nests one level deeper in each; what two verbs share sits at their command's root in the layer. The entrypoint folder holds nothing but the entrypoint and the platform scripts it dispatches to.

**A tool of dozens of verbs groups them by the domain they work in instead** — a folder a verb would have to itself is a file or two, and a flat root past what a pass reads is the problem the split exists to solve. `genshinParity` and `genshinAssets` each hold a `commands/` folder of their verbs, one folder per domain (`music`, `sky`, `witness`, `fit`, `scene`…) in each layer, and a `shared/` beside them for what several domains reach, the layer's root holding folders alone as `references/layer-placement.md` has it. A file lives in the one domain whose verbs import it, found by following each verb's imports, so a move between domains is read off the import graph rather than argued.
