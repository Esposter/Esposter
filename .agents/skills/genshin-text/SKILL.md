# Genshin Text

How it works, from the dump to a lookup, is `apps/web/content/docs/genshin/game-text.md`; this skill is the rules a change that shows the game's words follows.

## Settled — do not re-propose

- **Translating a string the game already says, or an i18n library for it.** The game ships its own translation in fifteen languages; a consumer's own words go in its own typed module — the persona's are `apps/web/content/docs/infra/claude-interface/persona-plugin.md`'s, which also records why a keyed library lost to a typed function per string.
- **Shipping a whole text map, or loading one at run time.** It runs to tens of megabytes per language, and neither a browser nor a stranger's plugin install has the dump; the referenced subset is the only shippable shape.
- **`genshin-text` as a dependency of the persona plugin.** The plugin's frozen npm lockfile would disagree with every release that moves the range; the modules it runs are a generated copy (`apps/web/content/docs/infra/claude-interface/persona-plugin.md`).
- **A `t(key)` function over the lookup.** The lookup is indexing a loaded chunk, `gameText[GameTextKey.X]`, and syntax is never wrapped (the `over-engineering` skill, `references/syntax-extraction.md`).

## Rules

- **A word the game says is `gameText[GameTextKey.X]`, never a literal** — search the text map with `find` before deciding the game does not say it: nearly all of what the opening shows before the client loads is there, some of it worded per platform or per gender. What the account kit shows as the player signs in is in the kit's own strings, which `write` reads beside the text map by the kit's key.
- **A label only a screen reader says is a word too**: an `aria-label` and a glyph button's `label` are read from the game text like any drawn word, so a reader hears their own language; a brand's name or a number stays as it is.
- **A screen that shows a word takes `gameText` as a required prop** from the host that resolved the language, never by injection and never with English as a default, so a host that forgets it fails to compile; a fixture passes `ENGLISH_GAME_TEXT`. A `genshin-interface` piece has no `genshin-text` dependency, so it takes its words already resolved, as labels, coloured runs (`TextSegment`) or a slot, from the `genshin-world` screen around it that holds `gameText`.
- **A string's colour tags are split by `splitGameTextColors`**, never stripped or matched by hand: `write` keeps them in every chunk (`getInterfaceGameText`), each run keeps the CSS colour its `<color=#RRGGBBAA>` tag gives it, and a screen draws a run as a `span` with that colour.
- **A string's numbered values (`{0}`, `{1}`) are filled by `fillGameTextValues(text, ...values)`**, never a chain of `.replace` calls: it fills every number at once and takes a value holding a replacement pattern (`$&`) as it is.
- **A key's value is the game's own id** — the manual text map's name for an interface string, else the raw hash — found with `pnpm -C scripts genshin:text find "<pattern>"`, or by the screen's shared manual-id prefix with `find --id "^UI_FORGE_PAGE_"` when its words (Start, Materials) are too common to search for and written with `pnpm -C scripts genshin:text write`; a key is one line in `packages/genshin-text/src/models/GameTextKey.ts` and nothing else lists it. `write` reads the enum through the package's `dist`, so `pnpm -C packages/genshin-text exec tsdown --no-clean` runs first, or the new key is silently left out of every chunk. An attribute's name is filed under its own `FIGHT_PROP_*` id, the value `genshin-world`'s `Attribute` already takes, so `find` lists it first among the matches of its English. A manual-map label whose hash the English text map lacks (the combine types' `COMBINE_TYPE_NAME6` and `COMBINE_TYPE_NAME12`) is missing from `find`, and its English is read from `TextMap/TextMap_MediumEN.json` under the manual map's hash.
- **`write` and `quests` read their inventory through each package's built `dist`**, since `tsx` resolves no `source` condition: a new `GameTextKey` or `QuestId` is built first (`pnpm exec tsdown --no-clean` in its package), or the run writes the inventory as it last built.
- **A quest's words are the world's, never a `GameTextKey`**: `genshin:text quests` publishes every word a carried quest and its talks show as one record a language under `questText`, by the same text ids, and a host hands a talk or the quest screen the record of its language as its `textMap` (`apps/web/content/docs/genshin/quests.md`).
- **An achievement's title, description and category name are the world's too**: `genshin:assets achievements` publishes them as one record a language under `achievementText`, by their text ids, and `AchievementTextLoaderMap` fetches one language by its key (`apps/web/content/docs/genshin/achievements.md`).
- **An Archive entry's name is the world's too**: `genshin:assets archive` publishes every entry's name as one record a language under `archiveText` by its text id, through the same `buildTextChunks` as the achievements (`apps/web/content/docs/genshin/archive.md`).
- **A book's body is read from `Readable/`, not a text map**: the body's text is not in `TextMap`, so `genshin:assets archive` reads it from the dump's `Readable/<code>/` folder, named by the localization row its document's quest text id points at, and publishes it to the hosted game data as one index per language, `bookBody/<language>`, keyed by body id, which `readGameDataEntry` reads when a volume opens (`apps/web/content/docs/genshin/hosted-game-data.md`). The folder is fetched into the dump by `genshin:text fetch` beside the tables, never committed (`apps/web/content/docs/genshin/archive.md`).
- **A table the dump lacks is fetched, never committed**: a table a reader names that is absent from `ExcelBinOutput/` is downloaded from `DimbreathBot/AnimeGameData`'s `ExcelBinOutput/` (the `main` branch, `raw.githubusercontent.com`, each directory listed whole through the Git Trees API) by `genshin:text fetch`, which also keeps each file the dump holds at its size, into the dump beside the others, outside the repository. The readers only read the dump.
- **The card game's names and descriptions are the world's too**: `genshin:text gcg` publishes the card game's words as one record per language, as `apps/web/content/docs/genshin/game-text.md` sets out, and `GcgTextLoaderMap` fetches one language by its key (`apps/web/content/docs/genshin/genius-invokation.md`).
- **A character's, a weapon's, an enemy kind's or a recipe's name is the world's, never a `GameTextKey`**: the stat tables, the enemy kinds and the recipes (cooking, processing and crafting) carry each one's `nameTextId`, `genshin:text names` publishes every name they cite as one record a language under `nameText`, after `genshin:assets stats`, `enemies`, `crafting` and `cooking`, and a screen reads it through `NameTextLoaderMap`, one language fetched by its key (`apps/web/content/docs/proposals/genshin/wish.md`). A monster's name is filed under its description, not its row.
- **An item's name is its `nameTextId` through the name records; a `GameTextKey` is a string the code names.** `genshin:assets items` publishes each material's `nameTextId` and `genshin:text names` publishes every such name into the same records. The names builder collects every published record's and every data file's `nameTextId`s; a new item source needs no edit there.
- **`src/generated/` is the writer's alone, in both packages.** Its output is never formatted (`oxfmt.config.ts` ignores `**/generated/**`), and `scripts/src/services/genshinText/getPersonaModuleSource.test.ts` fails the day the persona's copy and its source disagree, so a change to a copied module is followed by a `write`.
- **A module the persona copies imports only from its own package**, since the copy re-aims `#src/` and the plugin's install carries nothing else; `matchGameLanguage` stays out of `PersonaCopiedModules` for that reason (`scripts/src/services/genshinText/constants.ts`).
- **A reader's language comes from `matchGameLanguage`, and a language's tag from `GameLanguageTagMap`** — never a locale table of a consumer's own.
- **A language is never a location.** Nothing but text is chosen by the reader's language: whether a third party works for them is asked of their network, never guessed from the language they read.
- **A persona string the game already says comes from the game text**, and a localization module holds only phrasing the game never says.
