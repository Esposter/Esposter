# Code Without `@esposter/shared`

Read when handling a rejection in code that cannot import `@esposter/shared` — a package a stranger's `npm ci` installs alone, or a configuration file loaded before any workspace package is built.

- **A package installed alone** — the shipped `genshin-persona` plugin, installed by a stranger's `npm ci` — reads a rejection as `const [outcome] = await Promise.allSettled([promise])` and terminates at the process boundary: a hook's `registerQuietExit`, the synthesizer's log-and-exit, a verb's stderr and exit code. The skill's rules still hold there — the boundary handler writes what was lost (stderr, or the plugin's own log) before it exits, and a fallback taken on a rejection says why first.
- **A file loaded before the packages build** — the Nuxt configuration `nuxt prepare` reads from `postinstall` — reads a rejection the same `Promise.allSettled` way, with `Promise.try` around a call that may throw synchronously, since the app does not depend on neverthrow itself: the dev upgrade forwarder in `apps/web/configuration/hooks.ts` logs the reason and closes the socket. The helpers in `@esposter/shared` stay the only code that calls neverthrow's primitives.
- **A web worker that cannot load `@esposter/shared`** — the terrain tile worker, whose `now` reads `process.hrtime` as the dev server loads it — takes the same route: `Promise.allSettled([Promise.try(build)])` around each build, a rejection logged with `console.error` and answered with the item's key, so the requester releases the item instead of waiting on it. Its message handler, `handleMessage`, is `async` for this, and a queue drained after the ground loads is answered with `Promise.all`, which keeps the posts in the order they were asked for.
