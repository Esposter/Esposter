# Bundle Size Ceilings

Read when a package's size test fails, or a new library package needs its size test.

Every library package under `packages/` with a build has `src/index.test.ts` asserting a bundle ceiling on its built entry (`dist/index.js` for most) and a types ceiling on `dist/index.d.ts` (on each entry's declaration file where the package has no index entry). A private package emits no declarations, so it has only the bundle ceiling. Each reads the built file's size and holds it to a number written in the test, in KiB. **Copy the file from any sibling package** rather than writing it from scratch. When a ceiling is raised is the `build` skill's rule (`references/dist-size.md`).

- **Workflow**: copy a sibling's file, then `pnpm build` (the test reads the compiled `dist/`) and run it, so the number is written against the size the build actually shows. A ceiling is a count of KiB times `KIBIBYTE` (or `KIBIBYTE` itself for one), at or above that size.
- **Several packages at once** (a change rippled through `dist/` and the size tests fail): from the repo root, `vp run build:packages` then `pnpm test:packages -t "size" index.test.ts` — one rebuild of every library package, then only the size tests. Rebuilding first is not optional: without it the tests read the stale `dist/`, and a ceiling is never raised to a number a failure printed from it (`build`'s `references/dist-size.md` says when one is raised).
- **The `index.test.ts` argument is not optional either — it is what stops a size run from running the suite.** `-t "size"` selects which _tests_ execute, never which _files_ load: without a path argument vitest collects, transforms and imports every test file in every library package to run the handful of assertions these files hold, which is minutes of work for the seconds they actually take. The path argument is a substring match on the file path, so it keeps one `src/index.test.ts` per package — every package still checked — and drops everything else. Regressing the rest is CI's job, and it shards it.
- **New library package**: add a `test` script (`"test": "vitest"`) and a `@types/node` devDep; `vitest` comes from the root toolchain. Never add `@vitest/coverage-v8` per-package — coverage runs only from the repo root, so the provider lives in the root `package.json` alone.
- **One ceiling covers every OS.** Module order is why a build's bytes can differ by platform: the minifier hands out two-character identifiers in module order, and the declaration bundle concatenates declarations in it. An equality snapshot had to be split per platform for that. A ceiling is not compared for equality, so its one number only has to sit at or above the larger of the two builds, and no per-platform pair is written.
- **Narrow it by file, never by package.** The pair's whole value is that it covers every library package, so the
  one whose `dist/` a change rippled into cannot be the one left out. A variant narrowed by package — skipping the
  slow one, listing the ones that "obviously" moved — reports green over the package it dropped, and the drift
  surfaces on someone else's run instead. Adding or deleting a source file is enough to move a bundle, so the
  package that needs checking is rarely the one the change is about. Narrowing to `index.test.ts` costs no
  coverage for the same reason: every package's size test is named that, so none of them is the one left out.
