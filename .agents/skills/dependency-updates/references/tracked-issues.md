# Tracked Issues

Read when bumping `tsrs`, `vitest` or `@vitest/coverage-v8` — each has something to watch.

- **`tsrs`** — the typecheck and the type-aware lint backend (`tsrs-lint`, which vite-plus launches). The catalog names its `next` dist-tag rather than a range, because vite-plus 1.7 runs `tsrs-lint` from the tag that is ahead of `latest`; the catalog entry's `@TODO` names the release that lets the range come back. So a bump is a `pnpm refresh:lockfile`, as `references/dist-tag-aliases.md` describes for a tag. Two things to watch on a bump: the switches `oxlint.config.ts` sets for the backend (`TSRS_LINT_RUN_EXTERNAL_CODE` and "TSRS_FAST") carry a `@TODO` on [vite-plus 3476](https://github.com/voidzero-dev/vite-plus/issues/3476), which retires them; and the hang the `oxlint` skill's `references/ignore-patterns.md` describes is the one a new backend could bring back, so a bump is the time to recheck it.
- **`vitest`, `@vitest/coverage-v8`** — Renovate's vitest monorepo group moves them as the pair they are (`@vitest/coverage-v8` peers vitest at the exact version). A major also waits on `@nuxt/test-utils` peering the new line — it widens its `vitest` peer one major at a time, and the next major needs the same; no rule encodes that, because the peer conflict fails the install in the branch and a major is never automerged.
