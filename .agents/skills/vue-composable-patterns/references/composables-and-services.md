# Composables and services

Read when a function is about to be written in `composables/` or `services/`, when one is called outside component setup, or when a listener, timer or piece of state is kept in two places. `SKILL.md` has the one-line rule; this page is its reasoning and where it stops.

A composable is a function that needs a component's setup: it owns reactive state across calls, registers something a scope tears down, or reads what only setup can give it (`inject`, the route, another composable). A function with none of those is a **service**: it lives in `services/`, is named for what it does and takes no `use`. The prefix is a claim about where the function may be called, and a false one sends the next reader looking for a scope that is not there.

- **A composable called from a service, a store action or a callback is a service.** The skill already says a composable is called at setup, never inside a callback (`references/resource-cleanup.md`); a function every caller breaks that for was never one. Reading a store is not setup context, since a store is looked up where it is used, so a closure over `useAlertStore()` is a service that looks it up when it runs. The find is `rg "\buse[A-Z]\w*\(" apps/web/app/services` less the store, router and runtime-config lookups.
- **A listener, timer or observer that a component's life ends is a composable**, built on the VueUse primitive that tears it down (`useEventListener`, `useResizeObserver`, `tryOnScopeDispose`), never a service holding a raw `addEventListener` and a stop it returns. A raw one stays where a composable cannot be: a worker, the service worker, server code, the framework-free packages, a one-shot listener inside a promise that settles it, a dispatcher that is not the DOM, and a listener ended by a signal its caller owns (the `vue` skill's `references/inline-handlers.md` names each). A function that registers its own listener and ends it itself, such as one that swallows a single click, is a service either way.
- **Two places keeping the same state transitions are one composable.** The press that becomes a drag was tracked separately by the page builder, the survey palette and the whiteboard palette, each with its own touch rest and Escape; one `usePressDrag` owns it and each editor brings only what differs. The test is the transitions, not the spelling: two composables that each hold an `isDisposed` flag set on scope disposal repeat a line, not a behaviour, and the flag is not extracted (`earning-a-composable.md`).
- **A name another skill settles stays.** The Tiptap `use*Extension` factories are composables by the `tiptap` skill, and the dungeons `use*` hooks run inside a Phaser scene's `onCreate` scope, which is the setup context there (`vue-phaserjs` skill).
