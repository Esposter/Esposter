# A Pull That Stops on a Conflict

Read when `git pull --rebase` on `ai/queue` stops on a conflict. The loop is in `SKILL.md`; this page is how each conflict is settled.

A pull that stops on a conflict is resolved in the rebase, one commit at a time. A commit whose author date and subject are already in `git log --format='%aI %s' <merge-base>..origin/ai/queue` is one the collector ported and re-resolved, so the remote's copy is the right one: `git rebase --skip`. Match `git log -1 --format='%aI %s' REBASE_HEAD` whole: a port keeps the author date to the second, so the pair names one commit, where a subject alone (`chore: format`), or a subject and its files, can belong to another session's commit. Any other conflict is the session's own commit meeting the remote's changes, so both are kept, merged by hand, then `git add` and `git rebase --continue`. **Neither side is ever taken whole** — `git checkout --ours` or `--theirs` over a conflicted file drops every change the other side made, conflicting hunk or not. Read what each side changed against the merge base (`git diff REBASE_HEAD~1 REBASE_HEAD -- <file>` for the replayed commit, `git log -p <merge-base>..origin/ai/queue -- <file>` for the remote) and keep the substance of both: where one side's design replaces the other's, whatever the replaced side fixed is carried into the new design rather than dropped with it. Afterwards, `git diff origin/ai/queue --stat` should show only the session's unported commits.
