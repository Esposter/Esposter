# A Pull That Stops on a Conflict

Read when `git pull --rebase` on `ai/queue` stops on a conflict, or replays commits that are not the agent's. The loop is in `SKILL.md`; this page is what the pull replays and how each conflict is settled.

On a branch, `git pull --rebase` replays only the agent's commits never yet on `origin/ai/queue`: it rebases from the branch's fork point, read off the reflog of `origin/ai/queue` that every worktree shares (`apps/web/content/docs/infra/review-collector/two-writers.md`), so a commit the agent has landed is never replayed, however the collector's rewrite has since changed it. Every conflict is one of the agent's own commits meeting what the queue gained since: another agent's commit, or a resolution of the collector's.

A detached worktree has no fork point, since git computes one only for a checked-out branch. Its pull replays every commit of the rewritten queue that its `HEAD` reaches, skips by patch-id the ones the rewrite left unchanged, and stops on each one the collector's resolution changed, a conflict in a commit that is not the agent's. `git rebase --abort`, then `git switch -c <name>` once, puts the worktree on a branch; the reflog already holds its base, so the next pull replays only the agent's own commits.

The agent that made a commit settles its conflict in its own `git pull --rebase`, one commit at a time, by these rules. When the queue already carries the commit's change, such as a held commit the collector re-landed while the session re-landed it too, `git rebase --skip` keeps the remote's copy; otherwise both sides are kept, merged by hand, then `git add` and `git rebase --continue`. **Neither side is ever taken whole** — `git checkout --ours` or `--theirs` over a conflicted file drops every change the other side made, conflicting hunk or not. Read what each side changed against the merge base (`git diff REBASE_HEAD~1 REBASE_HEAD -- <file>` for the replayed commit, `git log -p <merge-base>..origin/ai/queue -- <file>` for the remote) and keep the substance of both: where one side's design replaces the other's, whatever the replaced side fixed is carried into the new design rather than dropped with it. Afterwards, `git diff origin/ai/queue --stat` should show only the session's unlanded commits.
