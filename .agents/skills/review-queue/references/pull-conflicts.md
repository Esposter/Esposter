# A Pull That Stops on a Conflict

Read when `git pull --rebase origin ai/queue` stops on a conflict, or replays commits that are not the agent's. The loop is in `SKILL.md`; this page is what the pull replays and how each conflict is settled.

On a branch, `git pull --rebase` replays only the agent's commits never yet on `origin/ai/queue`: it rebases from the branch's fork point, read off the reflog of `origin/ai/queue` that every worktree shares. Nothing rewrites the queue, so a commit the agent has landed is never replayed. Every conflict is therefore one of the agent's own commits meeting what the queue gained since: another session's commit, or Renovate's.

A worktree is created on a branch (`git worktree add -b`), never detached. A detached worktree has no fork point, so its pull replays every commit the queue holds that its `HEAD` reaches. If one was made detached, `git rebase --abort`, then `git switch -c <name>` once, puts it on a branch; the reflog already holds its base, so the next pull replays only the agent's own commits.

The agent that made a commit settles its conflict in its own `git pull --rebase`, one commit at a time. When the queue already carries the commit's change, `git rebase --skip` keeps the remote's copy. Otherwise both sides are kept, merged by hand, then `git add` and `git rebase --continue`. **Neither side is ever taken whole** — `git checkout --ours` or `--theirs` over a conflicted file drops every change the other side made, conflicting hunk or not. Read what each side changed against the merge base (`git diff REBASE_HEAD~1 REBASE_HEAD -- <file>` for the replayed commit, `git log -p <merge-base>..origin/ai/queue -- <file>` for the remote) and keep the substance of both: where one side's design replaces the other's, whatever the replaced side fixed is carried into the new design rather than dropped with it. Afterwards, `git diff origin/ai/queue --stat` should show only the session's unlanded commits.
