# A Held Commit or a Failed Fix Replay

Read when the collector's run fails red naming a held commit, a queue commit carries the collector's held comment, the red names `ai/review-fixes`, a window the bot skipped again after it was asked, or an issue lists a window's deferred findings.

**When the collector's run fails red naming a held commit, or a queue commit carries the collector's held comment** — the queue's first owed commit failed its reshaping or its conflict resolution past the attempt cap (the commit's own comments say which) — the queue is the session's to repair, and every run stays red until it is. The comment lands first. A commit the reshaper could not split is split by hand under the cap, the parts that need no review trailered `Express:`. The same red naming `ai/review-fixes` — a fix whose replay onto `develop` failed past the cap — is the one time the session writes that branch: rebase it onto `origin/develop` commit by commit, keeping every fix's message and trailers, prove the fixed files unchanged with `git diff <old head> -- <their paths>`, and push with a lease naming the sha it read. A conflict past the cap is the one hand rebase the Settled list allows: `git pull --rebase` first, then `git rebase origin/ai/review-fixes` — the fixes lead the next window, and the porter reads what the queue owes against the tree they built — resolved commit by commit, and pushed with a lease naming the sha the pull brought (`--force-with-lease=refs/heads/ai/queue:<that sha>`), never bare. Every count names the collector's own services (`COLLECTOR_SOURCE_PATH`) as its basis, so a held commit whose failures a collector fix has since answered needs no hand: pushing a fix to those services to the queue is the fresh turn, and the next run retries it (`apps/web/content/docs/infra/review-collector/runner.md`).

**When the red names a window still skipped after the collector's one ask for its review** — the run's error says "the bot skipped its review again after it was asked" — the CodeRabbit plan or its billing is refusing it: a file limit under the cap the collector cuts to, or usage credits run out. Fix the plan or the billing first, then comment `@coderabbitai review` on that window; the bot's reply fires the cycle, which merges the window once its review completes. The collector never asks twice on its own, since a second ask before the fix is skipped the same way.

**When an issue lists a window's deferred findings** — the drain failed past the cap, so each open finding got a `Deferred after <n> attempts` reply and the walk went on — nothing waits on it, and the findings are the session's to answer like any other: fix each in a commit carrying `Answers: <comment id>` (`Drains: <review id>` for the body's), reject the rest by reply with the evidence, push, and close the issue once every finding it lists is answered (`references/answering-findings.md`). The cause the issue quotes says whether the collector failed rather than the findings: a collector fault is answered by fixing the collector's services on `ai/queue`, which every later drain runs on.
