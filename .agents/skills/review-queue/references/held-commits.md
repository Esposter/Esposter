# A Held Commit or a Failed Fix Replay

Read when the collector's run fails red naming a held commit, a queue commit carries the collector's held comment, or the red names `ai/review-fixes`.

**When the collector's run fails red naming a held commit, or a queue commit carries the collector's held comment** — the queue's first owed commit failed its reshaping or its conflict resolution past the attempt cap (the commit's own comments say which) — the queue is the session's to repair, and every run stays red until it is. The comment lands first: under a rate limit the run exits idle rather than red. A commit the reshaper could not split is split by hand under the cap, the parts that need no review trailered `Express:`. The same red naming `ai/review-fixes` — a fix whose replay onto `develop` failed past the cap — is the one time the session writes that branch: rebase it onto `origin/develop` commit by commit, keeping every fix's message and trailers, prove the fixed files unchanged with `git diff <old head> -- <their paths>`, and push with a lease naming the sha it read. A conflict past the cap is the one hand rebase the Settled list allows: `git pull --rebase` first, then `git rebase origin/ai/review-fixes` — the fixes lead the next window, and the porter reads what the queue owes against the tree they built — resolved commit by commit, and pushed with a lease naming the sha the pull brought (`--force-with-lease=refs/heads/ai/queue:<that sha>`), never bare. Every count names the collector's own source as its basis, so a held commit whose failures a collector fix has since answered needs no hand: pushing the fix to the queue is the fresh turn, and the next run retries it (`apps/web/content/docs/infra/review-collector/runner.md`).
