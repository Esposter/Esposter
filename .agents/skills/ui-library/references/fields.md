# Fields

Read when adding a search, a text field or a form. `SKILL.md` has the one-line rules; the reasons are here.

- **A search is `UiTextField` with the search type**: a pill with a search mark, its label as the hint inside it and still its accessible name, and its own clear button once it holds text, so a feature never draws one beside it. A surface rule draws and never lays out: `ui-field` carries no padding, which the call site gives. A field is a step off the surface it sits in — `--ui-field-background`, one translucent layer of the text colour that no surface overrides — never an accent tint at rest, which reads as a highlight, and draws no ring and no shade at rest: `ui-field` rings and tints it while focused, and tints it while invalid, so a feature adds neither. The UnoCSS preset's preflight already strips the native inset border of `input`, `textarea` and `select`, so a feature never adds `b-none` to an input.

- **A control that asks for focus says `is-autofocus`**; how the one prop runs for a dialog and for a page, and what it leaves alone, is `openspec/specs/architecture/ui-library/design.md`. An element a component owns that has no `is-autofocus` calls `useAutofocus(() => element, () => isWanted)`, never `element.focus()` in `onMounted`, which `restrictedFocusSyntaxes.js` bans in the Nuxt app's components and composables (a focus after an action, as a move or a close, is the keyboard following the reader and stays), and an editor takes `focus-position` rather than its own option. A skipped ask logs nothing. The Genshin packages' screens are outside this route: each focuses its own control in `onMounted`, which is one expression with no guard to carry, since a game screen has no text entry for a reader to be typing in, so a shared focus-on-open helper over it is syntax extraction and stays rejected (the `over-engineering` skill, `references/syntax-extraction.md`). A boolean prop reads `false` when absent, so a template binds `isAutofocus || undefined`, never the bare prop, or every control carries the attribute and `Dialog.vue` finds one that no one asked for.
- **A field around controls of its own is one `ui-field` in one state**: drawn whole at rest and active through `:focus-within`, which a feature never sets. Its formatting buttons are disabled while the editor is unfocused and keep the focus on press (`apps/web/app/components/RichTextEditor/MenuBarButtons.vue`); an action that needs no selection stays enabled.
- **A field is `UiTextField` inside a `UiForm`**, passed rules from `UiRules` — the library's builders, one wording across every field — or a `UiRule` of its own. A list built from constants is a plain array, never a computed. The form's `isValid` is false only once a field has failed, so a submit button can stand disabled on it.
