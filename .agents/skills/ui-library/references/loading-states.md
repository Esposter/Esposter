# Loading States

Read when a list or a panel is filled by a read. `SKILL.md` has the one-line rule; the gate and the states are here.

- **A list a read fills is loading until a read settles, never empty.** Skeletons in the content's own shape while a read is out and nothing is on screen — the first read, and a sort, filter or scope change that empties the list before it reads again — `UiErrorState` when it failed, and `UiEmptyState` only once a read has settled with nothing. The gate is the read's own state (`readItems`' and an auto search's `isPending` and `isError`, `useAsyncData`'s `status`); an empty state behind `items.length === 0` alone flashes on every read. `readItems` records a failed read rather than throwing it, so an auto search over it never sets `isError` on its own: a search that reads through `readItems` takes its state from `useReadItemsSearch`, which also gives the retry. No lint can tell a read-backed list from a local one, so the design pass asks it of every list.
- **A typed search is pending from the keystroke until its search lands.** `useAutoSearch`'s `isPending` covers the window the throttle holds a typed query back, not only the request in flight: a list over it must not read an empty result for text nobody has searched yet. A search that failed is the error state instead, never pending.
- **A read's pending and error are held by the owner that issues it, and the list reads them there.** A read a list issues again — a filter, a retry, a second page of the same screen — is invisible to a list bound to the first call's refs, so the composable or store holds one state for its list and every call writes it. A read whose result is discarded (`await readX();` at setup) draws no error state at all; bind its result and draw the error ahead of the empty state.
- **Why the rule is held by owners, not a lint rule:** the exceptions are every empty state that is not read-fed (a palette, a local draft list, a filter with no read behind it), and a list of those would be a roster. The find recipe (`.agents/ledgers/ui-library.md`, recipe 6) finds the residue and each hit is read.
