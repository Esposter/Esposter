# Links and Sources

Read when a page links another page, or records a decision taken from outside the repo. The one-line rules are in `SKILL.md`; this page is their full statement.

## Links

- **Every line earns its place.** If another page already says it, link instead, by a path relative to the linking page, so the link works on GitHub and in any checkout: from `specs/post/likes/design.md`, the resource standard is `../../architecture/resource/design.md`. The link **text** is prose naming the page, never the path repeated (`[resources](../../architecture/resource/design.md)`): a path reads as punctuation mid-sentence, and the reader already sees where it goes on hover. `scripts/src/workspace/openspecLinks.test.ts` fails on a relative link under `openspec/` that resolves nowhere.
- **Outside `openspec/`**, a README or a manifest links a spec by its GitHub URL (`https://github.com/Esposter/Esposter/blob/main/openspec/...`), since an npm page or a plugin listing resolves no relative path; a skill cites it by its repo path in backticks, which the citation test resolves.
- **A page cites code by its name, never by a line number.** A line is a measurement of a file that the next edit moves, so a citation of a line of a repository file names what the line sits in instead: the symbol (`` `createCharacterMaterial` ``), the section's title, or a relative link to the page. Every form that names a line counts: `path.ts:NN`, `path.ts:NN-MM`, a shorthand `:NN` after such a path, `line NN`, `lines NN to MM` and `line NN of path.ts`. A value the line gives stays in the sentence. The rule does not cover a line of an external source, which no edit in this repository moves: a `{data-root}` dump, a URL, a `.go` or other source the repository does not track, or a bare game-data `.json` name. A sentence that cites one names its file beside the lines, so the external file is the one it reads. Nor does it cover a line inside a fenced block (a program, a log or a quoted game-data row), a version such as `7.1`, a measure such as `lines NN units apart`, a ledger row, the archive, a vendored skill, or a sentence about a line of the page itself. `scripts/src/workspace/lineNumberCitations.test.ts` fails on each citation of a repository file's line in `openspec/` (archive excepted) and `.agents/skills`, and `scripts/src/services/citations/getLineNumberCitations.ts` is the one reader of these forms.

## Sources

- **A decision taken from outside the repo cites where it came from**, as a bullet in the design's `## Sources`: the link, its publisher, and one clause on what it grounds here — the ground truth a reader checks the decision against. A source is opened and read before it is cited, never recalled, since a misremembered spec is worse than none; one that renders nothing a reader can read (a client-side-only page) is swapped for one that does. References every surface shares live on the design sources page (`openspec/specs/architecture/design-sources/design.md`), and a page lists only what its own decisions draw on.
- **A requirement's citations move to the design, and the requirement keeps only the behaviour.** Each removed citation is one bullet under the design's `## Sources`, carrying its path and line references verbatim and one clause naming the requirement it grounds by header. Repo code paths go to `## Key files` instead. Scenarios move theirs too: their GIVEN, WHEN, THEN and AND lines carry the behaviour, and the bullet names the scenario by its title. A title states the claim its scenario checks, so when a body changes its claim the title changes with it; a title that still states its claim keeps its wording, even where it names where a number came from. Nothing is paraphrased or dropped in the move: a citation that disappears from the design is a source lost.
