Notes on a tree several units share:

- `apps/web/app/store` root files (`alert`, `bookmark`, `cache`, `clipboard`, `layout`, `navigationTrail`, `notification`, `overlay`, `pageMark`, `recentPage`, `storage`): the two plain Maps here (a timer registry and an invalidator registry) are not state, so they are not reactive
- `apps/web/app/store/resource`: blade-scoped state, torn down on unmount
- `apps/web/app/store/dungeons`: every Phaser instance is `markRaw`d at the one site it enters state
- `apps/web/app/store/post`, `app/store/user`, `app/store/survey`, `app/store/achievement`: the three dialog stores here are per-service with `""` targets
- `apps/web/app/store/dashboard`, `emailEditor`, `webpageEditor`, `clicker`: the three content stores share one load-seed shape
- `apps/web/app/store/message` top-level files: `dialog`, `emoji`, `emojiPicker`, `index`, `roomCategory`, `roomCategoryDialog`, `scheduledMessageJob`, `sentMessage`, `thread`, `threadFollow`: the message module's own stores beside `data` and `pin`, which the row above holds

## Rules

Enforced rather than swept, so not in the units above:

- A store read by dot outside its own source — `packages/configuration/eslint/restrictedStoreSyntaxes.js`.
- A store's own source calling a nested store's method by dot — `packages/configuration/eslint/restrictedStoreCallSyntaxes.js`.

## Exclusions

- Cursor-pagination mechanics — the `pagination` ledger's question, over the same files.
- `provide`/`inject` sites that should be stores are a `vue-components` finding, not one here; this ledger reads stores that already exist.
