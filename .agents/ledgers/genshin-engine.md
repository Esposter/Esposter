## Open findings

- **`toSceneColor` runs Newton steps a dozen times a frame.** `applySkyState` calls it for every colour the screen shows as it is, and `useSky` calls `applySkyState` each frame, so a frame pays several hundred `toneMapNeutral` evaluations and their tuples against the rule that nothing allocates per frame. Khronos' PBR Neutral has a closed-form inverse (the peak back through the compression, the white share undone, the toe's offset from the least channel), which is exact, allocation-free and a fraction of the cost. It is a decision rather than a fix because the two disagree above a display peak of about 0.94: there Newton stops each channel at `SCENE_CHANNEL_LIMIT` and solves the others against the stopped one, where the closed form clamps the true inverse, so the brightest cloud and sky colours shift and the solved login values and parity snapshots move with them. Options: take the closed form and re-solve the login sky, or keep Newton and write it into a target colour with scratch tuples.
- **`sampleSkyState` drops a keyframe's optional colours.** `SkyKeyframe` declares the back colours and the two halos as optional, `SkyState` inherits them, and `sampleSkyState` blends only the required fields, so a region whose keyframes set a halo draws none and nothing fails. Only `LoginSkyStateMap` sets them today, as whole states. Options: blend them where both neighbours set one, or move them off `SkyKeyframe` onto `SkyState` beside `fogColor` and `shape`, which makes setting one on a keyframe a type error.
