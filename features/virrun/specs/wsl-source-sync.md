# virrun — WSL ext4 Source Mirror

On win32, read the repo source from a WSL-native ext4 mirror instead of straight from `/mnt/c`, so an `os`/wsl run stops paying the v9fs read tax on every source file — and keep that mirror fresh with a host-side manifest delta, so the _sync itself_ never stat-walks the tree over v9fs either.

## Overview

The shipped WSL bridge moved the write-heavy caches (pnpm store, snapshot overlay dirs, corepack home) onto WSL ext4, but the **source lower was still `/mnt/c`**: `createWslBwrapArgs` used the wslpath-translated cwd as both `--chdir` and the `--overlay-src` read-only lower. So every fork re-read the whole source tree — and the toolchain's own file reads (tsc, vitest, eslint walking the tree) — over 9p/v9fs, documented at 15–64× slower than ext4. That was the cause of the win32 gap: `os/wsl` benched at **0.06–0.31× native** vs Linux's 0.76–0.95× (`localMonorepo.platform.bench.win32.md`), and the earlier "overhead is inherent overlayfs cost, stop squeezing" verdict was measured on **ext4 only** — it never covered the v9fs source read. The mirror fixed the toolchain's reads, but the first cut's per-run `rsync -a --delete` still quick-check stat-walked every source file over 9p (**~12.5s on a ~5k-file repo with zero changes** — larger than the whole remaining overhead), which the manifest delta sync below removes.

Fix: keep a per-repo ext4 mirror of the working tree under the existing WSL native cache root, incrementally sync it (host → mirror) before each run, and point the `--overlay-src` read-only lower at the mirror — but mount the overlay at, and `--chdir` into, the repo's **logical `/mnt/c` path**, not the mirror's `/home/.../sources/<hash>/tree` path. Reads hit ext4 at native speed while `pwd` and every absolute path a tool emits match the native baseline instead of leaking the mirror path (`buildBwrapArgs` takes a `sourceDir` decoupled from `cwd` for exactly this; the working-directory differential pins it). Write-back is unaffected — its flush target is derived independently from `options.cwd`, and the mountpoint now equals that host path, so the upper diff maps back 1:1.

## Why this is contained

`persistRun` already computes its flush target as `hostDir = options.cwd` and hands it to `applyFlushPlan` (`persistRun.ts:35,48`), which translates it to `/mnt/c` Linux-side. That is **separate** from the mirror `createWslBwrapArgs` picks for the `--overlay-src` lower. Sourcing reads from the mirror does not touch write-back: the upper diff is relative to the overlay **mountpoint**, which is the logical `/mnt/c` path — the same layout as the host working dir — so it flushes back 1:1. `buildBwrapArgs` grew one optional `sourceDir` param (defaulting to `cwd`, so the native Linux path is byte-identical); `ExecOptions` and the flush plan are unchanged.

The mirror is also read by `createSnapshot` capture (it routes through the same `createWslBwrapArgs`), so the one-time `pnpm install` manifest walk (many small `package.json` reads across the workspace) also moves off v9fs for free.

## Mechanism

1. **Mirror location** — a self-contained entry dir `<wslNativeCacheRoot>/sources/<sha256(hostCwd)>/`, a sibling of `snapshots/` and `store/` under the ext4 root (`getWslNativeCacheRoot.ts`), holding the synced working tree in `tree/` beside an `origin` marker recording the host cwd it was cloned from and a `manifest.json` recording the tree state the mirror holds. `getWslSourceMirrorEntryPath` addresses the entry Linux-side and `getWslSourceMirrorEntryUnc` addresses the same entry host-side (both via `getSourceMirrorKey`); `getWslSourceMirrorPath` appends `tree/`, and that `tree/` leaf — not the entry root — is the `--overlay-src` lower, so the sandbox source view stays a byte-exact copy of the repo and the metadata never shows through. Keyed by the host working-dir absolute path so distinct repos/worktrees never collide.
2. **Manifest delta sync** — the planner (`createWslSourceMirrorSync`) walks the working tree **on the host FS** (`buildSourceMirrorManifest`: posix relative path → type/size/mtimeMs/symlink-target, the same quick-check signal rsync uses) and diffs it against the entry's published `manifest.json` (`diffSourceMirrorManifests`). The naive per-run `rsync -a --delete` quick-check stat-walked every source file over 9p — measured **~12.5s on a ~5k-file repo with zero changes** — which was the ~8–10s win32 floor that masked the snapshot layer entirely; the host walk replaces it at NTFS speed. Three outcomes: **no delta** → empty script, the run pays no sync at all; **delta** → pid-tagged temp files staged in the entry dir over the UNC (null-delimited copy + delete lists, next manifest, origin marker), applied by `xargs -0 rm -rf` + `rsync -a --from0 --files-from` so only changed files cross v9fs; **no readable manifest or missing tree** (first run, `cache clean`, corrupt file) → full `rsync -a --delete` fallback, which also self-heals any mirror-vs-manifest drift. Both sync shapes end by publishing the staged manifest + origin via atomic `mv` inside the lock, so the manifest never claims a state the mirror doesn't hold.
3. **Folded invocation** — a non-empty sync script rides the run's own `wsl.exe` invocation as a preamble ahead of bwrap (`createWslOsBackend`), not a separate spawn: `{ <sync>; } || exit "$?"`. A failed sync exits before the sandbox starts and surfaces its stderr through the close handler — never a stale mirror, never an `os` → native fallback. On success the sync is silent (rsync without `-v`), so the child's stdout/stderr stay byte-exact vs native for the differential/task-cache captures. `createWslBwrapArgs` stays pure: it derives the mirror path (`getWslSourceMirrorPath`) without syncing.
4. **Excludes** — `node_modules` (supplied by the snapshot RO lower — never belongs in the source lower, mirrors the write-back rule), `.git` (large, churns every commit, unread by the dev-loop commands), and an active `environment` preset's **prepare outputs** (`.nuxt`): those are owned by the source-keyed prepare layer, so the host's platform-specific copy must be kept out of the sandbox — otherwise it shadows the prepare layer and leaves the prepare capture incomplete (files unchanged by `nuxt prepare` would be read through the host lower rather than captured). Everything else is mirrored: **over-copy is correctness-safe, under-copy is a bug**. Other build outputs (`dist`, …) stay in scope — the toolchain may read them and they are cheap deltas. One `resolveMirrorExcludes` feeds both the host walk and the full-rsync fallback's `--exclude` args (bare name = any depth, slashed pattern = exact relative path), so the two sides always agree on the mirrored set.
5. **Concurrency & bounds** — the whole mutation (deletes + rsync + manifest/origin publish) runs under one exclusive per-mirror `flock` (fd-group form), so concurrent syncs serialize and a manifest is never published for a half-applied delta; `flock -w` + `timeout` bound a stalled lock or ext4 volume Linux-side (`SOURCE_MIRROR_TIMEOUT_SECONDS`), replacing the old spawn-level timeout. A running fork holds no lock — mirror mutation under a live reader is tolerated exactly as before (rsync writes temp+rename per file), and a run whose plan showed no delta never touches the lock.
6. **Platform gate** — win32/WSL only. Native Linux source already lives on ext4 (or the host FS), so `createLinuxOsBackend` keeps `--overlay-src` on the real source, no mirror, no sync.
7. **Reaping** — two sweeps. `reapAbandonedSourceMirrors` runs once at os-backend startup (`createWslOsBackend`, beside `reapOrphanedWslRuns`) and sweeps every `sources/<hash>` whose `origin` marker points to a host path that no longer exists — a deleted worktree or moved repo. Unlike `snapshots/`/`prepare/` (keyed on a lockfile/source hash, where every entry but the current one is superseded), each mirror keys a distinct live repo, so this is the one cache entry with nothing to supersede it and needs its own origin-keyed sweep (reusing `sweepStaleEntries`). A missing or blank marker is spared — reap only what is provably abandoned, never a first-run partial or a concurrent live repo. `reapStaleSourceMirrorTemps` (the file-shaped twin of `reapStaleTemps`) runs per plan and unlinks staged temps whose **host** owner pid is dead — the sync script removes its own temps on success, but a hard-killed run strands them, and staging host-side is what keeps every temp attributable in the Windows pid domain. Both best-effort and off the critical path.

## Constraints / Notes

- **Goal is closing the v9fs gap, not guaranteed native-beating on win32.** With the manifest delta, the per-run residual is the host-FS walk + one UNC manifest read (no wsl.exe spawn on the no-change path) plus sandbox overhead, against native's local NTFS reads. Expect win32 `os/wsl` to move from 0.06–0.31× up toward the Linux 0.76–0.95× band; whether it crosses 1.00× depends on delta size. Report the measured numbers honestly — do not claim a win the bench doesn't show (the bench-truth rule).
- **Manifest delta over git introspection (decided).** An earlier note deferred a git-driven delta (`git ls-files` + `git diff`); the shipped mechanism uses a plain host-FS stat-walk manifest instead because it is generic-any-repo **and** covers gitignored-but-mirrored outputs (`dist`, …) that git enumeration would miss — a git-driven delta would leave those stale in the mirror, an under-copy bug. The walk is also the change detector rsync itself uses (size+mtime quick-check), so the delta and the fallback agree by construction. Same blind spot as rsync's quick-check (content change preserving size+mtime), accepted as parity. Attribute-only changes (chmod) on quick-check-identical files are not re-synced — meaningless for NTFS-sourced trees whose Linux perms are synthesized anyway.
- **The walk is synchronous and on the exec hot path — deliberately.** virrun is a one-command CLI built on sync spawns (`readWslPath`, probes); there is no concurrent I/O to starve, and the walk costs ~100s of ms on NTFS vs the ~12.5s 9p walk it replaces.
- **Mirror eviction (shipped).** Two layers. Within a mirror, the delta's delete list (or the fallback's `rsync --delete`) keeps `tree/` == the working tree every synced run (host-removed files drop). A _whole abandoned_ `sources/<sha256(hostCwd)>` entry (deleted worktree, moved repo) is reclaimed by `reapAbandonedSourceMirrors` at os-backend startup: it sweeps every entry whose `origin` marker points to a now-absent host path (via `sweepStaleEntries`), sparing a live/blank/missing marker so a concurrent run is never touched. Eviction is keyed to source existence — precise, not LRU or TTL, and with no size budget. `cache clean --all` still drops the whole `sources/` tree outright (win32-only, from the WSL-native ext4 root — see `cacheCleanCommand`).
- **Absolute host paths inside a command** resolve against the repo's logical `/mnt/c` path, matching the host tree, because the overlay is mounted there (the mirror is only the `--overlay-src` lower, not the mountpoint). `pwd` and tool-emitted absolute paths therefore equal native — pinned by the working-directory case in the shell differential corpus.
- **PATH re-anchoring (shipped fix, now belt-and-suspenders).** An earlier cut chdir'd the sandbox onto the mirror path, which broke bare-command resolution: the WSL login PATH (Windows-interop appends the Windows PATH) carries `/mnt/c/<repo>/node_modules/.bin`, which was then the raw host tree, so a bare `tsgo`/`eslint`/`oxlint` resolved the **win32** binary and crashed needing its `-linux-x64` sibling (e.g. `Unable to resolve @typescript/native-preview-linux-x64`, or esbuild's "installed for another platform"). `createOsExecOptions` prepends the mirror's own `node_modules/.bin` ahead of the login PATH to force the correct-platform binary. With the mountpoint now back at the logical `/mnt/c` path (the `sourceDir` split above), `/mnt/c/<repo>/node_modules/.bin` is once again the overlaid, current-platform dir, so the login-PATH entry already resolves correctly — the prepend is now redundant (its mirror-path target has no `node_modules`, since the mirror excludes it) and could be dropped as a follow-up. Regression-gated by `createOsExecOptions.test.ts`.
- **Rejected: copy source into the snapshot.** The deps snapshot is keyed by lockfile hash and reused across many source states; folding mutable source into the immutable install layer breaks the cache model. The mirror must be per-repo and separately synced. (The prepare layer is _not_ this: it captures only regenerated **outputs** into a separate **source-keyed** layer, never the source itself into the lockfile-keyed deps snapshot. → [snapshot-fork](snapshot-fork.md#prepare-layer-realized--source-keyed-generated-artifacts))
- **Rejected: full copy per run.** Defeats the point — a cross-boundary full write each run costs more than the reads it saves. Incrementality is load-bearing.

## End-To-End Plan

- **Today**: shipped — the mirror serves the source lower at ext4 speed, and the manifest delta keeps the per-run sync off v9fs (empty script on a clean tree, changed-files-only rsync on a dirty one, full-rsync self-heal when the manifest can't be trusted).
- **Correctness**: the existing differential + write-back equivalence corpora already run on win32 and gate this — the mirror must produce byte-identical results and flush shapes vs native. No new correctness seam; if the mirror is stale or mis-synced, those tests fail. The planner's own contract (walk excludes, diff shape, skip/delta/fallback routing, temp lifecycle) is unit-gated beside the sources.
- **Failure/retry**: a failed sync (rsync missing, ext4 full, hung lock past `SOURCE_MIRROR_TIMEOUT_SECONDS`) fails the folded script before bwrap and aborts the run with the sync's stderr — never a silent partial mirror, and the unpublished manifest means the next run re-syncs. No `os` → native fallback here (the `os` backend never falls back by design); a broken mirror is a hard error. An unreadable working-tree **root** aborts the plan outright — degrading to an empty manifest would diff as "delete everything".
- **Unsupported until later**: mirror sharing across worktrees of the same repo (keyed by exact cwd).
