# Roadmap

Open work for the cross-cutting standards on this section, each item a decision or a feature. An idea waiting on a revisit trigger is parked in [deferred](/docs/architecture/deferred).

## Open

- [ ] **`pnpm dev`'s package build: whether a failed build stops the dev server, and whether it overlaps Nuxt's start.** [Build pipeline](/docs/architecture/build-pipeline) records that `apps/web`'s `dev` script runs the root `build:packages` task before `nuxt dev`. The script chains them with `&&`, so a package whose build fails exits `pnpm dev` before Nuxt starts. The module it replaced, which ran the build beside Nuxt's own preparation, logged a failed build and let Nuxt start, and a cold start now pays the whole package build before Nuxt's preparation begins, where that module overlapped the two. Decide whether a failed package build should stop `pnpm dev` or only warn, and whether the build should overlap Nuxt's start again, then state the choice on the build pipeline page.
- [ ] **The parity page's build folder, which the root `vite.config.ts` restates.** The root build task `build:parity` runs `pnpm run build:parity` in the world package and names no path itself, but its cache input excludes the `parity-build` folder by name, a value `PARITY_BUILD_DIRECTORY_NAME` owns in `scripts/src/services/genshinParity/shared/constants.ts`, so renaming that folder on the scripts side leaves the root exclusion stale. The config path `parity/vite.config.ts` lives only in the world package's `build:parity` and `parity` scripts and the scripts' `PARITY_CONFIG_PATH`, with no root copy. The root config cannot import scripts' constants without a new cross-package import. Decide whether the root config reads the folder name through a shared module both packages import, or the scripts read the root's value, then have the one side the decision leaves read the other.
- [ ] **The upstream audit of `@codemirror/theme-one-dark`, owed by its replacement.** The code viewer's chrome and highlighting moved from the removed `@codemirror/theme-one-dark` to the app's own theme in `apps/web/app/services/codemirror/uiEditorExtensions.ts`, and that file's comment says the upstream tracker was only skimmed. The [dependency admission](/docs/architecture/dependency-admission) rule requires every upstream issue, open and closed, to get an evidenced verdict before the replacement lands, and the ledger row was dropped with no such record. Read the package's issue tracker whole, give each issue its verdict, and record them on a new docs page for the code viewer, which no page yet owns.
- [ ] [Leaf size](/docs/proposals/architecture/ai-native-resources/leaf-size) — the agent read answers an oversized leaf, such as a long string, with an empty `memberSizes` and so gives neither its content nor its size; the result needs a field for it, so decide the field and its name, then build it.
- [ ] **A duplicate-code gate in CI, at a zero threshold.** No workflow runs jscpd, so nothing fails on a duplicate: the sweep's finder (`scripts/src/sweeps/duplicateCode/index.ts`) prints rather than exits non-zero, and jscpd's default threshold is unset. The finder reports 16 pairs now, and the duplicate-code ledger (`.agents/ledgers/quality/duplicate-code.md`) still has 7 of its 21 units open. When the sweep reaches zero, add `kucherenko/jscpd` pinned to a commit SHA with `threshold: 0`, and give its `.jscpd.json` the finder's ignore globs, tests and import blocks included, so the gate and the sweep count the same code.
